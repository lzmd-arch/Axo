# 预注册：召回层门槛（弱记忆不注入）

**日期**：2026-11-01 　**状态**：已实现并达标（见 §4），默认开启。

## 0. 它解决什么、不解决什么

**解决**：陌生话题上，召回照样把几十条弱相关记忆塞进上下文（用户能感受到"开始胡说"，
工程师能看到 top 分数有断崖）。做法只有一条：**低于门槛的记忆不注入**——它们还在库里，
只是这一轮不去打扰模型。

**不解决**：这不判断"能不能回答"。问"如何养热带鱼"时没有相关记忆是正常的，模型该照常
回答；门槛只决定**哪些记忆进上下文**，不决定说不说话。

与任务书 AXO-MG-001 的关系、以及为什么产品不走三特征门控：见
[ADR-0028](https://github.com/lzmd-arch/BioSNN-Plug/blob/main/docs/adr/ADR-0028-metacog-gate-threshold-first.md)
与 `prereg-metacog-v1.md`。

## 1. 机制

```text
召回（多通道融合 → 排序 → MMR）之后，逐条按**融合分**过滤：
  融合分 < min_score 的记忆不注入上下文
min_score 默认 0.20，来自 settings_store.DEFAULT_RECALL_MIN_SCORE
设置页：记忆 →「记忆门槛」滑块，0.10–0.60
```

**为什么不是任务书里的 0.65**：0.65 是**余弦**的直觉，而这里过滤的是**融合分**
（词法/语义/时间/图按权重合成后的值）。同一批数据上，整句正样本的融合分中位是
0.567、半句是 0.565、陌生话题最大 0.163——拿 0.65 当门槛，连"这句话我确实有"都会被挡掉。
按 0.65 实现等于把预注册的判据 2 直接做死。

## 2. 标定（`tools/calibrate_recall_threshold.py`，库 217 条，种子 7）

| 组 | top 融合分 p5 | p50 | max |
| :--- | ---: | ---: | ---: |
| 正样本（整句） | 0.567 | 0.567 | 0.738 |
| 正样本（半句，前 12 字） | 0.211 | 0.565 | 0.738 |
| 陌生话题（20 条） | 0.099 | 0.126 | **0.163** |
| 真实提问（178 条，无标签） | 0.245 | 0.567 | 0.738 |

阈值扫描（每格是「注入条数中位 / 仍有注入的查询比例」）：

| T | 整句 | 半句 | 陌生话题 | 真实提问 |
| ---: | ---: | ---: | ---: | ---: |
| 0.10（旧默认） | 85 / 100% | 84 / 100% | 62 / 100% | 83 / 100% |
| 0.15 | 5 / 100% | 4 / 99% | 0 / 15% | 4 / 99% |
| **0.20** | **2 / 100%** | **2 / 97%** | **0 / 0%** | **2 / 97%** |
| 0.25 | 1 / 100% | 1 / 92% | 0 / 0% | 1 / 94% |
| 0.30 | 1 / 98% | 1 / 87% | 0 / 0% | 1 / 93% |

谷点在 0.16–0.21 之间，取 **0.20**。

## 3. 判据（先写死）

1. 陌生话题的注入条数：从 ~60 降到 **< 5**；
2. 高相关保留：整句正样本 **≥ 95%** 仍有一条；
3. 单次召回延迟增加 **< 5 ms**。

## 4. 结果

| 判据 | 结果 | 判定 |
| :--- | :--- | :--- |
| 1. 陌生话题注入 | 中位 62 → **0**，20 条里 0 条仍有注入 | 过 |
| 2. 整句保留 | **100%**（半句 97%，真实提问 97%） | 过 |
| 3. 延迟 | 中位 **19.66 ms → 15.15 ms**（少一条 MMR 路径，反而更快） | 过 |

## 5. "不确定"话术的边界（与任务书不同的一处）

任务书要求"若 k 条全低于 T，触发不确定话术"。**照字面实现会伤到产品**：问天气、问新闻、
说"今天有点累"都没有记忆，如果一律回"我不太熟悉"，助手就退化成只会背记忆的机器。

所以实际落地收窄成三条**同时**成立才说那句话（`MainWindow._should_say_uncertain`）：

1. 这一轮**不是任务语域**（任务轮带着全量工具、含 `search_memory`，模型能自己去查，
   替它拒答等于把路堵上）；
2. 阈值过滤之后**一条记忆都没有**；
3. 这句话是在问**记忆里的事**（`router.is_memory_question`：上次 / 我的记忆 / 记忆里 /
   记忆库 / 回想）。

闲聊轮与工具轮照常回答。话术库见 `src/axo/phrases.py`。

**2026-11-01 修订（预注册记录的更正，不改判据）。** 上面第 3 条与路由原先的 `_TASK_MARKERS`
是同一张词表：五个记忆词同时也在任务标记里，于是任何问记忆的话都被判成任务轮，
第 1 条恒不成立——这条话术**在真实路由下从没触发过**（此前的测试用替身窗口，绕过了路由）。
现在五个词移出任务标记、并在规则层显式判闲聊（0.7）；同时第 1 条按实际代码的判据写成
"不是任务语域"（代码检查的是 `_turn_uses_tools`，不是"工具表为空"——两者在 2026-10-31
闲聊轮带只读工具之后已经不是一回事）。可达性由 `tests/test_router.py` 的
`test_empty_recall_refusal_is_reachable_through_the_router` 钉住。

## 5.1 2026-11-01：词法/时间可靠度改了，门槛的口径跟着变（待重标）

同一天调了 ``RecallConfig`` 的可靠度（词法 0.9 → 1.2、时间 1.0 → 1.5，依据
``benchmarks/recall_tuning.md`` 的两向交叉验证）。融合分是**绝对**乘可靠度的，所以
"同一个数"对原始 Jaccard 的严格度会变：

- ``memcore.RecallConfig.min_score`` 从 0.10 重标为 **0.133**（0.139 × 1.2 × 0.8），
  默认门槛维持原来的严格度；
- **产品门槛 ``settings_store.DEFAULT_RECALL_MIN_SCORE`` 仍是 0.20，没有重标**。
  按新可靠度它对应的原始 Jaccard 约 0.21（旧口径约 0.28），也就是**比第 1–3 节那组
  判据通过时更松**。本文的 62→0、保留率、延迟三组数字因此**只对旧权重成立**；
  重标要用真实库重跑 ``tools/calibrate_recall_threshold.py``，在那之前 0.20 是一个
  "没跟着权重走"的旧数。

## 6. 限制

- 正样本取记忆原文，**太干净**；真实会话里还没有"有记忆支撑 / 没有"的人工标注。
  判据 2 在真实分布上是否仍 ≥95%，要等那批标注。
- 融合分随通道权重变。打开联想通道（`graph_weight`）后，同一个 0.20 不再对应原来的
  严格程度——设置页那条代价说明里已经写了。
- 阈值只决定"注入哪些"，不保证"注入的就相关"。它挡的是**弱**，不是**错**。

## 6.1 真实分布复评（2026-11-05，40 条人工标注）

语料：40 条真实提问，按 `docs/annotation-rubric.md` 标为 **support 28 / none 12 / partial 0**。
库：`D:\AxoData\memory\mem.db` 的副本（源库前后 sha256 一致）；`max_items=5`。
标注原件在仓外（真实提问，不入库）。

| 门槛 | support 至少注入一条 | none 注入 <5 的比例 | none 中位 | none 最大 |
| :--- | ---: | ---: | ---: | ---: |
| 0.133（库默认） | 100.0% | 0 / 12 = 0% | 5 | 5 |
| **0.20（产品门槛）** | **96.4%（27/28）** | **6 / 12 = 50%** | **4.5** | **5** |

**判据 2 在产品门槛下过**（96.4% ≥ 95%），但只剩一条 support 的余量。
**判据 1 不能干净地判过**：中位 4.5 < 5，但 12 条 none 里 6 条仍注满 5 条（`max_items=5`
的上限）；按“每条都 <5”的口径只有 50%。

读法：

- 0.20 相对 0.133 确实少注入了（12/12 满槽 → 6/12），但**一半的陌生话题仍然拿满 5 个槽**；
- 判据 1 原先的“注入条数 <5”是按中位写的，按中位看是 4.5、勉强过；按“没有任何一条满槽”
  看是失败的。两种读法都登记，**不挑好看的那个**；
- 产品门槛 0.20 **保留不动**：再抬会先伤 support（已只剩 27/28）；
- `tools/eval_recall_threshold.py` 原先用 `RecallConfig` 的库默认 0.133，**不是产品口径**；
  已改为默认 0.20，并加 `--min-score` 覆盖。上表两行是同一脚本分别跑 0.133 / 0.20 的结果。

**诊断（不改变产品默认）**：同一批 40 条上再扫两档：

| 门槛 | support 至少一条 | none 注入 <5 的比例 | none 中位 | none 最大 |
| :--- | ---: | ---: | ---: | ---: |
| 0.25 | 96.4% | 91.7% | 2.0 | 5 |
| **0.30** | **96.4%** | **100%** | **1.0** | **2** |

0.30 在这批真实提问上**同时满足**两条判据，support 与 0.20 持平（都是 27/28）。但这是
40 条、support 只剩 1 条余量的结果；**不因此改产品默认**。要改 0.20，先另写一份
真实库重标定的预注册，并把样本扩大——0.30 的“100%”只有 12 条 none，一条就能翻面。
