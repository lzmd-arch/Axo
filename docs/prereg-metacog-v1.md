# 预注册：Axo 元认知门控 v1（AXO-MG-001 的更正版）

**日期**：2026-11-01 　**状态**：机制已实现、离线判据**未通过**（见 §5），**不接线**。

## 0. 这份文档在更正什么

任务书 `AXO-MG-001` 的前提是「MG v11 组件已验证（三维门 OOD 全过）……**512 神经元
SNN 门控**」。对着两个仓库核对之后，这个前提有三处不成立：

1. BioSNN-Plug 里的 MG v11（`research/cognitive/run_metacognitive_gate_v11.py`）是
   **4 维情景记忆任务上的 kNN(5) 密度门**，特征是读出残差的
   `[max_errors, errors, state_norm]` 三个标量。**没有脉冲、没有 ALIF、没有 e-prop、
   没有 512 个神经元。**
2. 它没有留下任何检查点（`mg_v11_512.npz` 不存在）；产物只有
   `sweep_results/metacognitive_gate_v11/{summary.json,README.md}`。
3. `biosnn_bus.SpikeBus` 目前是**骨架**（模块文档自己挂着 warning）：只有
   `register/step/get/describe`，没有 `state()`、没有 `ALIFLayer`、没有发放率读出。

它自己的 README 也写明：「四族全过」只指四种**合成输入变换**（time_shift /
time_reverse / dim_dropout / correlated），**不是通用 OOD 的证明**，没有在真实分布
偏移上验证。

所以这一版**照机制落地，不照名字落地**：把 v11 的密度门搬到 Axo 真实召回账本上，
先离线判，过不了就不接线。512 神经元 SNN 版本进排期（见
`BioSNN-Plug_计划书_v6.3_amend1.md`），不在本文范围。

## 1. 机制

```text
输入：一轮 RecallLedger（memcore.recall 的产物，只读 injected / scanned）
特征：
  top_score   = 最强一条的融合分          ← v11 的 max_errors（最强证据）
  mean_topk   = 前 5 条融合分的均值        ← v11 的 errors（整体能量）
  density     = 注入条数 / 扫过条数        ← v11 的 state_norm（支撑尺度）
门：校准集上标准化 → 到最近 5 个校准点的平均距离取负 → 校准集上的经验分位
决策：分位 ≥ 0.7 → inject；≥ 0.3 → inject_with_caution；否则 uncertain
```

实现：`src/axo/metacog.py`（纯 numpy，`_PURE_LAYERS` 里有一条守卫盯着它不碰 Qt/网络）。
**它不改变任何回答路径**——本版只产出分数与三档标签。

## 2. 数据与协议（先写死）

- **库**：`D:/AxoData/memory/mem.db` 的**副本**（脚本自己复制、结束前比对源库
  sha256；召回一律 `settle=False`——看一眼，不是想起来）。
- **嵌入**：应用自己的随包 `bge-small-zh-v1.5`（512 维），不用词法替身。
- **正样本**：库内 200 条记忆，查询 = 该条的正文（"这句话我确实有"）。
  另加一组**难正样本**：记忆正文的前 12 字（真实的"半句 + 记忆里有完整那条"）。
- **OOD**：20 条与库无关的陌生话题（量子纠缠、养热带鱼、麻婆豆腐……）。
- **划分**：按 `memory_id` 的 sha1 奇偶分校准/评测两半，**同一条不会两边都出现**。
- 种子 7；库 217 条（2026-11-01 的快照）。

## 3. 判据（预注册，先写死）

1. **OOD 拦截率 ≥ 80%**，且**保留率 ≥ 95%**（"有记忆支撑"的那批里被误判 uncertain
   的比例 ≤ 5%）。
2. **必须有增量**：门控 AUROC ≥ 单特征基线（`top_score` 阈值）AUROC **+ 0.05**。
   达不到就说明三特征密度门只是把同一个数换了个说法——**按平凡解处理，不接线**。
3. 单次打分 ≤ 5 ms（纯 numpy，不含召回本身）。

第 2 条是这一版新加的，任务书里没有。理由：门控的输入就是召回分，若它与"给最强分
设一个阈值"等价，那它带来的只有复杂度。

## 4. 结果（2026-11-01，种子 7，库 217 条）

| 指标 | 值 |
| :--- | ---: |
| 门控 AUROC（正样本 vs OOD） | **1.000** |
| 基线①：`top_score` 阈值 AUROC | **1.000** |
| 基线②：召回非空就注入 AUROC | 0.500 |
| OOD 里召回一条都没命中的比例 | 0.0% |
| 难正样本（前 12 字）上门控 AUROC | **0.996** |
| 难正样本上 `top_score` AUROC | **0.996** |

同一保留目标下的对比（阈值都只在 calibration 上取）：

| 保留目标 | 门控 OOD 拦截 | `top_score` OOD 拦截 |
| ---: | ---: | ---: |
| 80% | 100.0% | 100.0% |
| 90% | 100.0% | 100.0% |
| 95% | 100.0% | 100.0% |

特征中位数：有记忆支撑 `top_score 0.567 / density 0.395`；陌生话题
`top_score 0.121 / density 0.291`。

## 5. 判定

- 判据 1：**过**（OOD 100%，保留在 95% 目标下 95.9%）。
- 判据 2：**不过**（1.000 vs 1.000；难正样本 0.996 vs 0.996，差 0.000 < 0.05）。
- 判据 3：**过**（单次打分约 0.1 ms，numpy 两次矩阵乘）。

**结论：这一版门控不接线。** 三特征密度门在这批数据上与"给最强分设一个阈值"完全
等价；把它接进回答路径只会多一层看不懂的数。

## 6. 顺带量出来的真问题

陌生话题上**召回照样注入了几十条记忆**（`density` 中位数 0.291 ≈ 217 条里 63 条），
最强分只有 0.121。也就是说：今天千岁问"如何养热带鱼"时，上下文里塞了六十多条弱相关
记忆，而分拣它们的办法只需要**一个** `top_score` 阈值。这比门控值得先做，且不需要
新机制。

## 7. 下一步（按代价排）

1. **阈值**：把 `top_score` 的截断做进召回（或在装配时过滤），先在离线数据上定值；
   这是本报告唯一有证据支持的动作。
2. **真实提问**：用真实会话里的用户消息做一批**人工标注**（有记忆支撑 / 没有），
   重跑判据 2——逐字整句太干净，区分不出机制差别。
3. **SNN 版本**：另立预注册（需要 ALIF 层、训练数据、脉冲读出），排期见 BioSNN-Plug
   计划书 amend1，**不在本季**。
