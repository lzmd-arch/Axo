# 预注册：LoCoMo 上的召回基线（v1，2026-11-02）

**状态：判据（更准确地说：口径）先落盘，代码未写，数据未跑。**

## 要回答的问题

在 LoCoMo（长对话记忆基准）上，**Axo 的召回能不能把回答所需的那几轮对话找出来**？

这一问是 Paper C 的前置条件：如果证据轮根本进不了候选，答题器再强也没用，
任何与 HeLa-Mem 的端到端对比都只是在量答题器。所以这一版**只量召回**，不量答题。

## 这不是一次通过/不通过的实验

**没有判据门槛。** 它是一次基线测量，本文件固定的不是门槛，而是**口径**——
口径先写死，是为了防止"换个 k 再报"这种事后选择。

后续若要把这个数与已发表结果比较（HeLa-Mem 报的是端到端 QA 准确率，不是召回），
必须另写一份带判据的预注册；**本文件产出的数不能直接拿去声称"优于/劣于"任何人**。

## 数据（不入库）

- 来源：`https://github.com/snap-research/locomo`，`data/locomo10.json`（10 段长对话）；
- 第三方数据，**不进本仓库**：只登记 URL 与 sha256，运行时从本地副本读；
- 每段对话含若干 session，每轮有 `dia_id`（如 `D1:3`）、`speaker`、`text`；
- 每条 QA 含 `question`、`answer`、`evidence`（若干 `dia_id`）、`category`。

## 口径（跑之前定死）

1. **记忆单位 = 一轮对话。** `content = "{speaker}: {text}"`（保留说话人，否则"她/他"指代丢失）；
   `memory_id = "{sample_id}:{dia_id}"`。
2. **查询 = 有证据的 QA。** `evidence` 为空或引用了不存在的 `dia_id` 的 QA**排除**，
   并报出排除条数（LoCoMo 的 category 5 是"adversarial"，预期在这里被排除）。
3. **时间通道中立。** 所有记忆的 `created_at` 固定为基准时间（`CREATED_AT`），
   不按 session 日期铺开——铺开会让"时间衰减"与"检索质量"混在一起。这是本版的**边界**，不是结论。
4. **配置 = 出厂默认**（`RecallConfig()`），不调任何旋钮。
5. **三个臂**，同一批记忆与查询：
   - **A1 纯词法**（不给 embedder）：完全离线、可复现，是"没有语义通道时的天花板"；
   - **A2 nomic-embed-text**：语义通道；
   - **A3 随包 bge-small-zh**：中文模型跑英文，作为**选型对照**（不是"更好的那个"）。
6. **指标**：hit@1 / hit@3 / hit@5 / hit@8（`RecallConfig.max_items` 默认 8，所以 8 就是上限，不报 hit@10——报一个被上限截断的数会误导）、
   **证据覆盖率**（每条查询的证据轮里被召回的比例，多证据查询用它才看得出差别）、MRR。
7. **分母**：只计有证据的查询。没有证据的查询**不进分母**（与金标准语料的规矩一致）。

## 跑之前的预期

**预期 A1 明显低于 A2/A3**：词法 SDR 是按字符哈希的，英文的分词边界对它不友好。
**预期 A2 ≥ A3**：随包嵌入是中文模型，英文上应弱一档。
写下来是为了防止事后把"词法不行"解释成"基准有问题"。

若 A2 的 hit@5 也低（比如 < 0.5），那说明**召回是 Paper C 的瓶颈**，先修召回，
再谈端到端对比——这句话现在写下，省得看到数之后再找理由。

## 不做的事

- 不做端到端答题（要 LLM，且会把这个基线变成"模型能力"的测量）；
- 不用 LoCoMo 的 `observation` / `session_summary` 之类派生字段——只用餐桌边的原始对话；
- 不因为某条 arm 结果难看就换 k、换配置、换数据子集；
- 不把这份数写进 README 的产品指标。
