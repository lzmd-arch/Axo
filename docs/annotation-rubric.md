# 标注规则：这条提问「有没有记忆支撑」

**为什么要有这一页**：`prereg-recall-threshold-v1.md` 的判据 2（高相关保留 ≥95%）当初是用
**记忆原文**当正样本测的，文档自己也写了“太干净”。这批标注就是把它放到真实提问上。
规则必须在**看数据之前**写死，否则标出来的东西回答不了任何问题。

## 一条提问怎么判

对每条提问，先假设“要回答它，用户的记忆库里得有什么”，然后三选一：

| 标签 | 含义 | 典型例子 |
| :--- | :--- | :--- |
| `support` | 库里**至少有一条**记忆能直接支撑回答所需的事实 | “我上次说的那个项目叫什么来着” |
| `none` | 库里的记忆**帮不上**——新话题、纯常识、纯闲聊、要现查的 | “今天天气怎么样”“帮我写个快排” |
| `partial` | 有相关记忆，但**不足以**支撑回答（只沾边、需要推理、需要多条拼起来） | — |

**只有 `support` 算正样本。** `partial` 刻意不算：它是最容易被“感觉像”骗过去的一类，
把它算进去等于把判据放宽。`none` 用来验判据 1（陌生话题的注入条数应 < 5）。

## 几条容易判错的

- **时间敏感的**（“明天几点开会”）：只有记忆里**明确记着**那个时间才算 `support`；记着别的
  会议不算。
- **自指的**（“你还记得我吗”）：不看对话上文，只看**库里**有没有能回答的记忆。
- **需要外部信息的**（新闻、天气、股价）：一律 `none`，无论库里存过什么。
- **同一件事的复述**：如果记忆里是同一句话的另一种说法，算 `support`（这正是语义召回要过的关）。

## 标注时不要做的事

- **不要按“模型上一轮答得对不对”判**——判的是记忆库有没有支撑，不是模型表现；
- **不要为了让判据好看而放宽 `partial`**；判据过不过是结果，不是目标；
- 拿不准就填 `partial` 并在 `note` 里写一句为什么。

## 产出与去向

- 语料 `questions.jsonl`：`{id, question, source_session, asked_at, label, note}`；
- **写在仓外**（默认 `D:/Projects/annotation_2026-11/`），是否入库由用户决定；
- 标注完成后跑 `tools/eval_recall_threshold.py`，结果追加进
  `docs/prereg-recall-threshold-v1.md` 的「真实分布复评」一节，**不覆盖原判据**。
