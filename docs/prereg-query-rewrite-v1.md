# 预注册：查询改写能否抬高硬改写检索（v1，2026-11-02）

**状态：判据先落盘，代码未写。**

## 问题

召回在"不点站名"的硬改写上只有 hit@1 = 0.40（bge 嵌入，见
`benchmarks/recall_embedding_swap.md`）。配置层已扫完、权重已到平台区，
所以下一刀只能动结构：**把提问先改写成接近记忆的说法，再检索**。

## 判据（跑之前写死）

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| Q1 | `benchmarks/paraphrase_v1_hard/` 20 条上的 hit@1 | **≥ 0.60**（基线 0.40） |
| Q2 | 单次查询的额外延迟 | **< 300 ms** |
| Q3 | 在 gold 全体 85 条上不得倒退 | ≥ 0.909（基线） |

**选择与报告分离**：改写器的任何可调项（提示词版本、是否拼原句、检索条数）
只在 gold 的**验证半**上选；留出半与硬改写集只报数、不选参。

## 怎么搭（跑之前定死）

- 改写器：本地 `qwen3-4b`（Ollama，`temperature=0`，thinking 关闭），
  输入是原提问 + 一条指令，输出一句"接近记忆写法"的问句；
- 检索：改写后的问句与原问句**各检索一次，取并集**（不是只用品改写结果——
  改写可能丢掉原句里的名字）；
- 嵌入：`local/bge-small-zh-v1.5@512`；权重沿用 1.2 / 0.45 / 1.5（已标定）；
- 延迟：只计改写那一次生成的墙钟时间，不含检索；
- 种子：生成温度 0，故改写是确定性的；仍需跑 3 次确认逐字相同。

## 失败长什么样

- 若改写后的问句与原问句高度相同（字面重合），说明模型没在改写、只是复述 →
  记录"改写无效"，不是"检索无效"；
- 若并集让 gold 上的精确类下降（Q3 不过），说明改写引入了噪声候选；
- 若延迟超 300 ms，则这条路线在产品上不可用，无论命中多高。

## 跑之前的预期

改写大概率能抬高命中（它直接对准"字面差距"这个失分来源），但**延迟很可能是
硬约束**：qwen3-4b 在 8GB 显卡上生成一句 20–40 字问句通常要几百毫秒到一秒。
如果 Q2 不过、Q1 过，结论应写成"有效但太慢"，并给出离线/异步改写的替代方案，
而不是悄悄放宽延迟门槛。
