## 当前状态

**屏幕识别与语音输入——两条接缝填上了。** 输入框旁边多了一个麦克风按钮（离线识别，
声音不出这台机器），工具表里多了一个 `look_at_screen`（看一眼屏幕，**一次一授权**）。
两件都按当初登记接缝时写下的形状落。值得记下来的几件事：

* **语音：库随产物发，模型不。** 冻结产物里装不了 pip 包——不随产物发的话，打包版的
  语音输入根本不可能工作；而模型（约 42 MB）与"Ollama 的模型要你自己 pull"同一个姿态，
  由用户解压到数据根下的 `models/`。找不到时说一句人话（去哪儿下、放到哪个目录）。
* **采集留在界面线程，解码去工作线程。** `QAudioSource` 的 `readyRead` 是属主线程的信号，
  搬它要自己管一个事件循环与一次对象迁移，而采集本身极轻。解码**边录边喂**，收尾那次
  只剩尾巴——否则一段 30 秒的录音要在最后一起解码，那一下足够超过线程收尾的 3 秒预算
  （超时的表现是 `0xC0000409`，没有回溯、没有 stderr）。
* **截图那一步多了一次交接。** `grabWindow` 必须在界面线程，而工具跑在 worker 线程。
  所以把闸门那套握手抽成 `agent/handoff.py` 的通用槽，截图是它的第二个实例——而
  **token 是承重件**：不回带身份的话，一次超时之后才慢吞吞回来的图会被下一次截图吃掉，
  模型描述的就是三秒前那张屏。
* **图只在当前这一轮活着。** 结果标 `replayable=False` → L5 整对跳过 → **像素永不落盘**，
  `store.py` 与 `assemble.py` 的 schema 一个字都不用改。而"看过屏幕的那一轮不写记忆库"
  是**另一道闸**：不关它的话，模型对屏幕的那段文字描述会以答复正文的身份进库，而它恰好
  是最有信息量的那一段。
* **能力门走 `read_file` 那个先例。** 模型看不见图时 `look_at_screen` **根本不登记**
  ——省一段 prompt、省一次必然失败的调用，也不弹一张注定白点的确认卡片。
* **打包这一步出了两个"构建全绿、用户那边不能用"的洞。** 一，`vosk` 的 C 库靠一句
  **运行时拼出来的** `dlopen` 加载，静态分析看不见，默认构建一个字节都不收——而它的
  Python 包好好地进了 PYZ，所以"缺失清单"那条判据**挡不住它**。二，多媒体的 FFmpeg
  运行库（18.7 MB）留在产物里没有剔：剔掉之后接手的是 Media Foundation 那个后端，而
  实测只能证明**它枚举得出设备**，证明不了它录得到音。前一条的正确做法是
  `--collect-binaries vosk` 加一条正向的布局断言，两条都写进 `_check_layout`。
* **语音那条路在真机上还有两个洞，都是"装了模型才会撞到"的。** ① `_begin_voice` 只把
  "正在听"推给了网页、**漏了 `MainWindow._voice_state`**——于是按第二次什么都不发生：
  录音不停、解码线程不收尾，按钮一直显示"正在听"而永远拿不到文字。它躲过了 gui 腿，
  因为那些测试是**手写** `_voice_state = "listening"` 的（照着"本该如此"写，而实现漏了
  一处）。修法是收成唯一入口 `_set_voice_state()`。② 那两条录音测试**依赖本机有没有
  模型**：它们直接跑真的 `DecodeWorker`，模型一装上就走进成功那一支、撞上替身没有
  `start` 而红。现在识别器是注入的。
* **云端那条路也做得成了，而且我第一版把它说错了。** 用户拿 `deepseek-flash`（DeepSeek
  官方唯一支持图片输入的那个模型）问"你能不能看我的屏幕"，得到的回答是"我没有屏幕接口"
  ——我当时的解释是"云端那条协议装不了图"。**那句是错的**：协议收图，只是**只认 `user`
  行的 content 分片**，而我们把截图挂在 `tool` 行上（那儿的 content 是字符串）。
  真正拦住它的是两件事：① 客户端没见过带图的 `user` 行；② 云端不报能力，于是那个工具
  根本不登记。修法：后端用一个约定属性 `images_ride_on`（`"tool"`/`"user"`）声明图挂哪
  一行，循环按它分派——云端那条路把截图**另起一条 `user` 消息**捎过去，而那条消息
  **不进逐字稿**（同 `_WRAP_UP_NOTE` 的纪律）；云端的能力判据改成**问用户**
  （设置 → 工具 → 「当前模型看得见图」，`ToolSettings.cloud_vision`，默认关）。
  **教训记下来**：把"我们没实现"说成"对方不支持"，会让人往一个改不动的方向使劲
  （他会去反复换模型，而每一换都一样）。
* **顺带修掉一个"应用根本起不来"。** `WebBridge` 上少了 `voice_toggled` 这个信号
  （槽里发的是 `ChatView` 上那个**同名**信号，两个 `self` 是两个对象），构造对话区的
  那一刻就 `AttributeError`。四条腿一条都没拦住，因为**没有任何一条测试构造真的
  `ChatView`**（离屏下 QtWebEngine 一渲染就把进程硬杀掉，见 gui 腿那条纪律）。
  补的是 `tests/test_bridge_contract.py`：纯源码分析、在核心腿里跑，两个方向都钉
  ——连的那一侧必须存在，发的那一侧必须属于自己。

**记忆放在哪，用户自己定。** 设置里多了一个「数据」页：显示**现在用的是哪个文件夹**、
它**听谁的**（默认位置 / 你选的 / 便携指针文件 / 环境变量），并提供「更改位置」与
「恢复默认位置」。换位置走的是**搬迁**：先把整棵数据根复制到新地方、逐文件按哈希校验，
通过之后才改指针，然后重启一次生效。指针记在注册表里，所以**删掉解压出来的那份、
重新下载一个新的，记忆还在**。

四件事是刻意的，值得记下来：

* **搬迁跨一次重启**（点击只写一条标记，真正复制发生在新进程打开任何东西之前）。原地
  搬需要在同一个进程里停掉四条线程、关掉记忆库、搬、校验、改指针、重启，而
  `MainWindow._shutdown` **刻意不关库**（那段注释专门挡住将来那句好心的 `close()`）。
  好处是任何时刻断电，盘上只有两种状态：源完整，或者源完整 + 目标完整。
* **源一个字节都不改。** 复制并校验通过之后才问一句"旧的那份删不删"，**默认不删**。
  删源用的是 `shutil.rmtree` 之外的算法——不用 `shutil.move`（跨卷时它先删后拷）、
  不用 `os.replace`（Windows 上要求目标目录不存在）。
* **优先级四档**：环境变量 `AXO_DATA` > 程序文件夹旁的便携指针文件（**只读，程序从不
  创建它**）> 注册表里那个 > `%LOCALAPPDATA%\axo`。`AXO_DATA` 保持最高是因为全部测试
  与打包自检都靠它做隔离。
* **首启多了一个向导**（欢迎 / 记忆放在哪 / 人设 / 模型 / 完成）。它问过的人设那一步之后，
  对话区那张首启卡片自己就不来了（连的是同一个槽，零新逻辑）；而**跳过整个向导 ≠ 回答了
  人设**，那时卡片照旧出现。走没走过记在 `app/onboarding_done` 里——**这里刻意没有沿用
  卡片那条"由状态推导"**：向导里有两步不留下任何痕迹，"推导"出来的判据会每次启动都把
  向导弹回来。

**P2 完成——看得见她记得什么。** 顶栏「记忆」开一个独立窗口，里面是全部条目（含人格锚），
可以改正文、软遗忘、彻底删除，每一条都能查「本轮它为什么被注入／为什么没被注入」，还可以
「以它为线索召回一次」看它在库里的邻居。顶栏另有一条上下文指示灯，数值与右侧账本**同一份
来源**。细节见 [README](../README.md) 的「记忆界面」。

**云端后端——填一个 API key 就能用 DeepSeek 这类模型。** 后端页从「一个服务地址」
变成两组：本机 Ollama，或者**云端的 OpenAI 兼容端点**（地址 + API key）。三件事值得单说：

* **key 用 Windows 的 DPAPI 按「当前用户 + 这台机器」加密之后才落盘**，设置文件里不是
  明文。换台机器或换个账户就解不开——那时**当成没配过**（回一句"没配 key"），不崩，也不
  假装连上了。
* **对话走云端，嵌入仍走本机 Ollama。** 这条不是取舍而是前提：多数云端厂商没有嵌入端点，
  而记忆的召回、回填、探针整条路都靠向量。所以云端模式下**本机仍然要有一个嵌入模型**，
  清单也仍然问 Ollama 要（与对话用哪家无关）。列表因此是**两份**，不是一个。
* **发出去的东西要说清**：这一轮的对话**以及被召回注入的那几条记忆**都会送到那个地址的
  运营方。设置页的云端组里就摆着这句话。记忆库本身、嵌入向量、逐字稿仍只在本机。

同版还有两件小的：**自动巩固不再往对话区写那一行**（它从此在人前完全无声，见
[memory.md](memory.md) 的「睡眠巩固」末尾那条登记），以及**按钮换成了磨砂玻璃那一套**——两边各自能做的不一样：Qt 外壳这
一侧只能拟态（QSS 没有 blur、没有 box-shadow，窗口底色也是不透明的），靠一层半透明渐变加
**上下两条亮度不同的描边**（顶边是光、底边是影）读出厚度；网页对话区那两处才是真的
`backdrop-filter`，因为只有那一侧背后真有壁纸，而且还能多给一道真投影。

那对描边里最要紧的是**顶底取的不是同一支颜色**。填充走 `fg_strong`（暗态白、亮态黑——
"离开背景"的方向随主题反转），边走的却是**该模式下最亮与最暗的那两个 token**（光就是白
的、影子就是黑的，不随主题反转）。混用的话，亮态那条顶边会是一道**黑**线，而描边是压在
填充之上的，叠黑只会更黑——屏幕上就是"光从下面打上来"。这条不是推的，是量出来的：
`tests/test_ui_theme_glass.py` 抓真渲染出来的像素来比（两次渲染对照：同一格把这道边擦掉，
看那一格有没有被推往设计的方向）。

**随后一次收口：路由补上"查记忆"那一族，环境槽那句事实换了措辞。** 两件事同一个来源——
用户实测打了一句「晚上好」，回头问"是不是 DeepSeek 用不了工具"。

* **能查记忆的说法原先整族漏在词表外**（"查看我的记忆"/"记忆里"/"我上次…"/"回想"/
  "记录一下"/"念一遍"/"别忘"），而查记忆**天然是问句**，正好被"句末问号 → 闲聊"那条规则
  吃掉。后果不是"答得不好"，是那一轮**一个工具都不声明**，模型只能照环境槽那句事实编一句
  "我无法使用工具查看记忆"——看起来像模型推卸，实际是路由没给它工具。补表之后 120 条语料上
  `hard` 类判对 **7/8**（原先 **0/8**），其余八类**一条没动**。
* **环境槽那句事实去掉了"做不到"的能力清单**（理由见「几个刻意的取舍」末尾）——那个清单
  会被原样背成能力免责声明，而它正是上面那句"我无法使用工具"的来源。

同时真的把"不许声称你调用了工具"补进了人格锚：它此前**哪里都没有**过（L1 不肯写它，写了
就是指令；L0 里也没有）。补它需要给内置锚配版本号与升级路径，所以那是**另一条收口**，
理由、版本记录与"它是一句要求不是闸门"的界限都在下面「几个刻意的取舍」末尾。

**同一族上的再一轮：歧义率 0.1667 → 0.1500，而"没压下去的那五条"才是这次的结论。** 那 20 条
亮标志的里只有 8 条**可压**——另外 12 条是语料故意构造的"一个标记词都没命中"，所以这个指标的
**地板是 0.10**。压掉的两条都不是靠加词：第 3 条从"整句**精确等于**一个应和词"放宽成"**全句
由应和词拼成**"（"好的，知道了"原先落在"判不出来"），外加 `心情` 进"情绪与状态"那一族。**剩下
五条放弃**：`梦`/`雨`/`花` 那一路能把 `chitchat` 的歧义**清成零**、看起来最像"压到位了"，但它们
是话题名词不是语域信号。理由与账都在 `benchmarks/routes/CORPUS.md`。

**上一版：睡眠巩固（P4c）。** 这是第一件**在后台自己改库**的事，所以它值得单说：

* **一轮做三件事，次序是要紧的**：拍一份整库快照 → 按关联图分簇、每簇在**自己那一小块 W**
  上做「挖掉一半、看还认不认得自己」的回放 → 认出自己的那些**「巩固次数」+1**。
* **它每天自己跑一次（默认开）**，跑完在记忆界面那句「SNN 热度」里留下真数字；托盘菜单与
  设置页「记忆」各有一个「立即巩固」，随时能按。
* **它只动「巩固次数」**——不改记忆正文、不改权重、不影响召回排序，改之前拍快照、留最近
  5 份。
* **认得出来多少，量在纸上，而这一次的结论是"没有结论"**：合成语料分不开"分簇解决了容量"
  与"那份语料自己的近重复压住了辨认率"。这是如实交付的一部分，不是没做完。

细节见 [memory.md](memory.md) 的「睡眠巩固（P4c）」。**P4a 与 P4b 没有改出厂行为**（前者只
交付一个数、后者的联想通道默认关），所以它们不进这一节，分别写在 [memory.md](memory.md)
的「关联基质量具：图 A 与 W」与「联想通道与邻居面板（P4b）」。

**更早：任务记忆、托盘与定时触发（P3b）。** 三件事，都是 P3a 留下的接缝的兑现：

* **关窗不再等于退出。** 窗口收进系统托盘，进程继续活着（这是下面那件事成立的前提——
  关窗即退的进程在"到点了"那一刻已经不在了）；真退出走托盘菜单的「退出」或 Ctrl+Q。
* **提醒真的会响。** `set_reminder` 从 P3a 起只落盘，现在到点弹气泡 + 在对话区留一条；
  程序没开着时错过的那些，下次启动聚合成**一句**，不逐条弹也不静默丢。
* **一轮任务可以只记一条。** 设置里「记忆」页一个勾选框（**默认不勾**）：勾上之后，调过
  工具的那一轮落一条 `TOOL_RESULT`，正文是回复、`meta` 里带工具轨迹；没调工具的那一轮
  逐条照旧——**那是个加法**。

细节见 [agent.md](agent.md) 的「托盘与定时触发」。

**更早：工具与语域（P3a）。** 模型**真的能动手**：七个工具（查记忆 / 读记忆 / 写记忆 /
遗忘 / 看时间 / 设提醒 / 读文件）在对话里可用，**改变状态的那三个要你在对话流里点一下
内联卡片才执行**，没点就是不做。哪一轮给不给工具由**语域路由**决定（斜杠命令 + 一张手写
的标记词表 + 一个默认关着的模型自分类），路由本身由 `benchmarks/routes/` 那 129 条语料
离线量着走。工具轮次写进逐字稿并能回放，界面上显示的是**真实的调用轨迹**、不是模型的
自述。细节见 [agent.md](agent.md) 的「语域、工具与确认闸门」——**那里有两条必须辨析的术语**。

**更早：金标准测试集 + 四项指标 + CI。** 它是闸门型资产——换嵌入模型、调 K、调阈值都要它
兜底。此前量具只有 `bench_space.py` 的 20+20 对，量的是**配对级的分隔度**（一句话对一条
记忆的 Jaccard 能不能分开），**没有候选池**，所以真正决定召回行为的 K、阈值、MMR 去冗、
token 预算驱逐一条都没被量到。那一版建出 `benchmarks/gold/`（200 条虚构记忆 + 76 条带
ground truth 的查询）、四项指标 **hit@K / MRR / 误注入率 / AUC**、`tools/bench_recall.py`，
并把门槛接进 CI 与每次提交。细节见 [bench.md](bench.md) 的「金标准集与门槛」。

**更早：首次使用时定一次人设。** 人格锚从一条变成两条——一条是程序内置的**事实**
（不可改、不可删，保证任何模型读到的身份完全一样），一条是你写的**说话方式**（可改、
可删）。全新的记忆库第一次启动时，对话区里出现一张卡片问一次，**答完之前输入框是灰的**；
以后在「设置 → 人设」里改。把你写的那条删掉，下次启动会重新问一次。细节见 [README](../README.md) 的
「首次运行：定一次人设」。

**更早：外观可调 + 一个能长大的设置窗口。** 主色三预设或自定义取色、壁纸只铺对话区且
可见度可调、明暗跟随系统（Qt 外壳与网页对话区**由同一次判定驱动**，不会一边白一边黑）；
顶栏加了「设置」，里面除了外观还有后端 / API 页。顺带修了三处布局硬伤：窗口初始尺寸按
屏幕算、三格分栏不再能被拖没、会话列表改成两行式。顶栏状态文字那一处**反而坏了**：换成
`ElidedLabel` 之后，它用的 `QSizePolicy.Ignored` 让布局把标签宽度算成 **0**，状态文字从
"会被硬裁"变成**一个字都不显示**，真正修好是 2026-10-10 那次（见 [operations.md](operations.md) 的「跑测试与 CI」里那段）。
当时验收看的是 `text()`，而 `text()` 一直是对的；要看的是"布局到底给了多少宽度"。

> 消费的全是 P1 已经产出的数据（条目、权重、逐条账本），**不引入新的研究风险**。P3 拆成
> 两版同理：**任务记忆要有工具调用才有内容可记，托盘要有后台任务才需要常驻**——两件的
> 依赖都在 P3a 里，所以它们排在 P3a 之后，而不是把 P3 一次做完。
>
> **P4 拆三版**（原来是"一行字装五件事"）：另外三件（三通道召回、联想可视化、睡眠巩固）
> 全都挂在基质上，而没有基质就无从谈起"第三通道值不值"。而且它是 P4 里**全部研究风险**
> 的所在——所以在接线之前先把它**建出来并量出来**。P4a 因此有一个反直觉的性质：它交付的
> **是一个数，不是一次行为变更**（`RecallConfig.graph_weight` 保持 0、`recall.py` 一个字
> 没改、`ChannelScores.graph` 保持恒 0）。理由见 [memory.md](memory.md) 的「关联基质量具」那一节。
>
> **P4b 的形状由 P4a 那个负数决定**：通道**接上了，但默认仍然关**。它交付的不是"联想通道
> 上线了"，而是"联想通道**可以**打开、打开要付什么代价已经量在纸上、图本身能看了"。
> 界面那一半（局部邻居列表）与召回那一半是两件事：前者展示图的**结构**，它成不成立
> 不取决于第三通道在召回里有没有增益。
>
> **P4c 的形状同样由那个负数决定**：既然"全库一个 W 一步补全"在 n≥500 上就塌，回放就
> **先按关联图分簇、再在每一簇自己的 W 上问"还认不认得自己"**——容量的作用域从全库缩到
> 簇内，上限取那条曲线上**唯一还活着的实测点**（n=200）。它交付的**不是**"回放认得出来"，
> 而是"认得出来多少**已经量在纸上**"：在合成语料上仍然随规模掉，而掉的原因是**那份语料
> 自己的近重复**、不是分簇——所以这里**没有**"分簇解决了容量"这个结论。见
> [memory.md](memory.md) 的「睡眠巩固（P4c）」与 `benchmarks/substrate/CORPUS.md`。
>
> **P5 那一行为什么是「未定义」。** 「项目仪表盘」这五个字从 `889c6d2`（P0 那一版）起就在
> 表里（当时还叫 `P4`，`git log -S` 追得到），但**它从来没有过定义**：没有设计稿、没有
> `project/` 包、没有验收标准。中间几次拆版（P1.5 插入、P3 与 P4 各自拆、云端后端抽成
> 不编号的「后端」行）只让编号平移，内容一次也没长出来。
>
> 2026-10-11 定下来：**这个终端是独立于 BioSNN 的工具，不是 BioSNN 第五阶段的实验台。**
> 于是那张面板仅有的两种含义都不成立——它既不是**给人看基质状态**的展示件（要看的东西
> P4b 的联想可视化与 P4c 的「SNN 热度」已经放进记忆界面了），也不是**量指标**的地方
> （BioSNN §九 那四个「调用决策」指标是另一个项目的事）。**写不出验收标准的东西不排期。**

> 的落点是托盘气泡或顶栏状态句多一句，不是一个面板）。届时内容由那个问句定死，并且
> **不要重做** P4b 的联想可视化与 P4c 的 SNN 热度。

P3a 的四项交付与各自的验收：**能在对话里真的用上七个工具**（`/task 帮我查一下…` 时模型
发出真实的 `tool_calls`，界面显示调用轨迹而不是模型的自述）、**改状态的过内联卡片确认**
（三个工具，点允许才落库，不点就是不落）、**路由可离线量**（`benchmarks/routes/` +
`tools/bench_router.py --no-model --check`，进 CI 与 pre-commit）、**逐字稿能回放工具轮次**
（`session/store.py` schema 3 加可选字段，老行逐字节不变）。

P3b 的三项交付与各自的验收：**一轮任务合成一条记忆**（设置里的「记忆」页勾上之后，调过
工具的那一轮只落一条 `TOOL_RESULT`，正文是回复、`meta` 里带工具轨迹；没调工具的那一轮
**逐条照旧**——那是个加法，不是一个替换）、**关窗不等于退出**（窗口收进系统托盘，托盘菜单
的「退出」与 Ctrl+Q 才真的结束进程；托盘不可用的机器上关窗仍然直接退出，见 [agent.md](agent.md) 的「托盘与定时触发」）、**提醒真的
会响**（`set_reminder` 登记的那条到点弹气泡 + 在对话区留一条；程序没开着时错过的聚合成
一句，不逐条弹、也不静默丢）。三件事的依赖都在 P3a 里：任务记忆要有工具轨迹才有内容可记，
托盘要有后台任务才值得常驻，而"到点了"要有常驻进程在听。

**本版：打包（P6a）——交付形态多了一个免安装的 Windows 目录。** `tools/build_exe.py`
把界面、QtWebEngine、对话区那几张网页资产与图标一起冻进 `dist/axo/`，**机器上
不需要装 Python**（Ollama 与嵌入模型仍然要）。产物不好找——`dist/` 是构建输出、在
`.gitignore` 里，编辑器里是灰的、远端上不存在——所以自检全过之后**在桌面放一个快捷方式**
（名字就是界面上的显示名），双击即启动。三件事值得单说：

* **冻结的入口是新的那一个，源码检出那条路没动。** PyInstaller 收的是**一份脚本**——它
  把入口文件当 `__main__` 跑，`__package__` 是空的，而 `ui/app.py` 里那几处相对 import
  在那种情况下解析不了。所以新增 `src/axo/__main__.py` 专门做冻结入口，它只有
  一句按名字找包的绝对 import（顺带让 `python -m axo` 也能用）。`run.bat` 走的
  仍然是 `python -m axo.ui.app`。
* **应用代码一个字没改。** 网页资产按**与源码相同的相对位置**放进 `_internal/`，于是
  `Path(__file__).with_name("theme.qss")` 那两处读取自动对上——这条假设由构建脚本的自检
  钉住，不成立就当场红，不留到运行时。
* **CI 验不了这一环，所以自检写在构建工具里。** 七条腿全在 `ubuntu-latest`，而 **Windows
  exe 只能在 Windows 上构建**。冻结坏掉的方式几乎都不抛异常（"双击之后什么都没发生"，
  或者"窗口开出来了、左上角空着"），所以 `tools/build_exe.py` 构建完立刻查盘上的事实，
  再真起一次**看有没有开出窗口、窗口上有没有图标**——判据不是"进程还在不在"。四条如实的
  限制见 [operations.md](operations.md) 的「打包（P6a）」。

## 你聊的东西绝不进版本控制

会话逐字稿、记忆库、你选的壁纸、配置——**推上去就收不回来了**，所以这里不靠"记得
别提交"，靠三层各管一段：

| 层 | 管什么 | 在哪儿 |
|---|---|---|
| 默认值 | 数据目录根本不在仓库里 | `src/axo/paths.py` |
| 忽略规则 | 万一指进来，也进不了 `git add` | `.gitignore`（含 `*.jsonl`、`*.db*`、`sessions/`、`wallpapers/`） |
| 断言 | **索引里现在确实没有**——查的是 `git ls-files`，不读 `.gitignore` | `tests/test_repo_hygiene.py` + pre-commit 钩子 `repo-hygiene` + CI |

第三层是唯一"检查结果而不是意图"的一层：前两层写对没写对，它都能给出一个事实答案。
它把 `.jsonl` 一律当逐字稿，只放行**逐个登记**过的量具语料目录（目前三个：
`benchmarks/gold/`、`benchmarks/routes/` 与 `benchmarks/substrate/`）——逐字稿与语料同名，而漏掉一份私人对话
不可逆，多放行一个目录只是多写一行。**登记是一份一份来的，不是"benchmarks/ 下面的都放
行"**：那条更松的写法会让误放进来的 `benchmarks/transcripts/2026-10-10.jsonl` 被静默
放行，而"放行"在这里的含义是"推上去就收不回来了"。逐个登记的另一半好处是，加一份新语料
**必须动那个文件**，于是"这里还有一份语料"在 diff 里看得见。

> 反向的失效**踩过两次，形状一模一样**：路由语料落地时 `.gitignore` 没跟着加放行，于是
> 那份 `utterances.jsonl` 只在工作区里——**本地每条腿都绿**，而门槛、指纹测试、仓库卫生
> 都要等到别人检出之后才会红。P4a 加基质语料时又漏了一次（`memories.jsonl` /
> `queries.jsonl` 被抓在 `*.jsonl` 里）。所以"加一份语料"要动的名单是**两份**：
> `.gitignore` 的放行规则与 `_JSONL_ALLOWED_UNDER`，同一次提交里改完。
>
> 第二次之后补了一条守卫，把"两处要一起动"从一句叮嘱变成一次执法：
> `test_repo_hygiene.py::test_registered_corpus_directories_survive_the_ignore_rules`
> 按 `_JSONL_ALLOWED_UNDER` 逐个目录问"里面的 `.jsonl` 会不会被忽略规则挡住"。它问的
> 问题与上面那条**不重复**——`git ls-files` 看不到被忽略的文件，正是那个盲区让前两次
> 都是绿的。登记了却没放行，现在当场红。

另一件事同样进了机制：`tools/bench_space.py` 的 40 句语料是**全仓唯一"形态上就是
记忆条目"的东西**（第一人称、具体、可查），它曾经写着真实的显卡型号、盘符与相邻仓库
的名字，2026-10-10 换成同形状的虚构事实，并由 `test_repo_hygiene.py` 里一张 denylist
盯着别再改回去。

> 那两张 denylist **自己写着被禁的词**——要拦一个词就得写下它。这是知情的取舍，理由
> 写在 `tests/test_repo_hygiene.py` 的模块 docstring 里：语料的正文已经干净，剩下的
> 只是一张"被禁词清单"，且没有通用规则能代替它。

> **真出了事怎么办。** `git rm --cached <路径>` **不等于**删掉内容——历史里还在，
> 远端还有。要 `git filter-repo` 重写并强推，然后假设那份内容已经泄露（改了历史也
> 清不掉别人 clone 走的副本）。所以这一节的重点是前面那三层，不是这一段。

## 几个刻意的取舍

**对话区是网页，外壳是 Qt。** markdown 流式渲染与 Live2D 都要求完整的 web 引擎；
用原生控件做这两件事等于把标准重写一遍。两者之间用 `QWebChannel` 直连，
**默认不起本地 HTTP 服务器**——不需要端口、不需要令牌、不需要管理服务器生命周期。
唯一的例外是用户显式开启的「手机同步」MemoryBridge：它只在开启时监听，
走加密通道、默认拒绝未配对来源，且只暴露读与追加两个动作。

**会话记录 ≠ 记忆库。** 前者是逐字稿（可以几百兆，可以整段删掉），后者是提炼
出的条目（带权重、分层与关联，删一条会改变图上的边）。混在一起的话，
「清空聊天记录」这个动作就有概率把长期记忆一起清掉。

**记忆的编码有两条轴，别把它们混成一条。** 一条是**模型依赖性**：词法 SDR
（blake2b 哈希，**模型无关**）做相似度、去冗与关联基质的地基；语义 SDR（依赖当前
embedding 模型）走语义通道。若记忆结构依赖 embedding，换模型就等于关联全废——那条
承诺也就不成立了。

另一条是**同一个源上的稀疏度**：在同一个词法 SDR 之上再取一档更稀疏的**关联码**
（k=64，对词法码的 k=573），喂图 A 与神经元级基质 W。它与模型无关（纯哈希子采样），
所以"记忆独立于模型"这条在基质上同样成立——**换嵌入模型不用重建图**。P4a 说的
"双尺度"指的就是这一条；把它读成上一条（词法 / 语义）曾经是一次真实的误读。

**不做**（"轻"的边界）：多用户／云同步；向量库（P ≤ 5 万时 numpy 分块 matmul
约 5 ms，够用）；常驻守护进程（**系统托盘已经落地了，而且它不是守护进程**——那要有后台
任务才需要进程活着，而托盘的存活范围就是"这个程序开着的时候"，退出仍然是用户按一下的
事，见 [agent.md](agent.md) 的「托盘与定时触发」）；自学的人格模型（偏好是规则表，不做 embedding 化的
「性格向量」——那会把性格重新绑回模型）。

**工具循环只加一条消费路径，不动已有的那条。** `tools` 非空才走 `AgentWorker`，为空仍走
`ChatWorker`——**回归为零**是本版的一条硬约束，而合并不带来新能力、却要碰已经稳定的生成
路径。代价是两条路径短期并存会漂移，所以配了一条平价测试与一条写死的移除准则（见 [operations.md](operations.md) 的
「跑测试与 CI」）。

**路由的模型自分类默认关，而且这个默认值是量出来的。** 本机那个 4B 模型在"两个工具该调
哪个"上五轮只对一轮，它不足以可靠地判自己这一轮属于哪个语域。于是 `/task` 这类显式命令
是**主要**的可靠入口，不是便捷方式——这也是为什么路由三段里最先落地的是斜杠，模型自分类
排最后、而且默认关。

**模型仍可能声称做了一个它没做的动作，环境槽只是缓解、不是保证。** 工具是靠请求里的
`tools` 字段声明的，而"字段不存在"与"字段为空"在模型的输入里长得一模一样——它读得到自己
收到了什么，读不到自己**没**收到什么。所以没有工具的那一轮，L1 环境槽会补一句事实：「这一轮
没有工具可用，也不会有任何动作被执行」（`session/environment.py`）。它是**事实**不是
**指令**，两处都写会让人格锚那条"一个字都不许改写"的纪律失去意义。

**这句事实只写"这一轮发生了什么"，不列能力清单。** 列清单的话，**那个清单可以被原样背
回去**：2026-10-11 用户打「晚上好」，模型据它回了一句"我无法使用工具查看记忆"，用户于是
以为工具坏了（真实原因是那一轮是闲聊语域、本来就不该有工具，见 [agent.md](agent.md) 的
「语域、工具与确认闸门」）。所以它写的是一句描述"这一轮发生了什么"的**事件**——说的是同一件事实，但它不能
被反手当成能力免责声明，因为里面已经没有能力可列。`tests/test_environment.py` 里有一条
专门钉住"清单不许回来"。

**"不许声称你调用了工具"这条要求归人格锚，而它此前哪里都没有。** L1 不肯写它（写了就是
指令），L0 里也没有，所以只能落进人格锚的正文——而那段正文只有程序能改：不给它一个升级
路径的话，"这条要求有地方兜着"就只是一句印象。

补它需要一次迁移，因为只改常量是**够不着**的：`ensure_builtin_anchor` 原先在库里已经有内置锚
时直接返回 `None`，于是新装的库有这句、老库没有，"任何模型读到的身份完全一样"会变成"同一个库
上一样、跨库不一样"——那比"大家都没有"更糟。所以内置锚现在带**版本号**，`ensure_builtin_anchor`
多了一个"旧了就原地升"的分支。它改写的只是**内置**那条：那条锚本来就只有程序能改
（`read_only_reason` 拦住界面上的编辑与删除），所以"正文与常量不一致"只有一个解释。

> **人格锚版本记录。** 第 1 版 = 加版本号之前写进库里的那些（**没有版本键**，所以它们是
> 判成"旧"的入口，而不是 0 或"未知"）。第 2 版加了第四句「只说你真的做过的事：只有真的
> 调用过工具才算用过工具，没调用就不要说保存了、记住了或查过了」。第 3 版只是把首句的
> 产品名换成 `Axo（阿螈）`（0.2.0 改名；第 5 版角色名改为 `千岁（阿螈）`），没有一个字的语义变化。第 4 版把首句从
> 「你是 Axo（阿螈）的**助手**」改成「你是 Axo（阿螈）」——用户自己那条人设里写的常常是
> "你就是 Axo"，而内置这句把她叫成"助手"，两条锚会同时进系统提示、当着面打架；让开的是
> 内置这一句，因为它本来只写"关于这个系统的事实"，而"她算不算助手"不属于事实。
> 改 `DEFAULT_PERSONA` 就要把 `BUILTIN_PERSONA_VERSION` 加一，并在这里添一行。
> 升级只在启动时跑一次，且**会在对话区说一句**（"已从第 1 版升到第 2 版"）——改的是模型
> 读到的身份正文，用户看不见那次改动，不说就是一次静默变更。

**这一句是一句要求，不是闸门。** 下面那段实测的否定结果它管不了：真正挡住"说了没做"的仍然是
对话流里那行**真实工具轨迹**与动作的确认闸门。

**而那句事实在最该起作用的那一次没有起作用——这是实测的否定结果，不是推测。** 2026-10-10
那句露骨提示词（"调用 `write_memory` 工具，参数 content 填「我最喜欢的颜色是靛蓝」"）被路由
判成 `ambiguous=True / tools=False`，也就是说**这一轮确实没有工具**、**两句事实都在提示词
里**（拒绝的那句不在，因为这一轮根本没走到闸门），而模型照样回了"已通过 write_memory 工具
保存记忆……该记忆已写入本地文件系统"。所以"降低概率"这个说法要收紧成：**在本机这个 4B 模型
上，它没有拦住已经发生的那种幻觉。** 唯一的事实来源仍然是对话流里那行**真实工具轨迹**，
而不是模型的自述——界面上显示的就是前者。
