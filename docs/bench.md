## 金标准集与门槛

`memcore/recall.py` 有九个可调参数，而在 P1.5 之前**没有任何东西能告诉你改了一个参数之后
变好了还是变坏了**。金标准集补上那个缺口：`benchmarks/gold/` 下 200 条虚构的海洋观测站
记忆 + 76 条带 ground truth 的查询，每条查询都跑真正的 `recall()`，落一份逐条账本，再算
四项指标。

**它是量具，不是数据集**，所以它的数字进 CI 当**门槛**——"不恶化即绿"，不是"召回很好"的
声明。语料的冻结纪律、十一类难例的构造、以及一份留档的敏感度实测写在
`benchmarks/gold/CORPUS.md` 里。

### 四项指标的精确口径

记号：查询 $q$ 的期望集 $E_q$、可选集 $O_q$、注入序列 $\mathrm{inj}_q$（顺序 = `recall`
返回顺序 = MMR 选择顺序 = 模型在提示里看到的先后），$\mathrm{topK}_q = \mathrm{inj}_q[:K]$。

- **hit@K** = $\frac{1}{|Q_{ans}|}\sum_q \mathbb{1}[E_q \cap \mathrm{topK}_q \ne \varnothing]$，
  macro，$K \in \{1,3,5,8\}$。分母 $Q_{ans}$ 只收**有答案的**查询——`no_answer` 那类
  （库里确实没有）不进分母：把"我们没有编造"算成一次没命中，是在给自己制造假失败。
- **MRR** = $\frac{1}{|Q_{ans}|}\sum_q \frac{1}{\mathrm{rank}_q}$，未命中**计 0**（不是
  排除）。只对命中者算的那个另报为 `mrr_answered`，**不进门槛**——门槛绑的是把"答不出"
  算进去的那个。
- **误注入率** = $\frac{\sum_q |\mathrm{inj}_q \setminus (E_q \cup O_q)|}{\sum_q |\mathrm{inj}_q|}$，
  **micro**（按注入条数汇总，不是按查询平均）。`optional` 不算错——判它错会把"去冗做得
  好"变成一个负分项。这个口径在槽位填满时会饱和（每条 1 条正确、8 个槽位 → 上限
  0.875），所以它主要响应"注入了多少条"；排得准不准由 hit@K 与 MRR 管，两者互补。
- **AUC** = $\frac{\#\{s_p > s_n\} + \frac12 \#\{s_p = s_n\}}{|P| \cdot |N|}$。正集是
  $E_q$ 各条的 `fused`，负集是库里不属于 $E_q \cup O_q$ 的条，逐查询配对后 pooled，
  并列按 ½ 计。**它因此是上界**：`fused` 只由通道得分与通道权重决定，与 `min_score`、
  `max_items`、`budget`、`mmr_lambda` 全都无关，所以 AUC 描述的是"这个打分函数能不能把
  对的排在错的前面"，在任何阈值下都成立。

四项都取的是**最稳的代表**：per-category 的数字照报，但**不进门槛**——n≈5 时标准误约
0.18，拿它当判据等于每天红一次。

### 怎么跑

```bash
uv run python tools/bench_recall.py                     # 报告；探测到 Ollama 就用语义通道
uv run python tools/bench_recall.py --no-semantic       # 纯词法，不探测（CI 与 pre-commit 用这条）
uv run python tools/bench_recall.py --no-semantic --check   # 与基线比，跌破容差即退出码 1
uv run python tools/bench_recall.py --no-semantic --json    # 额外一份机器可读报告
```

退出码有含义：**0** = 达标（或只是报告）、**1** = 跌破基线容差（**不是程序出错**，意思是
"召回行为比登记在案的基线差了"）、**2** = 用法或环境不对、**3** = 结构不变量被违反——
那既不是"变差"也不是"没配好"，**是 bug**。

> **门槛只绑词法通道**（`--no-semantic`）。词法 SDR 是 blake2b 哈希编码，不需要模型、
> 不需要网络、不需要 GPU，所以它在 CI 与每次提交里都跑得动；把门槛绑在语义通道上等于让
> "有没有装模型"决定提交能不能过。语义数字仍然会报，它的价值是回答"换一个嵌入模型会不会
> 更好"，那不是一个 CI 判据。
>
> 一个直接的后果，别误读：本机 40 对短句上词法 AUC 已是 0.884，这套语料上是 0.909——
> **离线 AUC 逼近的是词法打分函数自身的天花板，不是系统上界**。本地带 Ollama 跑过一次
> `--semantic` 作对照（数字记在 `CORPUS.md`）：**AUC 从 0.9093 涨到 0.9243，而 hit@8
> 从 0.9559 跌到 0.8971、误注入率从 0.8205 涨到 0.8902**。排序变好而用起来变差，因为
> `min_score` 那个初值是按**词法量纲**标定的，多一条通道就把一批不相关的也抬过了它。这正是
> "本版只报告、不改默认值"的原因：换通道组合要重标阈值，而那要真实库上的数据。

### 语料是量具，不是文档

改它等于换了一把尺子。四道锁缺一不可，全部写在 `benchmarks/gold/CORPUS.md` 里；这里只
记**改语料时要动的三处**（必须同一次提交）：两份 JSONL → `freeze.json` → 重跑
`--freeze` 更新 `baseline_lexical.json`。少任何一处都会红，而失败消息直接写出还差哪个。

```bash
uv run python tools/bench_recall.py --no-semantic --freeze   # 重算基线（强制重跑，不接受手工输入）
```

**门槛的红不是"程序出错"。** 先分流：语料被改过（sha256 不符）、召回行为真的变了（指标
跌破容差）、还是结构不变量被违反（pinned/cold/excluded 被注入——**那是 bug**，别当"数字
不好看"顺手把容差调宽）。`--check` 会把前两条线索都打出来。

### 第二把尺子：路由语料

`benchmarks/routes/` 是金标准的**同位体**：那一个把记忆灌进 `:memory:` 库再逐条召回，
这一个把输入逐条喂给路由。区别只在被测对象，纪律一套——语料是**量具不是数据集**，冻结
判据同样是 `sha256(原始字节)`，同一份 denylist（`bench/corpus.py::PERSONAL_DENYLIST`）机械
执行。131 条虚构输入分十一类（斜杠 7 / 祈使 24 / 问句 14 / 闲聊 25 / 歧义 13 / 否定 10 /
重复与纯标点 8 / 长任务 12 / 提醒 3 / 屏幕 5 / 今天还判错的 10），每一条为什么这么构造写在
`benchmarks/routes/CORPUS.md` 里。

```bash
uv run python tools/bench_router.py --no-model            # 只有规则层，不探测（CI / pre-commit 用这条）
uv run python tools/bench_router.py --no-model --check    # 与基线比，跌破容差即退出码 1
uv run python tools/bench_router.py --no-model --freeze   # 重算并覆盖基线
```

**两把尺子，不是一个。** 门槛只绑**规则层**（纯函数、离线、确定性）；**模型自分类照报不
进门槛**——它要 Ollama，把门槛绑上去等于让"这台机器装没装模型、装了哪个"决定提交能不能过
（与召回那边只绑词法通道是同一条纪律）。"该不该把模型自分类打开"正是那份报告要回答的
问题，而它不是一个 CI 判据。

**`accuracy` 与 `coverage` 必须成对看。** 这一层有一档"我不知道"（歧义 → 退回闲聊并反问），
所以：只看准确率，一个把 40% 的输入都推给用户确认的规则层能接近 1.0——那正是最该被看见的
退化；只看覆盖率，一张"什么都判 task"的表能拿满分。报告因此印三个数：`accuracy`（分母是
**敢判的那些**）、`coverage`（敢判的比例）、`accuracy_all`（放回全长度，包含蒙对的）。
再加一个 `majority_baseline`——**它是底线不是成绩**（首次实测 0.6083，说明这份语料闲聊占
多数，任何准确率都要先减掉这层水份）。

**容差 0.02 不是采样噪声。** 这份测量是确定性的（同一份语料跑两遍逐位相同，有一条测试钉住
它），没有任何随机来源，所以按统计学算标准误在这里是错的。0.02 折成条数大约一到两条，取
这么紧是因为**这张表是手写的、每次改都是一个词**——改一个词而弄坏了另一条，正是这个门槛
要抓的那件事。反过来，改善只会把数往上推，任何时候都是绿的。

**「今天还判错的 10 条」进门槛，金标准的近义改写不进。** 分界线不是"难不难"，是**够不够
得着**：这 10 条里每一条都够得着——加一个同义词、补一条否定式的正向读法、挪一条优先级，
都不需要模型也不需要网络（其中两条刻意不收，理由在 `CORPUS.md`），所以它们是**可见的待办
清单**，账记在准确率的分母里；近义改写要语义通道，离线腿够不着，只能只报告。

> **首次实测（规则层）**：覆盖 0.7917 / 准确率 0.9684（含"不知道"一起算 0.9333）/ 任务查全
> 0.9524 / 闲聊查全 0.9811。这张表在"敢判的那些"上已经很准，**短板是覆盖率**——25 条亮了
> 歧义，其中 8 条其实是过度谨慎。完整报告、分类别数字与那 8 条判错的清单在 `CORPUS.md`。
> **模型层的数一次都还没有**（要跑 120 次 Ollama），`baseline.json` 里 `model_layer` 是空的，
> 这是有意留白。
>
> **2026-10-12 追记：上面那句"加一个同义词就能修好"兑现了 7/8。** 那 8 条里有 5 条是同一族
> （"去看已经存下来的东西"，被"句末问号 → 闲聊"整族吃掉），补进词表之后 `hard` 类判对
> **7/8**，覆盖 0.7917 → 0.8333、准确率 0.9684 → 0.9900，**其余八类一个数没动**。剩下那条
> `u-0113`（"谢谢你帮我查资料"）是刻意不修的，理由在 `CORPUS.md`。基线与这份追记的差不是
> 漂移——门槛是相对闸门，改善不重新冻结。
>
> **2026-10-12 再追记：语料补了一族，120 → 125 条。** 提醒那条链的两个新工具落地时，漏了
> "在同一个提交里补语料"这一步，这一轮还上：新增 `reminder` 类 3 条（那两个工具的入口词就是
> 照着它们挑的）+ `hard` 2 条。**这一次必须重冻基线**——语料指纹变了，不重冻就是拿两把尺子
> 比（`test_baseline_row_was_frozen_on_this_corpus` 会核）。地板随之从 0.9684 / 0.7917 抬到
> **0.9811 / 0.8480**。新加的两条 `hard` 里，一条是判错的、一条是判不出来的，两条都不修的
> 理由写在 `CORPUS.md` 那一节里。
>
> **2026-10-12 第三次追记：又补了一族，125 → 129 条。** 屏幕识别落地时量到同一个机制：
> 「屏幕上写了什么？」「你屏幕上现在是什么？」在标记词表里一个都不命中，于是被「句末问号
> → 闲聊」整族吃掉——那一轮不声明任何工具，用户看到的是"这功能没做"。补的是**两个方位
> 说法**（`屏幕上`/`我的屏幕`），不收光杆名词 `屏幕`（"屏幕看久了眼睛疼"是闲聊）。
> 新增的 3 条 `screen` 全对，另加一条反空转对照（含"屏幕"但必须留在闲聊）。
> 语料指纹变了 ⇒ 又一次**强制重冻**：地板 0.9811/0.8480 → **0.9817/0.8450**。
>
> **2026-10-12 第四次追记：129 → 131 条，同一个机制第三次。** 上一个提交刚落地，用户在
> 真机上问了一句表里没有的说法——「我屏幕现在是什么」（**省了那个"的"**）——它落进闲聊
> 语域、一个工具都不声明，模型只好如实说"我这一轮没有工具可用"，而用户看到的是"它说没有
> 工具"。收 `我屏幕` 这个词（暴露面与已有的 `我的屏幕` 完全一样），加两条 `screen` 见证
> （第二条不含「屏幕上」，是第二个独立见证）。**两条新语料全对，其余 129 条一条没被带偏**：
> 准确率 0.9817 → 0.9820、覆盖率 0.8450 → 0.8473，两项都往上走 ⇒ 地板重冻到
> **0.9820/0.8473**。
