# 换嵌入模型：nomic-embed-text vs 随包 bge-small-zh（2026-11-01）

动机：分类拆分显示失分集中在 `paraphrase`（0.2）与 `redundant_pair`（0.4），而权重扫描
证明**瓶颈不在融合权重**、在语义通道本身。所以换模型、不动权重，做一次干净对比。

跑法：

```bash
python tools/bench_recall.py --model nomic-embed-text --json                      # Ollama
python tools/bench_recall.py --local-embed build/bundle/embedding/bge-small-zh-v1.5 --json
```

## 结果（gold 85 条查询，权重同为 1.2 / 0.45 / 1.5）

| 指标 | nomic-embed-text (768) | **bge-small-zh (512)** | 差 |
| :--- | ---: | ---: | ---: |
| hit@1 | 0.831 | **0.909** | **+7.8pp** |
| hit@5 | 0.909 | **0.974** | **+6.5pp** |
| paraphrase | 0.200 | **0.600** | **+40pp** |
| redundant_pair | 0.400 | **0.600** | +20pp |
| distractor_topic | 0.750 | **0.875** | +12.5pp |
| exact | 0.875 | 0.875 | 0 |
| budget | 0.600 | **0.800** | +20pp |

提升集中在**改写与近重复**两类——正是我们事前指出的窟窿。**方向是对的，幅度超过预期。**

## 但这条不能直接采纳，原因有三

1. **换嵌入 = 换向量空间**。库里已有条目的向量是按 `ollama/nomic-embed-text@768` 存的，
   bge 是 `local/bge-small-zh-v1.5@512`。`spaces` 表支持按空间分行存，所以旧向量不会坏，
   但**要在新空间上重算一遍**（全库重嵌入），这是一次数据迁移，不是改个默认值。
2. **样本量依旧很小**：paraphrase 与 redundant_pair 各 n=5，一条查询就是 20 个百分点。
   0.909 这个数需要更多查询支撑才敢当结论。
3. **权重要重扫**：1.2 / 1.5 是在 nomic 上调出来的，换 bge 之后最优点可能不同；
   现在拿旧权重配新模型，等于让新模型背着别人的参数跑。

## 下一步（按顺序）

1. 把 paraphrase / redundant_pair 各扩到 ≥20 条；
2. 在新语料上**用 bge 重扫一次权重**（同样是验证集选参、留出集报数）；
3. 两项都稳了，再谈"默认嵌入换成 bge"——那一步要连带做**全库重嵌入**与迁移说明。

## 扩样复验（2026-11-01 晚）

gold 的 paraphrase 只有 5 条，一条翻转就是 20 个点。为此新写了一组 **20 条人工改写**
（`benchmarks/paraphrase_v1/queries.jsonl`，针对 m-0041…m-0056 的实时读数，每条都换了说法、
事实不变；`never` 里放了同族的近似条目作为干扰）。同一批记忆、同一套权重，只换嵌入：

| 嵌入 | hit@1 | hit@5 |
| :--- | ---: | ---: |
| nomic-embed-text | 0.750 | 0.750 |
| **bge-small-zh** | **0.850** | **0.850** |

**方向复现了**：bge 在新的一组 20 条改写上仍然领先 **+10pp**。

**但这组比 gold 的 paraphrase 容易**：两臂在这组上都远高于 gold 上的 0.2/0.6，因为新写的
问句大多**点明了站名**，词法通道也能兜住一部分。所以它证明的是"方向一致"，不是"幅度"。
要定幅度，得写**不点站名、只描述场景**的改写（例如"那个靠海的浮标站电瓶低到两成会怎样"）。

## 现在的结论（保守版）

1. bge 优于 nomic，**三组数据方向一致**（gold 全体 +7.8pp、gold 的 paraphrase 类 +40pp、
   新写的 20 条 +10pp）；
2. 幅度不确定，取决于改写有多"绕开字面"；
3. 采纳仍要**全库重嵌入**，且用 bge 重扫权重——这两件没做。

## 硬改写（不点站名）：两臂都掉下来，但差距更大

`benchmarks/paraphrase_v1_hard/`：同样 20 条，但**不写站名全称**，只用属性指代
（"靠海那个浮标站"、"一号站"、"二号站"），数字也换说法（"两成"、"十分之一"、"仨月"）。

| 嵌入 | 易版（点站名） | **硬版（不点站名）** |
| :--- | ---: | ---: |
| nomic-embed-text | 0.750 | **0.200** |
| bge-small-zh | 0.850 | **0.400** |

三点读法：

1. **难度确实来自"绕开字面"**：同两臂、同一批记忆，点不点站名让 hit@1 差 0.45–0.55；
2. **bge 在硬版上是 nomic 的两倍**（0.400 vs 0.200），方向一致、相对优势更大；
3. **但绝对水平都低**——0.4 意味着硬改写里六成还是找不回来。换嵌入是"把天花板抬高一点"，
   不是"解决问题"。

## 汇总：三档难度、两臂

| 语料 | n | nomic | bge |
| :--- | ---: | ---: | ---: |
| gold 全体 | 85 | 0.831 | **0.909** |
| gold 的 paraphrase 类 | 5 | 0.200 | **0.600** |
| 改写·易版（点站名） | 20 | 0.750 | **0.850** |
| 改写·硬版（不点站名） | 20 | 0.200 | **0.400** |

**四组里 bge 全胜**，且越是"只有语义能过"的题，相对优势越大（+40pp 那一档）。

## 用 bge 重扫权重：**不用改，现有权重已在平台区**

同一套两向交叉验证（A 半选参、B 半报数，再反过来），网格
`lexical ∈ {1.0, 1.2, 1.4}` × `semantic ∈ {0.3, 0.45, 0.7}`，`time` 固定 1.5：

| 方向 | 选出的最优 | 留出集 hit@1 | 现有权重（1.2 / 0.45）留出 hit@1 |
| :--- | :--- | ---: | ---: |
| 正向（valid 选、test 报） | lex 1.4 / sem 0.45（与 1.2/0.45 **并列**） | 0.974 | **0.974** |
| 反向（test 选、valid 报） | lex 1.4 / sem 0.7 | 0.821 | 0.821（同档） |

**两向的结论一致：现有权重已经和网格最优打平**，换 bge 之后**不需要重新调参**。

这条比"扫出更好的参数"更有用——它说明换嵌入这件事只有**一个变量**（模型本身），
迁移方案不用同时改权重，风险因此小一档。

## 采纳清单（代码层面已具备，缺的是数据迁移）

| 项 | 状态 |
| :--- | :--- |
| 证据：bge 优于 nomic（四档语料方向一致） | ✅ |
| 权重不用动（两向扫平） | ✅ |
| bench 支持本地嵌入（`--local-embed`） | ✅ |
| **全库重嵌入 + space_id 迁移** | ❌ 未做，这是采纳前唯一剩下的硬活 |

重嵌入不是改默认值：库里旧向量在 `ollama/nomic-embed-text@768` 空间，bge 是
`local/bge-small-zh@512`；`spaces` 表支持分行存，所以旧向量不会坏，但要**按新空间补算一遍**
才能用新模型检索。这一步要预注册（耗时、失败可重试、中途可回滚）。
