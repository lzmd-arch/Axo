# 召回融合权重的特调（2026-11-01）

目标：在不动语料、不动门槛的前提下，看**融合权重**还有没有空间。
方法照既有规矩：**验证集选参、留出集报数**，两向各做一次（避免划分运气）。

## 结果

| 评估 | 默认（0.9 / 0.45 / 1.0） | 候选（**1.2** / 0.45 / **1.5**） | 差 |
| :--- | ---: | ---: | ---: |
| 正向：留出集 hit@1 | 0.789 | **0.842** | **+5.3pp** |
| 正向：留出集 hit@5 | 0.868 | **0.947** | **+7.9pp** |
| 反向：留出集 hit@1 | 0.795 | **0.821** | **+2.6pp** |
| 反向：留出集 hit@5 | 0.872 | 0.872 | 0 |
| 全量语料 hit@1 | 0.792 | **0.831** | **+3.9pp** |
| 全量语料 hit@5 | 0.870 | **0.909** | **+3.9pp** |

**两向选择出来的都是同一个配置**（`lexical_weight=1.2`、`time_weight=1.5`、语义权重不动），
这是它比“单次划分赢了”更可信的地方。

## 搜索空间（跑之前定，写在这里）

`lexical_weight ∈ {0.9, 1.2}` × `semantic_weight ∈ {0.45, 0.7}` × `time_weight ∈ {1.0, 1.5}`，
共 8 组；选择依据是**验证集 hit@1**（并列看 hit@5）。语义权重调高在每一档都更差，
所以最终候选里它保持原值。

## 这不是什么

- **不是把门槛调松**：`min_score` 与注入门槛都没动，变的是**排序用的融合权重**；
- **不是在留出集上调出来的**：留出集只在选参之后跑一次；
- **幅度有限**：hit@1 +2.6～+5.3pp，而且是 85 条查询上的数，换语料未必成立。

## 采纳（2026-11-01 已做）

1. ✅ `RecallConfig` 的默认改为 `lexical_weight=1.2`、`time_weight=1.5`；
2. ✅ `bench_recall.py --check` 全项在容差内（hit@8/MRR/AUC 不降，false_injection 0.868→0.882 仍在界内）；
3. ✅ `tests/test_recall_gate.py` 与相关核心腿全绿。
