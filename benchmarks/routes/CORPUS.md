# 路由语料

## 这是什么

**一把尺子，不是一个数据集。** 120 条虚构输入 + 人工标注的语域，用来回答一个问题：
*改了规则层的一个标记词之后，路由是变准了还是变不准了？*

在它之前，`agent/router.py` 的那两张词表是一堆**只能靠读代码判断**的初值——"`别`"
该放在 task 触发之前还是之后、"谢谢你"算不算 task 信号，改任何一个都无从比较。这里
补上那个缺口：每条输入都走真正的 `decide_turn()`，口径写在
`src/biosnn_memterm/bench/routeeval.py` 里——**那里是定义，报告只是报告**。

它与金标准语料（`benchmarks/gold/`）是同位体：那一个把记忆灌进 `:memory:` 库再逐条
召回，这一个把输入逐条喂给路由。区别只在被测对象，不在纪律。

语料**全部虚构**，与金标准同一份 denylist 由 `bench/corpus.py::PERSONAL_DENYLIST` 机械
执行——建公开仓时"有没有夹带私人信息"是唯一一个**不可逆**的问题，而人眼扫 120 行中文
是扫不干净的。这一条在 `tools/bench_router.py --freeze` 里也挡了一道：**会泄漏的语料
不许冻结**（只在测试里挡的话，泄漏会先进基线文件，然后才在 CI 上红——那时它已经在版本
控制里了）。

## 文件

| 文件 | 是什么 |
|---|---|
| `utterances.jsonl` | 120 条输入 + 标注，一行一条 |
| `freeze.json` | `sha256(原始字节)`、条数、类别普查、schema 版本 |
| `baseline.json` | 规则层的**实测**基线与容差（先跑后填，见下） |
| `CORPUS.md` | 本文件 |

### `utterances.jsonl` 字段

`id`（`u-0001` 形式的稳定序号）、`text`（送进 `decide_turn` 的**原始**输入，斜杠命令也
原样写在这里）、`expect`（`"chat"` 或 `"task"`）、`category`、可选 `note`。

`expect` 记的是"**应该**怎么走"，不是"规则层实际会怎么判"——两者不一样的地方正是这份
量具的读数。合法值在读盘处就被挡住（`routes.py::load_utterances`）：写错一个字母的症状
是**那一条永远判错**，而报告上只会看到"准确率低了 0.008"，看起来像模型不行。

`note` 不参与计算，但**别省**：它是语料里唯一能解释"为什么这条该是 task"的地方，也是
判错清单能读懂的原因。

## 九类难例

| category | 条数 | 构造 | 压住哪一项 |
|---|---|---|---|
| `slash` | 7 | `/task` `/chat` 显式指定，含大小写、裸切换、认不出的 `/home/user/...` | 结构不变量：来源必须是 `slash` 且判定与标注一致 |
| `imperative` | 24 | 祈使动词 + 对象（找/查/读/列/算/提醒/记/忘/译） | 任务查全——**这一层的主战场** |
| `question` | 14 | 问号结尾但在讨主意、问看法、问知识 | 闲聊查准：问号类不该一律判 task |
| `chitchat` | 25 | 情绪、附和、闲聊陈述 | 闲聊查全 |
| `ambiguous` | 12 | 一个标记词都没命中、但事实上是闲聊 | **覆盖率**（见下） |
| `negation` | 10 | 带 task 动词却被否定掉（"别帮我查了"） | 任务查准：否定式不该触发工具 |
| `emoji_punct` | 8 | 重复嘟囔、纯标点、`ok` | 短输入不该被长度规则误判 |
| `long_task` | 12 | 长句 + 多动作委托，含句末问号的那种 | 长句不该改变判定；问号不该把委托拉回闲聊 |
| `hard` | 8 | **今天还判错的那些** | 准确率——它们是待办清单，不是豁免区 |

`ambiguous` 那一类的**准确率恒为 `n/a`**（分母是"敢判的那些"，而这一类一条都不该敢判），
它压的是覆盖率。这不是缺陷：它记的是"这一档的存在有没有被浪费"。

## 一处与金标准语料**相反**的安排

金标准的 `paraphrase`（近义改写）**不进门槛**，理由是离线腿没有语义通道，拿它当判据等于
让"本机装没装嵌入模型"决定提交能不能过。

这里的 `hard` **进门槛**，理由正好相反：**这 8 条是可够着的**。加一个同义词（`回想一下`、
`记录一下`）、补一条否定式的正向读法（`别忘` = `记住`）、挪一条优先级，任何一条都能在
今天这张表上修好——不需要模型、不需要网络。所以它们不是"故意留着红的一块"，是**可见的
待办清单**，而它们的账（3 条有把握地判错）就记在准确率的分母里。

分界线不是"难不难"，是"**够不够得着**"。够不着的进报告，够得着的进门槛。

## 为什么 `accuracy` 与 `coverage` 必须成对

这一层有一档"我不知道"（歧义 → 退回闲聊并反问）。只看其中一个数都会被糊弄：

* **只看准确率**：一句"不知道"在闲聊占多数的语料上会白拿一个对。首次实测里 25 条亮
  歧义的输入中有 **20 条恰好蒙对**（都是闲聊标注），而一个把 40% 的输入都推给用户确认
  的规则层，准确率可以接近 1.0——那正是最该被看见的退化。
* **只看覆盖率**：一张"什么都判 task"的表能拿满分。

所以 `accuracy` 的分母是**敢判的那些**，`coverage` 是敢判的比例；报告另印一个
`accuracy_all`（放回全长度），它包含上面那部分蒙对的。三个数一起看，才说得清这张表是
"准"还是"怂"。

## 怎么跑

```bash
uv run python tools/bench_router.py --no-model            # 只有规则层，不探测（CI / pre-commit 用这条）
uv run python tools/bench_router.py --no-model --check    # 与基线比，跌破容差即退出码 1
uv run python tools/bench_router.py --no-model --quiet    # 只留一行结论（pre-commit 用）
uv run python tools/bench_router.py --no-model --freeze   # 重算并覆盖基线
uv run python tools/bench_router.py --json                # 额外一份机器可读报告（人看的那路走 stderr）
uv run python tools/bench_router.py                       # 探测到 Ollama 就再报模型层（只报告）
```

退出码：**0** = 达标（或只是报告）、**1** = 跌破基线容差（不是程序出错）、**2** = 用法或
环境不对、**3** = 结构不变量被违反（**那是 bug**）。

`--check` / `--freeze` 与 `--model` 互斥，且会强制 `--no-model`：拿一份纯规则层的基线去比
带模型跑出来的数，差值不是"变好还是变坏"，只是"换了个东西"。

**两把尺子。** 门槛只绑规则层——它纯函数、离线、确定性。模型自分类要 Ollama，把门槛绑上
去等于让"这台机器装没装模型、装了哪个"决定提交能不能过（与 `bench_recall.py` 把门槛只绑
词法通道是同一条纪律）。模型层的数字照报：**"该不该把 `MODEL_CLASSIFY_DEFAULT` 打开"正是
这份报告要回答的问题**，而它不是一个 CI 判据。报告把 `rule` / `model` / `hybrid` 分列，
三行走的是同一段判定代码（只换 `ModelRole`），所以那些数字代表线上会发生的那个东西。

## 冻结纪律：四道锁

与金标准同一套（`benchmarks/gold/CORPUS.md` 的展开），缺一不可：

1. **语料指纹**。`freeze.json` 存 `sha256(原始字节)`、条数与类别普查，
   `tests/test_router_corpus_integrity.py` 断言相等，失败消息直接写出该做什么。
2. **`.gitattributes` 显式列 `*.jsonl text eol=lf`**。指纹失效比没有指纹更糟——守卫看
   起来还在。
3. **基线文件**。`baseline.json` 存语料指纹、指标点估计、容差。判定 =
   `live >= baseline - tolerance`（四项都是越大越好，方向写死在
   `bench/routeeval.py::GATED`）。容差写进文件而不写死在代码里，这样调容差本身是一次
   可见的 diff。
4. **防空转的反向断言**。基线必须自身像一份真实测量（`accuracy >= 0.5` 且
   `coverage >= 0.5`），`--freeze` 生成时**强制重算、不接受手工输入**；另加一条结构层
   的：`ambiguous` 类的歧义标志率不低于 0.8——**一个不出标志的歧义层看起来和没有歧义层
   完全一样**。

**容差 0.02 不是采样噪声，是"允许几条翻转而不惊动人"。** 这份测量是确定性的（同一份语料
跑两遍逐位相同，`tests/test_router_gate.py` 有一条钉住它），没有任何随机来源，所以按统计
学算标准误在这里是错的。0.02 折成条数大约一到两条（分母各异：准确率 95、覆盖率 120、
任务查全 42、闲聊查全 53）。取这么紧是因为这张表是手写的、每次改都是一个词——**改一个词
而弄坏了另一条，正是这个门槛要抓的那件事**。反过来，改善只会把数往上推，任何时候都是绿的。

**"先跑后填"的顺序**：实现 `routeeval` → 本地跑一次 `--no-model --freeze` → 此后
`--check` 才有意义。在此之前 `--check` 遇到缺基线是 `SystemExit`，**不是"没基线就跳过"**：
跳过就是空转的守卫，而空转的守卫比没有守卫更糟。

**改语料时要动的三处**（同一次提交）：`utterances.jsonl` → `freeze.json` → 重跑
`--freeze` 更新 `baseline.json`。少任何一处，完整性测试会红并告诉你还差哪个。

## 首次实测（2026-10-10，规则层，`--no-model`）

```
输入 120 条
  条数 120   覆盖 0.7917   准确率 0.9684（在敢判的那些里）
  含「不知道」一起算 0.9333   歧义标志 0.2083
  任务  查全 0.9524   查准 0.9756
  闲聊  查全 0.9811   查准 0.9630
  「一律判闲聊」的准确率 0.6083
```

分类别（覆盖 / 准确率 / 歧义率）：

| category | 覆盖 | 准确率 | 歧义率 | n |
|---|---|---|---|---|
| `slash` | 1.0000 | 1.0000 | 0.0000 | 7 |
| `imperative` | 1.0000 | 1.0000 | 0.0000 | 24 |
| `long_task` | 1.0000 | 1.0000 | 0.0000 | 12 |
| `question` | 1.0000 | 1.0000 | 0.0000 | 14 |
| `emoji_punct` | 1.0000 | 1.0000 | 0.0000 | 8 |
| `negation` | 0.9000 | 1.0000 | 0.1000 | 10 |
| `chitchat` | 0.7200 | 1.0000 | 0.2800 | 25 |
| `ambiguous` | 0.0000 | n/a | 1.0000 | 12 |
| `hard` | 0.3750 | 0.0000 | 0.6250 | 8 |

判错的 8 条**全在 `hard` 类**：`u-0113` 谢谢你帮我查资料（礼貌词的过去时陈述被当成委托）、
`u-0114`/`u-0115` 问号结尾但该查记忆、`u-0116` 别忘了我说的、`u-0117` 回想一下我们第一次
见面、`u-0118` 记录一下我今天的感受、`u-0119` 把昨天那段话再念一遍、`u-0120` 我上次说想买
的那本书叫什么。

读出来的三件事：

* **这张表在"敢判的那些"上已经很准（0.9684），而它的短板是覆盖率（0.7917）。** 25 条亮了
  歧义，其中 7 条 `chitchat`、1 条 `negation` 属于**过度谨慎**——它们本该被有把握地判成
  闲聊。这些是下一轮补词表的直接目标，而且它们与 `hard` 不同：修它们不会让任何一条变坏。
* **`hard` 的 3 条"有把握地判错"比 5 条"不敢判"更值得看。** 一个不出歧义标志的错判会直接
  走错路（该查记忆的问句退成闲聊、该闲聊的礼貌话变成一次工具调用），而"不敢判"至少还能
  反问一句。这也是为什么 `hard` 要进门槛而不是像金标准的 `paraphrase` 那样只报告。
* **`majority_baseline` 0.6083 是这张表的底线**，不是成绩。它说明这份语料闲聊占多数，
  所以任何"准确率"数字都要先减掉这层水份再看。

**模型层的数一次都还没有。** 它要本机 Ollama 跑 120 次，且**不进门槛**——上面那份报告是
`--no-model` 的产物，`baseline.json` 里的 `model_layer` 是空的。这是有意留白。

## 补词表之后（2026-10-12，同一份语料，`--no-model`）

上面那份第一次实测量出了一件事：`hard` 类 **3 条有把握地判错、5 条不敢判**，而这 8 条里有
5 条是同一族——"**去看已经存下来的东西**"。它们之所以整族走不到 TASK，机制是**第 7 条**：
规则层是一张从上往下的表，"句末问号 → 闲聊"排在第 7 位，而"我上次说想买什么？"恰好以问号
结尾。句子没问题、词表也没坏，就是这一族**永远被问号吃掉**。

那一族补进去了（`上次` / `我的记忆` / `记忆里` / `记忆库` / `回想` / `记录一下` / `念一遍` /
`别忘`，理由逐条写在 `src/biosnn_memterm/agent/router.py` 的 `_TASK_MARKERS` 上）：

```
输入 120 条
  条数 120   覆盖 0.8333   准确率 0.9900（在敢判的那些里）
  含「不知道」一起算 0.9917   歧义标志 0.1667
  任务  查全 1.0000   查准 0.9792
  闲聊  查全 0.9811   查准 1.0000
  「一律判闲聊」的准确率 0.6083
```

| category | 覆盖 | 准确率 | 歧义率 | n | 与首次实测比 |
|---|---|---|---|---|---|
| `slash` | 1.0000 | 1.0000 | 0.0000 | 7 | 不变 |
| `imperative` | 1.0000 | 1.0000 | 0.0000 | 24 | 不变 |
| `long_task` | 1.0000 | 1.0000 | 0.0000 | 12 | 不变 |
| `question` | 1.0000 | 1.0000 | 0.0000 | 14 | 不变 |
| `emoji_punct` | 1.0000 | 1.0000 | 0.0000 | 8 | 不变 |
| `negation` | 0.9000 | 1.0000 | 0.1000 | 10 | 不变 |
| `chitchat` | 0.7200 | 1.0000 | 0.2800 | 25 | 不变 |
| `ambiguous` | 0.0000 | n/a | 1.0000 | 12 | 不变 |
| `hard` | 1.0000 | 0.8750 | 0.0000 | 8 | 覆盖 0.3750→1.0000、准确率 0.0000→0.8750 |

**其余八类一个数都没动**，这一条比 `hard` 涨了多少更重要：它说明补的是"漏掉的一族"，不是
把判定边界整体挪了。

判错的**只剩 1 条**：`u-0113` 谢谢你帮我查资料——礼貌词的**过去时陈述**被规则层有把握地判
成了 task。它**不会被修**：要修就得动礼貌词与 task 词的优先级，而"麻烦你帮我查一下"是一句
正常的委托（见 `router.py` 的 `_COURTESY_PREFIXES`），那个方向的代价更大。

> **`baseline.json` 里冻的仍是补之前那份数，这是有意的。** 门槛是**相对**闸门
> （"不恶化即绿"），改善不需要重新冻结；而重新冻结会把这批改善写成新的地板——下一轮改词表
> 时就看不见"退回到今天之前"这件事了。所以基线那侧的 0.9684 / 覆盖 0.7917 与上表不同
> **不是漂移**，`--check` 也照样绿。

**这张表的短板因此从"判不准"换成了"不敢判"。** 歧义标志从 0.2083 降到 0.1667，剩下的 20
条里 `chitchat` 7 条、`negation` 1 条属于**过度谨慎**——它们本该被有把握地判成闲聊。这是
下一轮补词表的直接目标，而且它们与 `hard` 不同：修它们不会让任何一条变坏。

## 再压一轮歧义（2026-10-12 晚，同上）

"剩下的 20 条"这句里有个容易上当的地方：那 20 条**只有 8 条是可压的**，另外 12 条是
`ambiguous` 类——它们是语料**故意**构造的"一个标记词都没命中"，本来就该亮标志。所以
`ambiguous_rate` 的**地板是 12/120 = 0.10**，从 0.1667 往下最多只能走到 0.10，而全部空间
就是那 8 条。

先量候选再动手（表在下面）。结论分两半：**两条用"改机制"拿到了，五条放弃了**。

```
输入 120 条
  条数 120   覆盖 0.8500   准确率 0.9902（在敢判的那些里）
  含「不知道」一起算 0.9917   歧义标志 0.1500
  任务  查全 1.0000   查准 0.9792
  闲聊  查全 0.9818   查准 1.0000
  「一律判闲聊」的准确率 0.6083
```

| category | 覆盖 | 准确率 | 歧义率 | n | 与上一节比 |
|---|---|---|---|---|---|
| `chitchat` | 0.8000 | 1.0000 | 0.2000 | 25 | 覆盖 0.7200→0.8000、歧义 0.2800→0.2000 |
| 其余八类 | — | — | — | — | **一个数都没动** |

拿到的两条都不是靠"往闲聊表里塞词"：

1. **`u-0050`「好的，知道了」——第 3 条自己太窄。** 它原先要求整句**精确等于**一个应和词
   （`folded in ACKNOWLEDGEMENTS`），而 `normalize` 只做 NFKC + casefold、**不删标点**，
   于是"好的，知道了"既不是"好的"也不是"知道了"，一路走到第 8 条。改成"**全句由应和词
   拼成**"（可达性切分，标点先去掉，句尾语气助词不算）。判据仍然是**全句**：`好，我们开始
   吧` 切到"我"就断了，照旧 `None`——放宽成"含有应和词"会让任何以"好的"开头的句子变成
   闲聊，而那正是第 5 条刻意只给 0.7 的地方。
   - 顺带改了一条老断言的**归属**：`嗯嗯嗯嗯` 从第 4 条（嘟囔 0.8）挪到第 3 条（应和 0.9），
     因为 `嗯` 本身就是应和词。结论没变、只有置信度变——正是 `tests/test_router.py` 那条
     docstring 说的"只有置信度能抓住的退化"。第 4 条另留了两个见证（`哈哈哈哈哈`、`？？？`）。
2. **`u-0053`「我今天心情特别好」——`心情` 入闲聊表。** 它属于"情绪与状态"那一族（与
   `累`/`开心`/`难过`/`无聊`… 同族）。

**放弃的五条是故意的**：`u-0062`/`u-0066`/`u-0068`/`u-0069`/`u-0070`（梦、打算出去、雨、
心跳、花）。量出来的账是这样的（**这张表是动手之前量的**，那时第 3 条还是"整句相等"，
所以各行的词是当时按"往闲聊表里加词"试的；最后一行的数才是"歧义清零"的价码）：

| 候选 | 覆盖 | 准确率 | 歧义 | chitchat 歧义 |
|---|---|---|---|---|
| 对照（只加上述两条之前） | 0.8333 | 0.9900 | 0.1667 | 0.2800 |
| + 知道了/心情/做梦/打算出去 | 0.8583 | 0.9903 | 0.1417 | 0.1600 |
| + 下雨/心跳 | 0.8667 | 0.9904 | 0.1333 | 0.1200 |
| **+ 梦/出去走走/雨/花** | **0.8917** | 0.9907 | **0.1083** | **0.0000** |

最后一行能把 `chitchat` 的歧义**清成零**，看起来最像"压到位了"。不收它的理由是那条分界线：
**`心情` 说的是说话人自己的状态，`雨`/`花`/`梦` 是话题名词**——话题名词说的是"这句话关于
什么"，不是"这句话是要对方做件事还是说句话"，而任何语域都可能有那个话题（"我养的花开了"
是闲聊，"帮我查一下这种花怎么养"是委托）。收话题名词等于把"这句话里出现过某个字"当成语域
证据。**分数来自那 120 条，代价落在用户看不见的地方。**

> **同一轮还量出两个"看起来该有用、其实没命中"的候选，一并记在这里免得有人重挑一遍。**
> `做梦` 接不住 `u-0062`（正文是"我今天做了个奇怪的**梦**"，中间隔着字），`下雨` 接不住
> `u-0068`（正文是"外面的**雨**下得挺大"）。这两个词是照着语料的**意思**挑的，不是照着
> **文字**挑的——**候选词得先在正文里真出现**。
>
> 还量了一条死路：给 `u-0091`「别搜了，我找到了」往 `_NEGATIONS` 里加 `别搜`，**一个数
> 都不动**。原因是 `_NEGATIONS` 只在**已经有 task 标记**时才被查（它判的是"标记被否定了
> 没有"），而这句里一个标记都没有——它要修得换机制，不是换词。

所以这一类剩下的 5 条**不修**，`ambiguous_rate` 停在 0.1500（离地板 0.10 还有 5 条）。
`tests/test_router.py::test_a_state_word_is_chitchat_but_a_topic_noun_is_not` 把这五个词
钉在表外，连 `做梦`/`下雨` 一起——免得下一轮有人照着一句语料的**意思**再把它们加回来。

## 已知局限

* **量的是这 120 条合成输入，不是真实对话。** 门槛的语义因此是**相对闸门**（"不恶化即绿"），
  不是绝对质量声明。
* **`expect` 是单人标注。** "我们上次聊到哪儿了？"该算 task（去查记忆）还是 chat（闲聊里
  顺口一提），换个人可能标另一边。`hard` 类里这种争议最密集——所以它们才在 `hard` 里。
* **类别不进门槛。** `chitchat` 25 条已经是最小的一档里最大的，标准误仍然是 0.09 量级；
  拿单类当判据等于每天红一次。只报告。
* **它不量延迟。** 规则层是几微秒的事，没有可量的东西；真正要量延迟的是模型层，而那要
  等模型层上了线再说。
* **语料只在 sdist 里，不在 wheel 里。** 与金标准同一处境，`default_routes_dir()` 处理
  源码检出与 `--corpus-dir` 两条路。**P6a 没有把它答了**：它冻结的是 exe，产物不带
  `benchmarks/`，安装态那条路仍然等到真发 wheel 时再定。
* **本版不做**：按类别设门槛、模型层的自动基线、把基准接进界面（不做"跑评测"按钮）。
