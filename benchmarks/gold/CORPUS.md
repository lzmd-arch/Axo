# 金标准语料

## 这是什么

**一把尺子，不是一个数据集。** 200 条虚构的海洋观测站记忆 + 76 条带 ground truth 的
查询，用来回答一个问题：*改了召回的一个参数之后，是变好了还是变坏了？*

在它之前，本仓唯一的量具是 `tools/bench_space.py` 的 20+20 对，量的是**配对级的分隔
度**（一句话对一条记忆的 Jaccard 能不能分开），**没有候选池**——所以真正决定召回行为
的 K、阈值、MMR 去冗、token 预算驱逐，一条都没被量到。这里补上那个缺口：每条查询都
跑真正的 `recall()`，落一份逐条账本，四项指标（hit@K / MRR / 误注入率 / AUC）的口径写
在 `src/axo/bench/metrics.py` 里——**那里是定义，报告只是报告**。

语料**全部虚构**。它不许含任何关于作者本人、本人机器、或本项目其它仓库的痕迹，这条
由 `tests/test_goldset_integrity.py::test_corpus_has_no_personal_identifiers` 用一份
denylist 机械执行——建公开仓时"有没有夹带私人信息"是唯一一个**不可逆**的问题，而人眼
扫 200 行中文是扫不干净的。

## 文件

| 文件 | 是什么 |
|---|---|
| `memories.jsonl` | 200 条记忆，一行一条 |
| `queries.jsonl` | 76 条查询 + ground truth，一行一条 |
| `freeze.json` | 两份 JSONL 的 `sha256(原始字节)`、条数、类别普查、schema 版本 |
| `baseline_lexical.json` | 词法通道的**实测**基线与容差（先跑后填，见下） |
| `CORPUS.md` | 本文件 |

### `memories.jsonl` 字段

`id`（`m-0001` 形式的人造稳定 id，直接当 `memory_id`）、`content`。可选：`kind`
（默认 `fact`）、`tier`（默认 `longterm`）、`taint`（默认 `user`）、`weight`、`pinned`、
`session_id`、`created_at`。

**`weight` 与 `created_at` 在文件里不写**，由 `goldset.py` 的两个常量统一给：`GOLD_WEIGHT
= 0.7`、`CREATED_AT = 1700000000.0`。前者是**免混淆变量**——真实库里权重各不相同，一组
参差的权重会让"词法通道排得准不准"与"这条被访问得多不多"混在一起；后者不固定的话惰性
衰减不可复现（`decayed_weight` 依赖"现在几点"，而基准把"现在"钉在 `CREATED_AT` 上，于是
衰减因子恒为 1，权重就是写下的那个数）。

### `queries.jsonl` 字段

`id`、`query`、`category`。可选：`expect`（**必须**出现的 id；空数组 = 库里确实没有
答案）、`optional`（出现与否都不罚——冗余对里"两条都对、只指定了一条"）、`never`（同
主题干扰项，进误注入率的分子）、`exclude`（传给 `recall` 的 `exclude_ids`）、`budget`
（默认 400）、`note`。

## 十类难例

| category | 条数 | 构造 | 压住哪一项 |
|---|---|---|---|
| `name_number` | 30 | 精确专名/数字 vs 同话题不同数字（"每五分钟" vs "每十分钟"） | hit@1 / MRR |
| `exact` | 8 | query 近乎逐字含某条 | hit@1 / MRR |
| `distractor_topic` | 8 | 同主题不同事实，干扰项进 `never` | 误注入率 / `min_score` |
| `no_answer` | 8 | `expect: []` 且库里确无相关知识 | 误注入率（**不进** hit/MRR 分母） |
| `redundant_pair` | 5 | 两条近重复都相关，一条 `expect` 一条 `optional` | `redundancy_threshold` / MMR |
| `budget` | 5 | 多条相关长记忆 + 很小的 `budget` | token 贪心（统计 + 硬不变量） |
| `paraphrase` | 5 | 近义改写、几乎无字面重合 | **语义通道**——只报告，不进门槛 |
| `cold_twin` | 2 | 唯一字面匹配是 `tier="cold"`，另给一条 live 的 `expect` | 结构性：COLD 淘汰 |
| `pinned_twin` | 2 | `pinned=True` 的那条字面匹配，另给 live 的 `expect` | 结构性：扫描期跳过 |
| `session_exclude` | 3 | 高相关但属别的 session，经 `exclude` 排除 | 结构性：`exclude_ids` |

**末三类是结构不变量，不是统计倾向。** 它们断言 `== []`（一条都不许进注入），**不参与
任何聚合**——200 条语料里混进一条人格锚，hit@1 可能还涨了 0.005：数字更好看，系统更坏。
它们各自额外配一条 live 的 `expect`，否则该查询在 hit@K 里天然为 0，会把聚合拉垮。

`paraphrase` 那一类**不进门槛**：离线腿没有语义通道，拿它当判据等于让"有没有装 Ollama"
决定提交能不能过。它的数字照报，价值是回答"换一个嵌入模型会不会更好"。

## 怎么跑

```bash
uv run python tools/bench_recall.py --no-semantic          # 纯词法（CI / pre-commit 用这条）
uv run python tools/bench_recall.py --no-semantic --check  # 与基线比，跌破容差即退出码 1
uv run python tools/bench_recall.py --no-semantic --json   # 额外一份机器可读报告
uv run python tools/bench_recall.py                        # 探测到 Ollama 就用语义通道
```

退出码：**0** = 达标（或只是报告）、**1** = 跌破基线容差（不是程序出错）、**2** = 用法或
环境不对、**3** = 结构不变量被违反（**那是 bug**）。

## 冻结纪律：四道锁

`tools/bench_space.py` 立过此规原文：「**语料是冻结的：别跟着阶段代号一起改。**这些句子
是量具，不是文档——改一个字，数就变了」。四道锁缺一不可：

1. **语料指纹**。`freeze.json` 存两份 JSONL 的 `sha256(原始字节)` 与条数，
   `tests/test_goldset_integrity.py` 断言相等，失败消息直接写出该做什么。
2. **`.gitattributes` 显式列 `*.jsonl text eol=lf`**。通配的 `* text=auto eol=lf` 现在
   **碰巧**也让它们走 LF，但"碰巧"不是判据。指纹失效比没有指纹更糟——守卫看起来还在。
3. **基线文件**。`baseline_lexical.json` 存受测配置全量、指标点估计、容差、语料指纹。
   判定 = `live >= baseline - tolerance`（误注入率反向，方向写死在
   `bench/gates.py::LOWER_IS_BETTER`）。容差写进文件而**不写死在代码里**——这样调容差
   本身是一次可见的 diff。
4. **防空转的反向断言**。基线必须自身像一份真实测量（`hit@8 >= 0.5`、
   `false_injection_rate <= 0.9`），`--freeze` 生成时**强制重算、不接受手工输入**。
   没有这两条，"把基线写成全 0 就永远绿"是两步就能走到的状态，而且看起来完全正常。

**"先跑后填"的顺序**：实现 harness → 本地跑一次 `--no-semantic --json` → 把实测数
**照抄**进 `baseline_lexical.json`（独立一次提交，commit message 写明"首次实测，非目标
值"）→ 此后 `--check` 才有意义。在此之前 `--check` 遇到缺基线是 `SystemExit`，**不是
"没基线就跳过"**：跳过就是空转的守卫，而空转的守卫比没有守卫更糟。

**改语料时要动的三处**（同一次提交）：两份 JSONL → `freeze.json` → 重跑 `--freeze` 更新
`baseline_lexical.json`。少任何一处，`tests/test_goldset_integrity.py` 会红并告诉你还差
哪个。

## 量具的区分度：探针证据

语料落盘之前先量过一遍「这组数动得起来吗」。**没有区分度的量具比没有量具更糟**：它给出
一个恒定的绿，让人以为有人在看。以下两组是留档的原始输出。

读出来的三件事：

* **`min_score` 与 `lexical_weight` 是主力**：`min_score 0.35` 让 hit@1 掉 52.9 个点、
  误注入率掉到 0（**一个都不注入了**——阈值把对的也砍了）。这两个旋钮改坏了，门槛一定
  会红。
* **误注入率是唯一对 `max_items` / `candidate_limit` 敏感的指标**：`max_items 3` 让它掉
  16.8 个点而其它三项纹丝不动。这四个数互补，不重复——所以四项都要在门槛里。
* **`semantic_weight 0.0` 在离线腿上毫无变化**，因为这轮根本没有语义通道的得分。这是
  "门槛只绑词法通道"的直接后果，也是它必须写在文档里的理由：语义数字要等本地带 Ollama
  跑一次才存在。

### 假设 B：`fused` 与阈值无关

上表 `auc` 一列**在所有 12 种配置下都是 0.909**，一个数位都没动。这不是巧合，是 AUC 合
法性的前提：`ChannelScores.fused` 只由通道得分与通道权重决定（`recall._fuse`），与
`min_score` / `max_items` / `budget` / `mmr_lambda` / `candidate_limit` 全都无关。所以
AUC 描述的是"这个打分函数能不能把对的排在错的前面"，在任何阈值下都成立——它因此是**上界**：
当前部署配置实际达到的质量不可能超过它。

这条性质由 `tests/test_bench_metrics.py::test_fused_does_not_depend_on_selection_knobs`
钉住（"同一条候选在 `min_score` 0.10 与 0.0 下 `fused` 逐位相同"）。将来有人把阈值塞进
`_fuse`（比如除以 `min_score` 做归一化），AUC 会静默变成另一个量而**没有任何一处会报错**
——那条断言就是那件事的哨兵。

**AUC 恒定还有第二个含义，写在这里免得被误读**：它因此**不响应配置改动**，只响应语料与
编码器的改动。它进门槛是为了拦"有人改了 `encode_lexical` 或语料"这类漂移，不是拦调参。

### 语义腿：本机跑一次的对照（**不进 CI、不判失败**）

复现：本机 Ollama 在 `127.0.0.1:11434`，模型 `nomic-embed-text:latest`（768 维，
`f16`，Q4_K_M）。

```
uv run python tools/bench_recall.py --no-semantic   # 词法（= 门槛绑的那条）
uv run python tools/bench_recall.py --semantic      # 词法 + 语义；连不上即非零退出
```

| 指标 | 词法 | 词法 + 语义 | 差 |
|---|---|---|---|
| hit@1 | 0.8824 | 0.7647 | **−0.1177** |
| hit@3 | 0.9412 | 0.8235 | −0.1177 |
| hit@5 | 0.9559 | 0.8824 | −0.0735 |
| hit@8 | 0.9559 | 0.8971 | −0.0588 |
| MRR | 0.9074 | 0.8074 | −0.1000 |
| MRR（只算命中者） | 0.9492 | 0.9000 | −0.0492 |
| 误注入率 | 0.8205 | 0.8902 | **+0.0697（更差）** |
| 空答注入数（条/查询） | 2.3750 | 8.0000 | +5.6250（更差） |
| AUC | 0.9093 | **0.9243** | **+0.0150（更好）** |
| 同主题干扰项 AUC | 0.9119 | 0.9265 | +0.0146（更好） |

分类别看，语义通道让 `distractor_topic`（1.0000 → 0.5000）、`budget`（0.8000 →
0.4000）、`pinned_twin`（1.0000 → 0.5000）、`redundant_pair`（0.6000 → 0.4000）四类
明显变差；`exact`、`name_number`、`cold_twin`、`session_exclude` 不变；**`paraphrase`
——本该由它救的那一类——一格没动（0.2000 → 0.2000）**。

**怎么读这一页。** 它记的是一次对照，不是一条结论。

1. **AUC 涨而端到端全跌，这两件事同时发生是本次最有价值的观察。** AUC 与阈值无关，
   量的是排序质量；hit@K / MRR / 误注入率量的是**部署配置**（`min_score=0.10`、
   `max_items=8`）。语义通道把排序变好了一点点，同时把一批不相关的条目也抬过了那个
   阈值——空答注入数从 2.375 涨到 8.0000，正好是 `max_items`，也就是 8 条
   `no_answer` 查询**被塞满了**。**阈值是按词法量纲标定的初值**，换通道组合就该重标；
   本版不改默认值，所以看到的就是"打分更好、用起来更差"。
2. **`paraphrase` 一格没动**，而这一类本来就是给语义通道准备的。两种解释都说得通：
   这个模型在中文短句上的排序质量不够（`RecallConfig.lexical_weight` 的注释记着它在
   本机 40 对上 AUC **0.760**，低于词法的 0.884），或者那 5 条改写还不够"无字面重合"。
   **它不能当成"语义通道没用"的证据**，只能说"换这个模型、在这套语料上、没有加分"。
3. **所以门槛只绑词法**：把语义数放进 CI，等于让"本机有没有装哪个模型"决定提交能不能
   过。这一页的作用是**下次换嵌入模型时的对照基线**——换完重跑同一条命令，比这一页。

**这一页的免责声明和别处一样、甚至更要紧**：一台机器、一个模型、一次运行。

### 联想腿：本机跑一次的对照（**不进 CI、不判失败**）

复现：

```
uv run python tools/bench_recall.py --no-semantic --graph-weight 0,0.25,0.5,1.0
```

图由该命令自行建立：200 个节点、1600 条有向边（`top_m=8`、`min_weight=0.1`、
`assoc_k=64`、`assoc_mode=hash`）。`w` 是 `RecallConfig.graph_weight`，即联想通道的
**可靠度**；`w=0.00` 那一列就是出厂默认（**门槛绑的也是这一列**）。

| 指标 | 无联想 (w=0) | w=0.25 | w=0.50 | w=1.00 |
|---|---|---|---|---|
| hit@1 | 0.8824 | 0.8824 | 0.8824 | 0.8824 |
| hit@8 | 0.9559 | 0.9559 | 0.9559 | 0.9412 |
| MRR | 0.9074 | 0.9037 | 0.9005 | **0.8935** |
| 误注入率 | 0.8205 | 0.8402 | 0.8628 | **0.8801（更差）** |
| 空答注入数（条/查询） | 2.3750 | 4.6250 | 5.7500 | **8.0000（更差）** |
| AUC | 0.9093 | 0.8921 | 0.8757 | **0.8450（更差）** |
| 同主题干扰项 AUC | 0.9119 | 0.8948 | 0.8784 | **0.8476（更差）** |

**怎么读这一页。** 它记的是一次扫描，不是一条结论。

1. **四项里没有一项变好，AUC 还跌得最狠（−0.0643）。** 这与基质语料上的实测负结果
   同向（`benchmarks/substrate/baseline.json` 的 `graph_hit@1` 0.8250 < 词法 0.8500），
   两套语料互相印证。**结论是"在这套语料上、这套参数下，联想通道拖后腿"**，不是
   "联想这个想法不对"——见下一条。
2. **为什么大概率是负的，写在实现里**：图的边来自 `assoc_sdr`，而 `assoc_sdr` 是从
   `lex_sdr` **派生的纯哈希子采样**（`memcore/graph.py::_extract`）。所以"联想找到的
   邻居"与"词法已经找到的东西"**同源**——它几乎只能把词法已经排过一遍的条目再抬一次，
   而那些条目里就有 `never`（同主题干扰项）与 `no_answer` 查询的无关条目。**加的是同
   一份证据的第二遍，不是新证据。** 空答注入数在 w=1.00 时正好顶到 `max_items=8`，
   与语义腿那页是同一个形状。
3. **所以开关保持默认关**（`RecallConfig.graph_weight = 0.0`），而且**门槛绑的仍是
   默认列**：`--check` 的基线 `baseline_lexical.json` 与 `gates.py` 的 `GATED` 一个字
   没动。这一页的作用与语义腿那页相同——**下次换关联码方案（`assoc_mode`、`k`）或换
   图参数时的对照基线**，以及"开关该不该打开"这个问题的答案。
4. **`hit@1` 四列全平**（0.8824）值得单独说一句：联想只改动排名中后段，从不改变
   榜首。这与"噪声或只会抬高"的算子性质一致——抬高的是本来就在榜上的那些。

**这一页的免责声明和别处一样**：一台机器、一次运行。`--graph-weight` 只报告、不进
门槛，也不与 `--check/--freeze` 同用（门槛绑默认配置，混用必然红，而红的原因不是
召回变差）。

## 已知的局限

* **量的是这套合成语料，不是真实记忆。** 所以门槛的语义是**相对闸门**（"不恶化即绿"），
  不是绝对质量声明。真实库上的表现这里没有发言权。
* **n = 76（有答案 68）的统计噪声。** p≈0.8 时标准误约 0.045，2σ 约 ±0.09。所以容差是
  0.05、门槛用最稳的 hit@8，**per-category 不进门槛**（n≈5 时标准误约 0.18，拿它当判据
  等于每天红一次）——只报告。
* **离线 AUC 逼近的是词法打分函数自身的天花板，不是系统上界。** 本机 40 对短句上词法
  AUC 已是 0.884，这里 0.909。"嵌入有没有加分"的对照已经跑过一次、记在上一节：**排序
  加分（AUC 0.9093 → 0.9243），端到端反而变差**——因为阈值是按词法量纲标定的。
* **语料只在 sdist 里，不在 wheel 里。** CLI 目前是"从源码检出跑"的工具。**P6a 冻结的是
