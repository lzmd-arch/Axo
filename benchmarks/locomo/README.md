# LoCoMo 召回基线（v1，2026-11-02）

**预注册：** [`docs/prereg-locomo-retrieval-v1.md`](../../docs/prereg-locomo-retrieval-v1.md)（口径写在跑之前）

只量**召回**，不量答题：把每轮对话当作一条记忆、把每条 QA 的 `evidence` 当作 ground truth，
看 `recall()` 能不能把证据轮排进前 k。

## 一句话

三臂都跑完。**nomic 臂 hit@5 = 0.495、证据覆盖@8 = 0.439**；随包中文模型 0.263；纯词法 0.139。
预注册写的两条预期都成立，但其中一条的**后果**也成立——见「读法 3」。

## 数据

- `locomo10.json`，sha256 **`553cd5a15e25f2ceccc6ed185221eba645080c93e5b91087560a91aa5961f365`**；
- 10 段 → **5882 条记忆**、**1973 条查询**；
- 排除：空证据 **4** 条、evidence 引用了不存在的 `dia_id` **9** 条；
- 数据不入库（第三方，22 MB），只登记 URL 与哈希：`github.com/snap-research/locomo`。

口径按预注册：记忆 = 一轮对话（`speaker: text`），`created_at` 全钉 `CREATED_AT`（时间通道中立），
`RecallConfig()` 出厂默认，α 与任何阈值都不参与。

## 结果

| 臂 | hit@1 | hit@3 | hit@5 | hit@8 | 证据覆盖@8 | MRR |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| **nomic-embed-text（768）** | **0.242** | **0.423** | **0.495** | **0.574** | **0.439** | **0.350** |
| 随包 bge-small-zh（512） | 0.132 | 0.225 | 0.263 | 0.310 | 0.226 | 0.189 |
| 纯词法（无嵌入） | 0.057 | 0.104 | 0.139 | 0.172 | 0.122 | 0.090 |

分母 1973（有证据的查询）；`hit@k` 是「证据里至少一条进前 k」的查询占比，`证据覆盖@k` 是逐条的 micro 覆盖率。

## 预注册偏差（照登）

预注册里写「LoCoMo 的 category 5 是 adversarial，预期在这里被排除」。**实际不会**：它带 `evidence`
（446 条），所以按「有证据就进分母」的规则它留在里面。只排除了 4 + 9 条。

这条偏差有实质后果：**category 5 的正确答案是「没提过」**，它的 `hit@5` 量的是「相关轮能不能被找到」，
不是「答得对不对」。把 cat 5 拿掉之后的池化 `hit@5`：

| 臂 | cat 1–4（1527 条） | cat 5（446 条） |
| :--- | ---: | ---: |
| nomic | **0.540** | 0.343 |
| bge-zh | 0.265 | 0.253 |
| 词法 | 0.139 | 0.141 |

headline 的 0.495 是**含对抗性查询**的数；不含它是 0.540。两个都报，不挑。

## 读法

### 1. 语义通道是主要来源，不是补充

nomic 的 `hit@5` 是词法的 **3.6 倍**（0.495 vs 0.139）。这与中文金标准上的结论同向：
词法通道能兜住字面重合，兜不住换说法。LoCoMo 的问题几乎全是换说法。

### 2. 中文嵌入跑英文差一档，而且这是选型问题不是能力问题

同一个库、同一批查询，只换嵌入：0.495 → 0.263。这与中文语料上「换成 bge 涨 7.8pp」**不是同一件事**
——那边 bge 是母语模型，这边它跑的是外语。两条结论合起来的读法是：
**嵌入必须和语料语言匹配**，没有"更好的那个模型"。

### 3. 预注册写的后果条款成立：召回接近 Paper C 的瓶颈线

预注册原文：「若 A2 的 hit@5 也低（比如 < 0.5），那说明**召回是 Paper C 的瓶颈**，先修召回，
再谈端到端对比——这句话现在写下，省得看到数之后再找理由。」

实测 **0.4952**，在 0.5 这条参考线下方。按字面，这一条成立。

需要同时说清的两点，避免把它读成"差 0.005 所以失败"：
- 那个 0.5 是写预注册时拍的参考值（原文是"比如"），不是从数据推出来的门槛；
- 单次运行、单数据集下，0.495 与 0.5 之间没有分辨力。

**正确的结论是：召回确实落在瓶颈线附近，而不是"刚好通过"或"刚好失败"。**
在把证据覆盖率从 0.44 抬到 0.7 之前，端到端对比主要量的是答题器，不是记忆系统。

### 4. 时序类最好、开放域最差

时序 0.606 高于单跳 0.576，开放域只有 0.292。开放域（常识/推断）本来就是检索最难的一档
——问题里的词与证据轮几乎不重合。这一档要提升得靠结构（重排、多跳展开），不是调阈值。

## 边界

- **检索口径 ≠ 答题准确率。** 这份数与 HeLa-Mem 报的 65.40（LongMemEval-S 端到端）**不能直接比**，
  与他们在 LoCoMo 上的端到端数字也不能比。
- 单数据集、单次运行、单机；没有多种子（检索是确定性的，种子只影响并列打破，未测）。
- 时间通道被刻意钉死（`created_at` 全等于基准时间），真实使用时它是有效的——本版量的是它的下限。
- 英文语料 + 中文随包嵌入是一个组合限制，不是产品默认路径的测量。

## 与 HeLa-Mem 的关系

他们报的是**端到端答题**（检索 + 作答 + 判分），我们报的是**检索**。要谈对标，必须先：
1. 定一个答题器（本地 qwen3-4b，或与他们一致的模型）；
2. 另写一份预注册，把「可比的」与「不可比的」写清楚；
3. 在那之前，这份数只能用来回答一个问题：**证据找不找得到**。答案是：一半左右找得到，还不够。

## 复现

```
python tools/bench_locomo.py --data <path>/locomo10.json \
    --expect-sha256 553cd5a15e25f2ceccc6ed185221eba645080c93e5b91087560a91aa5961f365 \
    --arm nomic --out <仓外>
python tools/bench_locomo.py ... --arm local \
    --local-model-dir <bundle>/embedding/bge-small-zh-v1.5
python tools/bench_locomo.py ... --arm lexical
```

三份 `*_full.json` 与本文件同目录；数据的哈希在每份 json 的 `data_sha256` 字段里。
