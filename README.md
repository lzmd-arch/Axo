# Axo

一个桌面终端，把**长期记忆与性格放在终端侧，而不是放在模型里**。

## 它要解决的问题

1. **上下文长度有限** —— 不靠把窗口塞满。分层装配 + 硬 token 预算 + 超预算按层
   反向驱逐 + 滚动摘要，每轮产出一份可审计的「注入了什么」账本。
2. **记忆跟着模型走** —— 记忆库是终端侧的本地文件（SQLite + npz + 纯文本 YAML），
   **模型只通过检索注入读它，永远不拥有它**。

这两个问题其实是同一个机制的两面：换模型 = 换一个读者。库、人格锚、偏好权重
一字节不变。这就是「每个模型第一次接入就拥有完全一致的记忆与性格」的工程口径。

## 当前状态

**P2 完成——看得见她记得什么。** 顶栏「记忆」开一个独立窗口，里面是全部条目（含人格锚），
可以改正文、软遗忘、彻底删除，每一条都能查「本轮它为什么被注入／为什么没被注入」，还可以
「以它为线索召回一次」看它在库里的邻居。顶栏另有一条上下文指示灯，数值与右侧账本**同一份
来源**。细节见下面的「记忆界面」。

**云端后端——填一个 API key 就能用 DeepSeek 这类模型。** 后端页从「一个服务地址」
变成两组：本机 Ollama，或者**云端的 OpenAI 兼容端点**（地址 + API key）。三件事值得单说：

* **key 用 Windows 的 DPAPI 按「当前用户 + 这台机器」加密之后才落盘**，设置文件里不是
  明文。换台机器或换个账户就解不开——那时**当成没配过**（回一句"没配 key"），不崩，也不
  假装连上了。
* **对话走云端，嵌入仍走本机 Ollama。** 这条不是取舍而是前提：多数云端厂商没有嵌入端点，
  而记忆的召回、回填、探针整条路都靠向量。所以云端模式下**本机仍然要有一个嵌入模型**，
  清单也仍然问 Ollama 要（与对话用哪家无关）。列表因此是**两份**，不是一个。
* **发出去的东西要说清**：这一轮的对话**以及被召回注入的那几条记忆**都会送到那个地址的
  运营方。设置页的云端组里就摆着这句话。记忆库本身、嵌入向量、逐字稿仍只在本机。

同版还有两件小的：**自动巩固不再往对话区写那一行**（它从此在人前完全无声，见下面「睡眠
巩固」末尾那条登记），以及**按钮换成了磨砂玻璃那一套**——两边各自能做的不一样：Qt 外壳这
一侧只能拟态（QSS 没有 blur、没有 box-shadow，窗口底色也是不透明的），靠一层半透明渐变加
**上下两条亮度不同的描边**（顶边是光、底边是影）读出厚度；网页对话区那两处才是真的
`backdrop-filter`，因为只有那一侧背后真有壁纸，而且还能多给一道真投影。

那对描边里最要紧的是**顶底取的不是同一支颜色**。填充走 `fg_strong`（暗态白、亮态黑——
"离开背景"的方向随主题反转），边走的却是**该模式下最亮与最暗的那两个 token**（光就是白
的、影子就是黑的，不随主题反转）。混用的话，亮态那条顶边会是一道**黑**线，而描边是压在
填充之上的，叠黑只会更黑——屏幕上就是"光从下面打上来"。这条不是推的，是量出来的：
`tests/test_ui_theme_glass.py` 抓真渲染出来的像素来比（两次渲染对照：同一格把这道边擦掉，
看那一格有没有被推往设计的方向）。

**随后一次收口：路由补上"查记忆"那一族，环境槽那句事实换了措辞。** 两件事同一个来源——
用户实测打了一句「晚上好」，回头问"是不是 DeepSeek 用不了工具"。

* **能查记忆的说法原先整族漏在词表外**（"查看我的记忆"/"记忆里"/"我上次…"/"回想"/
  "记录一下"/"念一遍"/"别忘"），而查记忆**天然是问句**，正好被"句末问号 → 闲聊"那条规则
  吃掉。后果不是"答得不好"，是那一轮**一个工具都不声明**，模型只能照环境槽那句事实编一句
  "我无法使用工具查看记忆"——看起来像模型推卸，实际是路由没给它工具。补表之后 120 条语料上
  `hard` 类判对 **7/8**（原先 **0/8**），其余八类**一条没动**。
* **环境槽那句事实去掉了"做不到"的能力清单**（理由见「几个刻意的取舍」末尾）——那个清单
  会被原样背成能力免责声明，而它正是上面那句"我无法使用工具"的来源。

同时真的把"不许声称你调用了工具"补进了人格锚：它此前**哪里都没有**过（L1 不肯写它，写了
就是指令；L0 里也没有）。补它需要给内置锚配版本号与升级路径，所以那是**另一条收口**，
理由、版本记录与"它是一句要求不是闸门"的界限都在下面「几个刻意的取舍」末尾。

**同一族上的再一轮：歧义率 0.1667 → 0.1500，而"没压下去的那五条"才是这次的结论。** 那 20 条
亮标志的里只有 8 条**可压**——另外 12 条是语料故意构造的"一个标记词都没命中"，所以这个指标的
**地板是 0.10**。压掉的两条都不是靠加词：第 3 条从"整句**精确等于**一个应和词"放宽成"**全句
由应和词拼成**"（"好的，知道了"原先落在"判不出来"），外加 `心情` 进"情绪与状态"那一族。**剩下
五条放弃**：`梦`/`雨`/`花` 那一路能把 `chitchat` 的歧义**清成零**、看起来最像"压到位了"，但它们
是话题名词不是语域信号。理由与账都在 `benchmarks/routes/CORPUS.md`。

**上一版：睡眠巩固（P4c）。** 这是第一件**在后台自己改库**的事，所以它值得单说：

* **一轮做三件事，次序是要紧的**：拍一份整库快照 → 按关联图分簇、每簇在**自己那一小块 W**
  上做「挖掉一半、看还认不认得自己」的回放 → 认出自己的那些**「巩固次数」+1**。
* **它每天自己跑一次（默认开）**，跑完在记忆界面那句「SNN 热度」里留下真数字；托盘菜单与
  设置页「记忆」各有一个「立即巩固」，随时能按。
* **它只动「巩固次数」**——不改记忆正文、不改权重、不影响召回排序，改之前拍快照、留最近
  5 份。
* **认得出来多少，量在纸上，而这一次的结论是"没有结论"**：合成语料分不开"分簇解决了容量"
  与"那份语料自己的近重复压住了辨认率"。这是如实交付的一部分，不是没做完。

细节见下面的「睡眠巩固（P4c）」。**P4a 与 P4b 没有改出厂行为**（前者只交付一个数、后者的
联想通道默认关），所以它们不进这一节，分别写在下面「关联基质量具：图 A 与 W」与
「联想通道与邻居面板（P4b）」。

**更早：任务记忆、托盘与定时触发（P3b）。** 三件事，都是 P3a 留下的接缝的兑现：

* **关窗不再等于退出。** 窗口收进系统托盘，进程继续活着（这是下面那件事成立的前提——
  关窗即退的进程在"到点了"那一刻已经不在了）；真退出走托盘菜单的「退出」或 Ctrl+Q。
* **提醒真的会响。** `set_reminder` 从 P3a 起只落盘，现在到点弹气泡 + 在对话区留一条；
  程序没开着时错过的那些，下次启动聚合成**一句**，不逐条弹也不静默丢。
* **一轮任务可以只记一条。** 设置里「记忆」页一个勾选框（**默认不勾**）：勾上之后，调过
  工具的那一轮落一条 `TOOL_RESULT`，正文是回复、`meta` 里带工具轨迹；没调工具的那一轮
  逐条照旧——**那是个加法**。

细节见下面的「托盘与定时触发」。

**更早：工具与语域（P3a）。** 模型**真的能动手**：七个工具（查记忆 / 读记忆 / 写记忆 /
遗忘 / 看时间 / 设提醒 / 读文件）在对话里可用，**改变状态的那三个要你在对话流里点一下
内联卡片才执行**，没点就是不做。哪一轮给不给工具由**语域路由**决定（斜杠命令 + 一张手写
的标记词表 + 一个默认关着的模型自分类），路由本身由 `benchmarks/routes/` 那 120 条语料
离线量着走。工具轮次写进逐字稿并能回放，界面上显示的是**真实的调用轨迹**、不是模型的
自述。细节见下面的「语域、工具与确认闸门」——**那里有两条必须辨析的术语**。

**更早：金标准测试集 + 四项指标 + CI。** 它是闸门型资产——换嵌入模型、调 K、调阈值都要它
兜底。此前量具只有 `bench_space.py` 的 20+20 对，量的是**配对级的分隔度**（一句话对一条
记忆的 Jaccard 能不能分开），**没有候选池**，所以真正决定召回行为的 K、阈值、MMR 去冗、
token 预算驱逐一条都没被量到。那一版建出 `benchmarks/gold/`（200 条虚构记忆 + 76 条带
ground truth 的查询）、四项指标 **hit@K / MRR / 误注入率 / AUC**、`tools/bench_recall.py`，
并把门槛接进 CI 与每次提交。细节见下面的「金标准集与门槛」。

**更早：首次使用时定一次人设。** 人格锚从一条变成两条——一条是程序内置的**事实**
（不可改、不可删，保证任何模型读到的身份完全一样），一条是你写的**说话方式**（可改、
可删）。全新的记忆库第一次启动时，对话区里出现一张卡片问一次，**答完之前输入框是灰的**；
以后在「设置 → 人设」里改。把你写的那条删掉，下次启动会重新问一次。细节见下面的
「首次运行：定一次人设」。

**更早：外观可调 + 一个能长大的设置窗口。** 主色三预设或自定义取色、壁纸只铺对话区且
可见度可调、明暗跟随系统（Qt 外壳与网页对话区**由同一次判定驱动**，不会一边白一边黑）；
顶栏加了「设置」，里面除了外观还有后端 / API 页。顺带修了三处布局硬伤：窗口初始尺寸按
屏幕算、三格分栏不再能被拖没、会话列表改成两行式。顶栏状态文字那一处**反而坏了**：换成
`ElidedLabel` 之后，它用的 `QSizePolicy.Ignored` 让布局把标签宽度算成 **0**，状态文字从
"会被硬裁"变成**一个字都不显示**，真正修好是 2026-10-10 那次（见「跑测试与 CI」里那段）。
当时验收看的是 `text()`，而 `text()` 一直是对的；要看的是"布局到底给了多少宽度"。

> 而是"认得出来多少**已经量在纸上**"：在合成语料上仍然随规模掉，而掉的原因是**那份语料
> 自己的近重复**、不是分簇——所以这里**没有**"分簇解决了容量"这个结论。见下面

托盘要有后台任务才值得常驻，而"到点了"要有常驻进程在听。

**本版：打包（P6a）——交付形态多了一个免安装的 Windows 目录。** `tools/build_exe.py`
把界面、QtWebEngine、对话区那几张网页资产与图标一起冻进 `dist/axo/`，**机器上
不需要装 Python**（Ollama 与嵌入模型仍然要）。产物不好找——`dist/` 是构建输出、在
`.gitignore` 里，编辑器里是灰的、远端上不存在——所以自检全过之后**在桌面放一个快捷方式**
（名字就是界面上的显示名），双击即启动。三件事值得单说：

* **冻结的入口是新的那一个，源码检出那条路没动。** PyInstaller 收的是**一份脚本**——它
  把入口文件当 `__main__` 跑，`__package__` 是空的，而 `ui/app.py` 里那几处相对 import
  在那种情况下解析不了。所以新增 `src/axo/__main__.py` 专门做冻结入口，它只有
  一句按名字找包的绝对 import（顺带让 `python -m axo` 也能用）。`run.bat` 走的
  仍然是 `python -m axo.ui.app`。
* **应用代码一个字没改。** 网页资产按**与源码相同的相对位置**放进 `_internal/`，于是
  `Path(__file__).with_name("theme.qss")` 那两处读取自动对上——这条假设由构建脚本的自检
  钉住，不成立就当场红，不留到运行时。
* **CI 验不了这一环，所以自检写在构建工具里。** 七条腿全在 `ubuntu-latest`，而 **Windows
  exe 只能在 Windows 上构建**。冻结坏掉的方式几乎都不抛异常（"双击之后什么都没发生"，
  或者"窗口开出来了、左上角空着"），所以 `tools/build_exe.py` 构建完立刻查盘上的事实，
  再真起一次**看有没有开出窗口、窗口上有没有图标**——判据不是"进程还在不在"。四条如实的
  限制见下面「打包（P6a）」。

## 只想用，不想编译

去 [Releases](https://github.com/lzmd-arch/Axo/releases) 下
`axo-<版本>-win64.zip`，解开，双击里面的 `axo.exe`。

**首次双击 Windows 会拦一下**——它没有代码签名，所有未签名的 exe 都会被这样拦：
点「更多信息」→「仍要运行」。

第一次启动是**空的**：没有记忆、没有对话，先看到的是一张人设卡片而不是输入框
（见下面「首次运行：定一次人设」）。要能聊天还得有一个模型，两条路任选：

* **本机**：装 [Ollama](https://ollama.com/download)，`ollama pull qwen3:4b`。
  4B 级量化模型，8 GB 显存这一档就够。想要**语义召回**（按意思找，而不是按字面）
  再加一个 `ollama pull nomic-embed-text`——没有它，召回退化成纯词法，能跑但没那么聪明。
* **云端**：设置 → 云端后端，填一个 API key（DeepSeek，或任何 OpenAI 兼容的端点）。
  这条路不需要显卡，也不需要 Ollama。

产物是**免安装**的：解开就能用，删掉那个目录就等于卸载——你的数据不在里面，
见「数据放在哪」。

如实说明的四条限制：**没有代码签名**（所以有上面那句 SmartScreen）、**只有 Windows
x64**（它是 PyInstaller 冻结的产物，而冻结只能在目标平台上做）、**没有 Live2D**
（P6b 在等 Cubism 物料）、**不装 Ollama 也不填 key 就是开得起来但聊不了天**。

## 跑起来

这一节是**从源码跑**。只要一个能用的程序，看上面那节。

前置三件：**Git**、**uv**、**Ollama**。

* **Git**——`winget install --id Git.Git`，或 <https://git-scm.com/download/win>。
* **uv**——本项目的运行入口：`winget install --id astral-sh.uv`，或 `pipx install uv`，
  或照 <https://docs.astral.sh/uv/getting-started/installation/> 走。装完
  `uv --version` 应该打印一行版本。
* **Ollama 已安装并在运行**（<https://ollama.com/download>），且至少有一个模型：

```bash
ollama serve                                  # 另开一个终端，或让它作为服务常驻
ollama pull qwen3:4b                          # 4B 级量化模型，8 GB 显存这一档就够
ollama pull nomic-embed-text                  # 嵌入模型（P1 起用）
```

### 如果 `ollama pull` 报证书错误

有些网络里 `registry.ollama.ai` 这一个**主机名**会被中间设备拦掉，报的是
`x509: certificate signed by unknown authority`。核对方法：

```bash
echo | openssl s_client -connect registry.ollama.ai:443 2>&1 | grep -iE "s:|i:"
```

若签发出的是一张自签名证书（例如 `O=redirect-cnzz`），而 `ollama.ai` 本身的证书
链是正常的，那就是针对这个域名的拦截，不是 Ollama 的问题。

**不要用关掉证书校验的办法绕**——那等于让一台中间设备随便签发证书。
可行的替代路径是从 `hf-mirror.com` 取 GGUF 再导入（`ollama create` 支持本地
GGUF，完全不需要联网）：

```bash
# 1. 取 GGUF（hf-mirror 通了就行；huggingface.co 的直连在这种网络里也常被拦）
curl -L -C - -o /tmp/Qwen3-4B-Q4_K_M.gguf \
  https://hf-mirror.com/Qwen/Qwen3-4B-GGUF/resolve/main/Qwen3-4B-Q4_K_M.gguf

# 2. 校验（大小与 sha256 可从 hf-mirror 的 /api/models/<repo>?blobs=true 拿到）
#    sha256: 7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5

# 3. 导入（Modelfile 内容见下面的「模型定义」）
ollama create qwen3-4b -f Modelfile.qwen3-4b
```

**模型存哪，得先定。** Ollama 默认把权重放 `%USERPROFILE%\.ollama\models`，一个
4B 模型 2.5 GB 起，几条就把系统盘吃掉。换盘的办法是环境变量 `OLLAMA_MODELS`：

```powershell
# ⚠ 这是**进程级**的，重启机器就没了。要持久请写进系统环境变量。
# ⚠ 而且**服务端也读它**——只给 CLI 设、不给服务设，CLI 写到一个盘而服务端去
#   系统盘找，症状是"导入说成功了，但模型列表里没有"。
$env:OLLAMA_MODELS = "E:\ollama-models"      # 盘符换成你自己的
# 设完之后要重启 ollama（服务端在启动时读一次，运行中改环境变量它看不见）
```

**模型定义**（`Modelfile.qwen3-4b`，采样参数取自 Qwen 官方 Model Card）：

```
FROM ./Qwen3-4B-Q4_K_M.gguf
PARAMETER temperature 0.6
PARAMETER top_p 0.95
PARAMETER top_k 20
PARAMETER num_ctx 16384
PARAMETER num_predict 2048
```

`num_ctx` 是 16384 而不是 32768：4B-Q4 的权重占约 2.5 GB 显存，8 GB 这一档的卡上
16K 的 KV cache 还放得下，32K 就要开始往内存换页、速度明显掉。
系统提示**刻意留空**——人格锚是终端侧的东西，走上下文装配进 system 消息，
不写死在模型定义里；写死就等于把性格绑回了模型。

然后取代码、装依赖、起界面：

```bash
git clone https://github.com/lzmd-arch/Axo.git
cd Axo
uv sync --all-extras
uv run python -m axo.ui.app
```

`uv` 会自己把 Python 3.12 拉下来，不需要你预装。`--all-extras` 把三组可选依赖
（`app` 界面、`llm` HTTP 客户端、`pack` 打包器）都装上；下面各节写的是更窄的
`--extra app --extra llm`，因为跑测试只要这几组——**但 `uv sync` 是精确同步**，
写窄了它会把没提到的那些摘掉，所以每一节都带全自己需要的那几组。

窗口出现后：顶栏应显示「Ollama 就绪 · N 个对话模型」，在下拉框里选模型，
打字，回车。文字会逐字出现。**如果这是一个全新的记忆库**，先看到的是一张人设卡片，
不是输入框——见下面「首次运行：定一次人设」。

**嵌入模型不会出现在下拉框里。** 判据是 Ollama 自报的 `capabilities` 含
`completion`——`nomic-embed-text` 只报 `embedding`，选它来聊天只会得到一个与
服务端语义无关的报错。状态栏会写明隐藏了几个。

### 首次运行：定一次人设

全新的记忆库第一次启动时，对话区里是一张卡片，而不是能打字的输入框：

* 上半段是**内置的那条**——这套终端本来带着的事实（记忆存在本机一个文件里、不属于
  任何模型、不知道的就说不知道）。**它不可改**，卡片上那段文字是只读的；要改它得改
  程序。这是"任何模型读到的身份完全一样"这句话的代价，也是它的全部意思。
* 下半段是一个空框，等你写**你想让它怎么说话**。程序刻意不给默认性格——填一句默认的，
  就等于在你开口之前替你把"它是什么样"这个决定做完了。
* 「就这样」把框里的字写进记忆库，**框空着时它是灰的**；「这一次先不写」放行，什么都不写。

两个按钮因此**不重叠**：一个要求你写了东西，一个专门用来放行。

答完（写了或选「先不写」）卡片收起、输入框解锁。写下的那段与内置那段**存在同一个记忆
库里**，所以换模型、换后端都还在——它本来就是"终端侧的东西"。

以后在「设置 → 人设」里改。那里两段正文都在：内置那段是只读标签，你写的那段可编辑，
配「保存我写的这段」与「删掉我写的这段」。保存**立刻生效**（下一次提问就带上），但它
与主题那种设置**不一样**——「撤销修改」只回退外观，不会撤销人设；这句话写在那页上，
因为它是这个窗口里唯一一处"看着像能撤销、其实不能"的地方。

把用户那条从记忆窗口里彻底删除，**下次启动会重新问一次**（本进程内不再弹，因为那时你
多半正在跟它说话）。注意「先不写」只是"这一次"：下次启动卡片还会来，永久不问的唯一
办法是写下任意一句——哪怕一个字。**这句话卡片上写着**（按钮的悬停提示里也有），因为
第一次手动验收时它正是被当成 bug 报上来的：行为没错，错在**没说**。这是有意的取舍：
没写就等于没做这个决定，而写一条空正文的锚、或另存一个"已经问过了"的标志，都是给
同一件事造第二个事实来源。

### 记忆界面

顶栏「记忆」开一个独立窗口（不挤现有的三格）。左边是全部条目，右边是选中那条的四段：
条目本身 / **本轮归因** / 向量状态 / 未启用占位。三个写动作与一个后台动作：

| 动作 | 它做什么 | 要留意 |
|---|---|---|
| 改正文 | 重算词法 SDR，并**丢掉该条的语义向量**交回填管线补 | 纯本地、瞬时，不等网络；**内置那条人设不给按** |
| 软遗忘 | 置 `tier=COLD`，可恢复 | **钉住的条目不给按**（见下） |
| 彻底删除 | 连向量一起删，问两次 | 内置那条不给按；删自己写的那条人设 = 下次启动重新问你一次（见上） |
| 以它为线索召回一次 | 用这条正文当 query 跑一次召回 | **探索参数**，与真实注入的阈值/条数不同 |

三条得先知道的事：

**「钉住」的条目禁软遗忘。** `recall` 在层级判定**之前**就跳过 pinned 的条目，所以
软遗忘一个钉住的条目是个无声的空动作——界面会显示「已遗忘」，而它照旧在每一轮的
上下文里（人格锚尤其：`persona_texts` 只看 `kind`，不看 `tier`）。按钮因此置灰并把
理由写在 tooltip 里，要让它消失只能彻底删除。**两条人格锚都是钉住的**，所以对它们
来说「遗忘」永远是灰的——用户写的那条也一样，它是**特意**钉住的：性格这种东西不该
因为"最近没用上"而被悄悄淡出。

**「以它为线索召回一次」用的是探索参数**（20 条、阈值 0.02），界面上会写明。它排出来
的名次**不等于**它被注入的理由——真实注入是另一套阈值与预算。不标注的话，很容易把
探索排名当成账本的解释。

**编辑之后那条会短暂显示「没有语义向量」，这是正常的。** 编辑是纯本地的，不等网络，
补向量交给既有的回填管线；`missing_embedding_ids` 按 `created_at` 升序取，改过的旧条目
凭「旧」插到队首，下一轮必被捡起。这段时间它照常参与词法通道的召回。

选中条目后，详情区下面多两栏：**局部邻居列表**（P4b）与**SNN 热度**（P4c）。

* **局部邻居列表**：建图那一刻它的前 8 个邻居，按边权降序，点一条跳过去。它展示的是
  **图的结构**，与"联想通道在召回里有没有增益"是两件事。
* **SNN 热度**：巩固跑过没有、认出了多少条。**没数据的时候一个数字都没有**——"巩固还没
  跑过"这句话里连 `0` 都不出现。有数据才写真数字（**M 条被回放认出，累计 N 次**），数据
  源是库里的 `reinforce_count` 与 `memory/consolidation/last.json`，见下面「睡眠巩固
  （P4c）」。
* **它叫"热度"，但这一版画不出热度，原因是那个数没有来源。** 面板要的是"每条记忆一个活跃
  度"，而基质一步算出来的是"哪条被激活得最强"——一个 argmax，没有"逐条一个标量"这个形状；
  而且那是**速率级**的活动，不是在跑脉冲。所以这一版它报的是**巩固的计数**，不是热度。至于
  那个数据源本身值不值得用（P4a 实测它在目标规模上塌掉），是另一件事，别和"还没建"混成一句。

图建没建、是不是过期，由这一栏的顶栏如实说出来——**说不出数字的时候就不说**，包括不写
`0 个邻居`。

### 设置窗口

顶栏「设置」开一个独立窗口，左分类右内容（**外观 / 人设 / 后端 · API / 工具 / 记忆**，按使用
频率排）。
**它是非模态的**——主色与壁纸可见度是"必须看着调"的参数，模态会让"拖滑杆 → 看效果"
变成"关窗 → 看效果 → 再开窗"。改动**按下就生效、随手存下**，没有「确定」那一步；
「撤销修改」回到**打开这个窗口时**的样子。

**外观**页：

* **主色**：三个预设（蓝紫 `#6b8afd`、青绿 `#3fb950`、琥珀 `#d9a441`）或「自定义…」取色。
  预设各带一支**手挑的**浅色值（例如蓝紫在浅色下用 `#3559c7`），自定义色则按对比度下限
  现算。这两件事在窗口里分开显示——用户选的原色与屏幕上的实际用色未必相同，**换过就要说**。
* **明暗**：跟随系统 / 强制暗色 / 强制浅色。跟随系统时 Qt 外壳与网页对话区走**同一次
  判定**（Qt 读 `QStyleHints.colorScheme()`，再把结果写进网页的 `documentElement`），
  网页侧**不再自己检测** `prefers-color-scheme`。两侧各判一次迟早会在某台机器上分成
  两半，而那种样子很刺眼、却很难归因。
* **壁纸**：选图后**复制进数据目录**（`%LOCALAPPDATA%\axo\wallpapers\`），
  设置里存的是受控文件名。原图被移动/删除/U 盘拔掉之后壁纸仍在；文件不在时按无壁纸
  显示并说一句，**不清掉设置里的名字**——文件回来了壁纸自己就恢复。只铺对话区。
  可见度 0–70，默认 18（正好等于网页侧此前写死的那个遮罩值，所以接上这个功能不改变
  任何已有观感）。上限 70 是**刻意的**：再高遮罩就只剩三成不透明度，而消息是铺满整个
  对话区滚动的，没有哪一块是可以不看的。

**人设**页：与首启卡片同一个编辑器的常驻版（内置那段只读、用户那段可改可删）。见上面
「首次运行：定一次人设」最后两段。

**后端 / API** 页：服务地址 + 「允许远程主机」+ 「测试连接」。

**工具**页：目前只有一项，**`read_file` 的可读目录**。加一条目录等于一次**授权**，所以
它是"边改边生效"的（与后端页的「应用地址」不同），但「撤销修改」会把可读目录也一起退
回去——那个按钮上写着"回到打开这个窗口时的样子"，而"哪几个目录被授权了"正是那个样子的
一部分。

> **一份都没有 = 那个工具被禁用**，不是"默认给个目录"。默认既不是当前目录也不是家目录：
> 模型去试一个没配的工具会白花一轮，所以未配置时 `read_file` **根本不出现在声明里**
> （省 prompt token），硬调则回一句"未配置可读目录"。校验用
> `Path.resolve()` + `is_relative_to()` 逐根比，**不是字符串前缀**——`/data` 会匹配
> `/database`。`resolve()` 顺带吃掉 `..` 并跟随符号链接，所以**符号链接逃逸天然被覆盖**。

> **「允许远程主机」这个勾选框不能省，也默认不勾。** `llm/ollama.py` 的 `_client()` 对
> 非本机地址会直接抛错，它是一道"让手滑把 `localhost` 写成内网 IP"变成一次**明确确认**
> 的**护栏**。所以只放地址输入框、不放这个框，等于放一个填了就一定报错的字段。勾选框旁边
> 如实写出代价：**「内容不出设备」这条假设从此刻起不再成立。** 改地址时若正在生成会被
> 拒绝——那一轮请求已经发出去了，换地址影响不到它，却会让下一轮用上另一个服务端，而
> 界面上看不出两轮回复来自两个模型。

**记忆**页：一个勾选框，**「把一次任务合成一条记忆」，默认不勾**。勾上之后，**调过工具的
那一轮**只落一条 `kind=TOOL_RESULT` 的记忆（正文是回复，`meta` 里带工具轨迹）；**没调工具的
那一轮逐条照旧**——那是个加法，不是一个替换，打开它不会让任何一轮突然不再被记住。默认关
是刻意的，与「模型自分类」同一个姿态：**新的入库语义先不替用户做主**。理由见下面
「托盘与定时触发」那一节。

同一页下面还有**睡眠巩固**那一节（P4c）：**「每天自动巩固一次」勾选框（默认勾）+
「每隔 N 小时跑一次」+「立即巩固」按钮**。关掉勾选框只**禁用**那个小时数、**不动**按钮——
"不自动跑"与"不许跑"是两件事，混起来用户会以为整个功能被关掉了（这个区分在按钮下面那句
提示里明说）。间隔在界面上是**小时**、存进设置的是**秒**：86400 那个数字对读它的人毫无
意义，而"24 小时"一眼就懂。同一页那条提示里如实写着**它会真的改库、会拍快照、周期调得越
短磁盘上攒得越快**，以及**默认的一天是占位值、没有实测依据**——代价写在好处前面，与「启用
联想通道」那个勾选框同一姿态。

设置存在 `QSettings("Axo", "axo")`（Windows 上是注册表），外观在
`appearance/*`、后端在 `backend/*`、工具授权在 `tools/*`、记忆在 `memory/*`。**读到的值一律当不可信输入**：每个字段各自回落、
绝不抛——"设置坏了导致程序打不开"是最糟的一种失败。一个已知的类型陷阱：注册表里读回来
的 bool 常常是字符串 `"true"`/`"false"`，而 `bool("false")` 是 `True`，所以可见度存
**整数百分比**、bool 一律过一遍 `_as_bool`。

### 语域、工具与确认闸门

> 这一节是**仓内的规格**。「同一灵魂，两种语域」这个说法出自仓库外的 `规划.md`——那份
> 稿子评审时够不着，而 P3 需要一份随代码走、能被评审的定义。这里只写**与已实现的代码
> 对得上的那部分**；P4 及以后的范围与个人规划内容不搬进来，那是另一份文档的事。
> （P3b 落地之后，它那一半规格在下面「托盘与定时触发」里。）

#### 语域是什么

**同一个灵魂，两种语域。** 陪伴型助手与干活型助手的分野不是两个产品、不是两种人格，
更不该是界面上一个「模式」开关——**用户不该先做一次分类再说话**。它是同一套人格在两种
说话方式之间的切换：闲聊时它在，干活时它也在，只是手上多了一件事。

于是"这一轮算哪种语域"必须自动定。这是 `agent/router.py` 的全部职责，它是个**纯模块**
（不 import Qt、不 import httpx），所以每一条判定都能在核心腿里逐条断言，也能被语料离线量。

#### 两个轴，别混名

规划稿把两件正交的事画成了一条链（「闲聊 ⇄ 任务中·可闲聊 ⇄ 等待确认」）。代码里**拆开**：

| 轴 | 取值 | 在哪儿 |
|---|---|---|
| **路由轴** | `CHAT ⇄ TASK` 两态，带迟滞 | `agent/router.py` |
| **agent 轴** | 正在调工具 / 正卡在确认卡片上 / 正在收尾 | `agent/loop.py` + `agent/gate.py` |

**「等待确认」是 agent 的瞬时状态，不属于路由。** 混名之后，"用户还没点那张卡片的时候算
哪种语域"会变成一个没法回答的问题——而实现上它必须有个答案。答案就是：**路由不管这件事，
它照旧是 TASK。**

#### 路由的三种信号，优先级从高到低

| # | 信号 | 特点 |
|---|---|---|
| 1 | **斜杠命令** `/task` `/chat` `/help` | 用户显式指定，**无视迟滞**；确定性、可离线断言；模型不可靠时**唯一可靠的入口** |
| 2 | **规则层**（一张手写的标记词表） | 表错了看得见、改起来是一行；**判不出来时返回"不知道"，不猜** |
| 3 | **模型自分类**（**默认关**） | 一次额外 LLM 调用；开不开由语料报告定，不由拍脑袋定 |

**斜杠命令仅当轮有效，裸命令切状态。** `/task 帮我查一下` 只影响这一轮；光打一个 `/task`
改的是**后续若干轮**的状态。命令本身**不进逐字稿正文**——用户说了 `/task`，进正文的是
"帮我查一下"，否则"用户说过 /task"会被当成一句话记进记忆库，而那不是任何人对任何事的
陈述。命令作为元数据记进消息供回看。`/help` **本地渲染**，不发请求。

**认不出的斜杠不是命令。** `/home/user/笔记.txt 里写了什么` 是一句正常的话（用户可能就在
问一个路径），当命令吞掉或报一句"未知命令"都会让人没法正常说话。

#### 词表里有一族是"去看已经存下来的东西"

写记忆是祈使句（"记住 X"），**查记忆几乎全是问句**（"我上次说想买什么？"），所以这两件事
在词表里是分开列的两组。分开的第二个理由更硬：查记忆那一族**整族都会被第 7 条吃掉**——
规则层的判定是一张从上往下的表，第 7 条是"句末问号 → 闲聊"，而"我上次说想买什么？"恰好
以问号结尾。于是句子没问题、词表也没坏，就是**这一族永远走不到 TASK**，而 TASK 是"这一轮
声明工具"的同义词。用户看到的因此不是"答得不好"，是模型回一句"我这一轮没有工具"。

那一族的主力词是 **`上次`**，而它**不是动词**：收它是因为它指的是"这件事发生过，而记录不
在你眼前"——也就是"去查"。另外是"说的是记忆这件事"本身（`我的记忆` / `记忆里` / `记忆库` /
`回想`）与三个**同义动词缺口**（`记录一下` / `念一遍` / `别忘`，表里原本只有 `记一下` /
`念一下` / `忘掉`）。`别忘` 整词入表是个刻意的写法：否定窗口只看标记**之前**那几个字，
`别` 在这个标记内部，所以它不会被否定判据反手判成闲聊。

**刻意不收的词与收进来的一样要紧。** `看看` / `几点` / `记得` 都不在表里：它们出现在
"你看看这个笑话"、"你几点睡的"、"记得昨天那个吗"里，收了会把日常闲聊判成任务——而那种
代价用户在**统计上看不见**（它落在闲聊上，不落在语料上）。这三个词在规则层都落到"判不出来"
（`None`），交给迟滞状态机，而不是硬判成闲聊。`tests/test_router.py` 里三条测试各钉一件：
那一族必须进 TASK（含问句）、`别忘` 不许被当成否定、**不收的那三个词不许被好心补进表里**。

**同一张表上还有一条分界线：收"语域信号"，不收"话题名词"。** 前者说的是"这句话是要对方做件
事，还是说句话"（`心情` 属于说话人自己的状态，与 `累`/`开心`/`难过` 同族）；后者说的是"这句
话关于什么"，而**任何语域都可能有那个话题**——"我养的花开了"是闲聊，"帮我查一下这种花怎么
养"是委托。按语料分数算，把 `梦`/`雨`/`花` 收进来能把歧义率从 0.1500 压到 0.1083、`chitchat`
那一类**一条不剩**；不做的理由就是上面那条线：**分数来自那 120 条，代价落在用户看不见的地方**。
同一轮还量出两条死路记在 `benchmarks/routes/CORPUS.md` 里（`做梦`/`下雨` 压根没在对应正文里
出现；往否定词表加 `别搜` 对"别搜了，我找到了"**一个数都不动**，因为否定词只在已经有 task
标记时才被查）。

**"整句应和"不能要求整句**精确等于**一个应和词**——中文的应和是拼出来的。`normalize` 只做
NFKC + casefold、不删标点，所以"好的，知道了"既不是"好的"也不是"知道了"，一路落到"判不出
来"。判据是**全句由应和词拼成**（标点先去掉、句尾语气助词不算）——仍然是
**全句**：`好，我们开始吧` 切到"我"就断了，照旧判不出来。放宽成"含有应和词"是不行的，那会让
任何以"好的"开头的句子变成闲聊，而第 5 条（句首礼貌词）刻意只给 0.7 就是为了不在这件事上
把话说满。

#### 迟滞是**不对称**的，理由是代价不对称

要迟滞是为了治"人格闪跳"（用户在任务中间插一句"好的"，下一轮助手就不干活了）。但**对称地**
实现它——往返都要连续两次反向信号——会让**开箱第一句「帮我查一下 X」拿不到工具**：状态从
`CHAT` 起步，一次 task 信号不够两次，于是助手说"我查不了"。那正是本版要交付的那件事，
不能死在门口。

所以只有**一个方向**要迟滞：**从 `TASK` 落回 `CHAT`**（连续 2 次反向信号）。往 `TASK` 走
是**立刻**的。两端代价不对等：

* 误进 `TASK` 的代价只是"这一轮工具可选"，而改状态的动作还有确认闸门兜着；
* 误离 `TASK` 的代价是**一件正做到一半的事没了工具**，而它恰恰是最常见的闪跳。

#### 歧义：只出标志，不出文案

规则层一条都没命中时，路由给出 `ambiguous=True`：语域退回 `CHAT`、**且不改变迟滞状态**
（"不知道"不是一个方向上的信号），循环据此**本回合一个工具都不声明**、正常聊天，并请模型
带一句确认。

**路由不产文案，也产不了**——它不知道用户上一句说了什么。"确认本身也是陪伴感"那句话由
**模型的措辞**承担。

#### 一个回合只判一次，判完存下来

路由的结论由一个地方产出、一个地方消费：`MainWindow._on_submit` 开头调一次
`_route(text)`，把三样结果（这一轮语域 / 要不要工具 / 要不要反问）**存进 `self._turn_*`
三个字段**，之后整条链路只读这三个字段——建环境槽、决定声明不声明工具、决定走
`AgentWorker` 还是 `ChatWorker`，全都不再重判。`_route` 是**纯决策**：不碰界面、不发请求。

**为什么要把这件事写进规格。** P3a 的规则层、迟滞状态机、120 条语料与 CI 门槛全都做完
而且全绿了很久，界面上却**一个消费者都没有**——`MainWindow` 里另有一个只认裸斜杠的
`_register` 字段，语域事实上由"用户打没打 `/task`"决定。后果不是"少个功能"，而是它**看起来
像模型不听话**：模型说"已通过 `write_memory` 保存"，而那一轮请求里根本没有 `tools` 字段。
一个纯模块有一百条测试，也证明不了它的结论**被用上了**——测试覆盖的是模块，不是接线。

所以那条 `_register` 旁路**删掉了**，不是留着不用：只要它还在，下次有人想让某个分支改
语域时，最省事的写法就是去改它，于是同一条线再断一次。`tests/test_ui_router_wire.py` 用
ast 同时钉"旧字段不存在"与"三个字段真的被赋值"——后者防的正是上面那个 bug 的精确形状。

#### 七个工具，三个过闸门

| 工具 | 确认 | 结果可回放 | 说明 |
|---|---|---|---|
| `search_memory` | — | 是 | 走 `memcore.recall`，**`settle=False`**：模型可能试探性调用，不该因此改变权重排序 |
| `read_memory` | — | 是 | 按 id 直读 |
| `read_file` | — | **否** | 读到的是**此刻**的文件内容，文件随时会被改。沙箱见上面「设置窗口」的工具页 |
| `get_time` | — | **否** | 这个工具的全部语义就是"当前值"。时钟由 `ToolContext` 注入，所以能测 |
| `write_memory` | **要** | 是 | 落 `kind=FACT`、标明来自模型；可信度由闸门背书 |
| `forget_memory` | **要** | 是 | **软遗忘**（`tier=COLD` + 回程票），不是删除 |
| `set_reminder` | **要** | 是 | 落盘，并由 `ReminderScheduler` 到点触发（见下面「托盘与定时触发」） |

**「要不要点头」只声明一处**：`Tool.requires_approval`，闸门只**读**它。不在闸门里再写一张
表——两张表迟早不一致，而表现是某个改状态的工具悄悄变成不需要确认，**那是一种没有任何
症状的失效**。

**「结果能不能回放」同理，但声明在 `ToolOutcome` 上**（`replayable=False`），而不是在工具
类上：它是**这一次返回**的性质，写在构造结果那一行，与"这个值是快照"的理由紧挨着。默认
`True`——理由与代价见下面「回放出去的东西」那节。**没有第二条表**：`session/assemble.py` 的
L5 不认工具名，只认逐字稿里那一位。

这些失败**不抛异常**，一律变成 `ok=False` 回灌给模型让它自我纠正（未知工具名、参数不合法、
工具内部异常、闸门拒绝）。这与回合末写记忆的纪律**不同**——那里写入失败要炸给用户看，
因为"以为记住了其实没记"是最坏的失败。

#### 确认长什么样，以及三种收场

卡片是**对话流里的一个节点**，不是模态框——模态框会挡住"任务中也能闲聊"这件事。

**标题自带一块不透明的底。** 卡片标题（「需要你确认 · write_memory」）与工具结果行的
标题一样，是 12px 的 `--fg-muted`，浮在**壁纸**上（`.msg` 自己没有背景），而壁纸是用户
选的任意一张图。靠蒙层不够——它只压掉 18% 的壁纸：纯白壁纸下对合成底只有 **3.59**、
浅色配纯黑壁纸 **2.96**，都在正文下限 4.5 之下（口径见 `ui/color.py`）。

**修法是不透明的 `--bg-elevated`，不是照抄顶栏那套 `color-mix(…, 70%, transparent)`。**
壁纸还透上来 30%，暗色配纯白壁纸时合成底成了中灰 `#5d5f64`，对 `--fg-muted` 只有
**2.08**——**比压根不打底还低**。不透明把这件事变成一个与壁纸无关的数（暗 5.66 / 浅
4.81），于是它可被断言而不是"看着还行"：`test_theme.py` 两条（底不透明、字过 4.5）互相
当前提，缺一条都会放行一种看不清的写法。

> **顶栏有同一个问题，量出来更低**（状态文字也是 `--fg-muted` 画在 70% 那层上，
> 暗色配纯白壁纸 2.08）。它没在这次改动里——那是一个独立组件的观感决定，不是本版交付物。

> **摘要由模板从参数生成，绝不让模型写。** 让模型解释自己的动作是幻觉的标准配方，这条
> 纪律在确认文案上和别处一样。

| 情形 | 裁决 |
|---|---|
| 点了允许 | 执行 |
| 点了拒绝 | 不执行，回灌一句拒绝 |
| 超时（默认 180 s）/ 取消 / 窗口关了 | **按拒绝** |

**fail-closed 是唯一安全的默认。** 把"没答"当成"同意"，会让用户在一次卡顿或一次超时之后
发现记忆里多了一条他从没批准过的东西，而且没有任何地方记着那件事发生过。卡片上有倒计时
和一个「跳过」（=立刻拒绝），所以正常收场由用户点，计时器只是给"人走开了"的兜底。

**四种收场都在真机上走过一遍**（2026-10-10，`qwen3-4b`）。这一版之前闸门是**零验证**的，
而它恰好是本版最没有先例的一环，所以记下每种收场各自**靠什么**算验过：

| 收场 | 怎么验的 | 证据 |
|---|---|---|
| 允许 | 人工点卡片 | 工具真的执行，回灌里带真实检索结果，模型引用了 id 与权重 |
| 拒绝 | 人工点卡片 | 回灌"这一步跳过了"，模型照实说被跳过、**没有**假装查过 |
| 停止 | 卡片挂着时点 ■停止 | worker 约 **1 秒**内醒来（时间戳与前一行同秒）。若 `ApprovalSlot.cancel()` 没接上，它要等满 180 秒 |
| 窗口关闭 | 自动化子进程测试 | `tests/test_ui_agent_worker.py` 等到 `approval_needed` 真发出后才走 `_shutdown` 的形状，断言退出码 0（不是 `0xC0000409`）、`RAN=0`、`STRAGGLERS=0` |

闸门的**机制**用 `search_memory` 验，而不是用 `write_memory`——因为这个模型肯调前者、不肯调
后者（见下）。验的是 `gate.py` 读 `requires_approval` 这条路径，与是哪个工具无关。探针改完
已还原，`search_memory` 仍是放行的那一类。

> **gui 腿曾经谁都不跑，现在有一条自动化在跑它了**（`tools/ci_local.py` 的第四条，标着
> 「本地独有」）。在它之前：`ci.yml` 用 `--ignore-glob='tests/test_ui_*'` 把这些文件排除在
> GitHub 之外（理由是把 Qt 塞进无头 Linux 不划算），而 `ci_local.py` 的 5 条腿**一条都不碰
> `tests/test_ui_*`**，全仓没有任何脚本或工作流调用过 `pytest -m gui`。于是上面第四条那种
> 测试、`test_ui_agent_worker.py` 那条 `0xC0000409` 守卫、以及 `test_ui_router_wire.py`
> （P3a 的接线守卫），**跑与不跑完全取决于有没有人记得手敲那一行**——而一句"记得跑"不是
> 一条守卫，它们守的又恰好都是本仓踩过的坑。
>
> 这条腿只证明**本机**全过，证明不了 CI 机器上会过；后者要它自己进 `ci.yml`，那是另一件事
> （要重新评估在无头 Linux 上装 Qt 的代价）。所以汇总里它标着「本地独有」，没有假装自己是
> CI 的一部分。

**界面显示真实的调用轨迹，绝不转述模型的自述。** 这一条是量出来的，而且**读工具与写工具
完全是两回事**：

* **读工具很可靠。** `search_memory` 在新会话里第一次被问到，**3/3 都真的调了**，参数是
  合法 JSON 对象、符合 schema。
* **写工具一次都没调过。** 四句提示词（含"调用 `write_memory` 工具，参数 content 填……"
  这种把参数都写进去的）**0/4**，全部以"已通过 write_memory 工具保存记忆……该记忆已写入
  本地文件系统"收场。

所以"五轮只对一轮"那个数（来自计划书 §八 的探针：只有 2–3 个工具、没有完整上下文）**不能
当成本模型的整体可靠性**——它量的是"两个工具该调哪个"，而真实应用里的形状是**能读不能写**。
对一个记忆系统来说，假的"已记住"是最坏的失败：用户会因此不再自己记着这件事。所以工具行
必须进对话流，而且只有工具调用记录说了算。

#### 工具轮次怎么进逐字稿、怎么进上下文

**逐字稿 schema 1 → 3，只加字段、不改历史字节。** `Message` 加**四个可选**字段：
1 → 2 是三个工具字段（`tool_calls` / `tool_call_id` / `tool_name`），2 → 3 是
`no_replay`（见下一节）。都沿用既有的"非空才写"风格，所以 **schema-1/2 的老行逐字节不变**
——不写迁移脚本：逐字稿可以几百兆、可以整段删，重写既慢又给"崩溃丢整段"开一次口子，
而加字段需要的只是"新行多几个键"。读者天然版本无关（字段全可选，缺键取默认）。

**工具结果单独成层（`L5`），不并进近期对话（`L3`）。** 理由有两条：L3 的语义是"连续逐字稿，
断就停不挖洞"，工具行插进去会破坏连续性；而且工具结果是**最该被驱逐**的旧任务输出，单独
成层才能"先丢它"。

**装进去以「整对」为单位。** 一条带 `tool_calls` 的 assistant 行 + **紧随其后**的那些 tool
行是一对，装不下一整对就整对丢——**绝不半留**，半个配对是模型无法解释的对话。逐出记进
`LayerReport(Layer.TOOLS, …)`，账本里看得见。

**L5 排在 system 之后、`L3` 之前，这是一次重排。** 真实时间顺序里工具历史在最近对话之后，
把它整体提前的**理由**是工具对自包含；按时间把工具行插进 L3 会破坏上面那条连续性。**这是
本版剩下的残余风险**（可能与模型的时序直觉冲突），探针里专门观察过，兜底方案是"只回放最近
一对"，仍然不动 L3。份额 0.20 **从"流向 L4 的余量"里拿**——L2/L3 一个都没减：L5 是这一轮
任务当下最新最相关的内容，L4 是最便宜、最可丢的压缩层。

> **第一个回合的装配与今天逐字节一致**——没有工具行时 L5 是空的，而 `assemble` 只在
> RECALL/RECENT 上调额度、L4 拿剩余。这是"回归为零"的另一半。

**回放出去的东西，模型当成"现在仍然成立"。这是 2026-10-10 人工验收量出来的第二个后果，
计划书里没预料到。** 计划书 §十一 只把 L5 列成"重排会不会让模型困惑"，而真实发生的两件事
都不是困惑，是**旧内容的语义被抹掉了时间**：

| 回放的是 | 模型的行为 | 性质 |
|---|---|---|
| **拒绝**回灌（含"不要重试这个动作，也不要假装它已经完成"） | 此后**再不肯调那个工具** | **缺陷**：那句"不要重试"是为当轮写的（防它死磕同一个被拒的调用），但它是**工具结果、落了盘、被逐轮回放**，于是在模型眼里变成一条**仍然生效的规矩**——一次拒绝 = 该会话内对该工具的永久封禁，而用户完全看不出为什么，只会觉得"这模型怎么不肯查了" |
| **成功**结果 | 认为结果**仍然新鲜**，跳过重查 | 对 `search_memory` 无害；对 `get_time`/`read_file` 是**陈旧风险**——它们的"当前值"语义被回放抹掉了（回放的是过期时间戳、旧的文件内容） |

保存下来的对照组是干净的：同一句话、同一模型，**唯一变量是上下文里有没有那条拒绝**——
有，就不调；没有，就调。所以这不是模型随机抽风。

**两条都已修（schema 3 的 `no_replay`）。** 根因只有一句话：**逐字稿记了"调了什么工具"，
没记"它怎么结束的"**，于是 L5 只能把两种截然不同的收场——「用户拒绝了」和「这是一个过期的
快照」——都当成正常结果回放。修法就是补上这一位：

| 谁标 | 标成 | 为什么 |
|---|---|---|
| 闸门拒绝（`agent/tools.py` 的派发口） | `denied` | 那次拒绝是**当轮的一次性事件**，不是一条关于这个工具的规矩 |
| 结果不耐放的工具（`get_time` / `read_file`，`ToolOutcome.replayable=False`） | `stale` | 它们的语义就是**当前值**，而回放递过去的是**当时值** |

`session/assemble.py` 的 L5 遇到带这一位的对就**整对跳过**（不再搬进后续轮次），而那一对
**仍然留在逐字稿里**——用户回看时该看到"这一步被跳过了"。账本上它与「装不下」「数据坏了」
分列成三个数（`skipped` / `dropped` / `broken`），因为它们分别是三个不同的诊断。

同时把回灌的文案改成当轮语气（"**这一次调用**跳过了……**这一轮里**不要重试同一次调用"）。
这是补刀不是主修：路径上只要还有一处把工具行搬进上下文（未来的新层），它都不至于被读成
一条规矩。

**上面那句"界面里的回看渲染"当时被写成一个**将来**的风险点，而它其实当轮就已经漏了。**
`display_rows()`（`ui/main_window.py`）在**打开一个旧会话**时把逐字稿逐行转成气泡，`tool`
行照原样渲染——于是那段写给模型的话逐字出现在用户的对话记录里，标题还写着「工具结果 ·
write_memory」，而那一步根本没有执行过。这一处**不是改语气，是换一套说法**：带
`no_replay="denied"` 的行标题成「已跳过 · <工具名>」，正文换成一句人话。实时那一侧本来
就不用修——它显示的是确认卡片（「已允许」/「已拒绝」），给模型的那段正文从来没上过屏。

> **标题用「跳过」不用「拒绝」。** `"denied"` 是三种收场合并成的一个值——用户点了拒绝、
> 超时、卡片挂着时按了停止，`gate.py` 都归成 `ApprovalDecision.DENY`。写"已拒绝"对后两种
> 是**替用户认一件他可能没做过的事**。
>
> **`stale` 不换说法。** 那是真跑过的结果，只是个快照——`get_time` 的时间、`read_file`
> 的文件正文，正是用户回看时想看的东西。守卫里那条反空转（`test_a_stale_result_is_still_a_result`）
> 挡住的就是"把所有带 `no_replay` 的行都当成拒绝"——那只差把 `== "denied"` 写成 `is not None`。

> **为什么这一位必须在逐字稿里，而不是让装配器去查工具定义。** `session/` 与 `agent/` 同在
> 纯层，而 `agent/loop.py` 已经 import `session/budget`——反向就是环。所以"哪个工具的结果不
> 耐放"这条知识 L5 **够不到**，它必须随数据走。
>
> **为什么 `replayable` 默认是"能回放"。** 老逐字稿里那些工具对都是 schema-3 之前写的，
> 那时还没有闸门拒绝这回事，它们本来就是普通结果；默认成"都不回放"会把用户已有的工具历史
> 一次性抹掉。代价是每加一个快照型工具都要记得标，而那件事**没有症状**——所以有一条回归
> 守卫盯着已经标对的那两个（`test_the_two_snapshot_tools_mark_their_results_as_not_replayable`），
> 它盯不住"新工具忘了标"，那在运行期没有判据。

#### 两个「闸门」不是一回事

这个名字在本项目里指两件不同的东西，混名的后果是一个没法回答的问题：「这句话要过闸门，
那它怎么没问我？」

| | 记忆写入闸门 | 工具确认闸门 |
|---|---|---|
| 判什么 | 这句话**值不值得记** | 这个动作**要不要你点头** |
| 在哪儿 | `memory/policy.py::PerItemPolicy.drafts` | `agent/gate.py` |
| 形态 | 纯规则，无 UI，每轮都在跑（P1 起） | 有 UI、跨线程，只在三个工具上触发 |
| 失效的样子 | 库里多了没用的条目 | 记忆里多了没批准过的东西 |

一个是**记不记**，一个是**做不做**。

### 托盘与定时触发

**关窗不再等于退出。** 窗口收进系统托盘，进程继续活着；真退出只有三条路——托盘菜单的
「退出」、Ctrl+Q、`aboutToQuit`——而它们都汇进同一个 `MainWindow._shutdown`（幂等）。
判据是抽出来的一个方法：

```python
def _close_should_hide(self) -> bool:
    return self._tray is not None and self._tray.active and not self._quitting
```

三个条件缺一不可，每一条都有对应的失效：**没有托盘**时收起来就再也叫不回来；**托盘建了
但不可用**（某些精简版 Windows、没有面板的 Linux 会话）时那个 `TrayController` 是一个
空壳对象，只看"对象不是 None"会静默走进隐藏支，而图标根本不存在；**用户按了退出**时
`_quitting` 已经置位，这时再收一次就是"按了退出但进程还在"。这三种情形在真机上都不容易
碰到，所以它们是 `tests/test_ui_close_to_tray.py` 里的一张真值表，而不是靠手验。

> **托盘不可用的机器上，关窗行为与加托盘之前一模一样。** 这一条比"统一行为"重要：在
> 那台机器上拦下关窗，等于窗口关掉了、图标也没有——应用**变得够不着**，只能去任务管理器
> 里杀。所以 `TrayController` 不可用时全部方法都是空操作，判据也直接取假。

**图标是程序化画的**（`QPainter` 画圆角方块 + 中心一个点，底色取主题强调色）。这个仓库
**零图片资产**，而 Windows 上托盘图标**绝不能是 null**：那不是"没图标"，是一个空白方块，
看起来像程序坏了。形状选得粗是同一个理由——它在 16px 下还得认得出来。

**窗口标题栏、任务栏、Alt-Tab 上那三处用的是同一个记号**，装它的时机是主题解析那一步
（`MainWindow._apply_theme` → `_install_window_icon`），所以换主色时它们跟着一起变。它与
`--icon` 嵌进 exe 的那一份**不是一回事**：后者只决定资源管理器里那个文件长什么样，窗口自己
不设图标就是空的。

#### 菜单现在三项：「显示」「立即巩固」「退出」

「立即巩固」（P4c）与另外两项**同形**——托盘不认识主窗口、更不认识"巩固"是什么，它只把
"用户按了这一项"说出去（`consolidate_requested`）。这一项存在的理由是**定时那条路在界面上
看不见**：巩固默认每天在后台跑一次，而"它到底跑没跑、认出了多少"在托盘上没有痕迹，所以
得有一个随时能按的东西。它走的是与定时**同一个 worker、同一道单飞守卫、同一段收尾**，
差别只有两条：**跳过"库里没有新记忆"那道门**（用户点它就是要跑一趟），以及**结果弹一条
气泡**——自动那条不弹，否则每次开机弹一次就是噪音。设置页「记忆」里那个同名按钮走的是
同一条路，所以两处不会在某次改动里分岔成两种行为。

#### 提醒：什么时候看一眼

`set_reminder` 从 P3a 起就只落盘，因为"到点了"需要有东西在听；关窗即退的进程在那一刻
已经不在了。现在那个"听"的东西是一个**单发 `QTimer`**，每次响过之后按最新的事实重排：

* **延迟夹在 1 秒到 60 秒之间。** 下限防的是紧循环（`next_due` 可能是过去，允许 0 就是
  一个把 CPU 打满、界面上什么都看不出来的 0 毫秒循环）；上限防的是时钟跳变与休眠——
  每 60 秒对一次表是最省事的兜底。
* **先写 sidecar 再弹**（write-ahead）。反过来的话，弹出之后、落盘之前进程退出（关窗收
  进托盘的人随时会这么做），下次启动会**重弹**同一条。两个方向的代价不对称：重弹每次都
  会发生，而"标了却没弹成"很少发生。
* **已经响过的记在另一个文件** `reminders.fired.jsonl`。`reminders.jsonl` 的契约是"这个
  文件装的是**还没被提醒的事情**"，往里掺第二种记录会让那句话变成假的，也会让
  `ReminderStore.all()` 从"读出全部提醒"变成"读出两种东西"。
* **错过的一堆收成一句**：程序没开着的时候到点的那些，启动时聚合成一条（前 5 条列名 +
  还有几条），聊天里一条 + 托盘一条气泡，然后一次性全标 fired。**不逐条弹**（关了一周再
  打开会变成一场通知风暴，而风暴的结局是用户把通知关掉——那时所有提醒一起失效），
  **也不静默丢**。
* **新登记的提醒立刻改排**：`_on_tool_finished` 见到 `set_reminder` 就调一次
  `reschedule()`。没有这一句，它得等当前这一觉睡满（最长 60 秒）才被看见，而"我刚说了
  三十秒后提醒我"的人不会等满六十秒。

> **多开时 sidecar 无锁**，两条进程会各弹一次同一条提醒。本版接受这个代价，没有做单实例
> 守卫——它是"同一台机器上同时开两个记忆终端"这个不常见前提下的一次重复通知，而不是
> 数据损坏。

#### 任务记忆为什么在设置里，而且默认关

一轮任务合成一条记忆，会**改变库里条目的粒度**：勾上之后，"帮我查一下上周的观测记录"那一轮
在召回时是一整条，而不是用户那句 + 回复那句分开的两条。它对召回是好事（一条任务是一个完整
的语义单元），但它是**用户看得见的入库语义变化**，所以与「模型自分类」同一个姿态：先不替
用户做主，给一个开关，默认关。

判据是 **`turn.tool_trace` 非空**——没调工具的那一轮交给 `PerItemPolicy`，逐字段与今天完全
相同。这一条是硬约束：`TaskPolicy` 是**加法**，不是"有工具的轮次记一条、没有的不记"。
`tests/test_memory_policy.py` 用一个交错断言钉它（同一个 `Turn` 喂给两个策略，逐字段比），
那正是防"排他"偷偷回潮。

> **轨迹是摘录，不是全文。** 单格结果最多 600 字、整条轨迹 8000 字，`result_chars` 记原文
> 长度，所以"被截过"这件事在数据里说得出来，而不是看起来像原文就这么短。上限不是审美：
> `meta` 逐字进 SQLite，而 `memcore` 单条 `meta` 的上限是 256 KiB，超了 `store.add` 抛
> `StoreError`、`MemoryWriter` 不吞——于是一次读 64 KiB 文件的工具调用会把整条记忆变成
> 对话里的一句「记忆写入失败」。全文仍在逐字稿里。

### 金标准集与门槛

`memcore/recall.py` 有九个可调参数，而在 P1.5 之前**没有任何东西能告诉你改了一个参数之后
变好了还是变坏了**。金标准集补上那个缺口：`benchmarks/gold/` 下 200 条虚构的海洋观测站
记忆 + 76 条带 ground truth 的查询，每条查询都跑真正的 `recall()`，落一份逐条账本，再算
四项指标。

**它是量具，不是数据集**，所以它的数字进 CI 当**门槛**——"不恶化即绿"，不是"召回很好"的
声明。语料的冻结纪律、十类难例的构造、以及一份留档的敏感度实测写在
`benchmarks/gold/CORPUS.md` 里。

#### 四项指标的精确口径

记号：查询 $q$ 的期望集 $E_q$、可选集 $O_q$、注入序列 $\mathrm{inj}_q$（顺序 = `recall`
返回顺序 = MMR 选择顺序 = 模型在提示里看到的先后），$\mathrm{topK}_q = \mathrm{inj}_q[:K]$。

- **hit@K** = $\frac{1}{|Q_{ans}|}\sum_q \mathbb{1}[E_q \cap \mathrm{topK}_q \ne \varnothing]$，
  macro，$K \in \{1,3,5,8\}$。分母 $Q_{ans}$ 只收**有答案的**查询——`no_answer` 那类
  （库里确实没有）不进分母：把"我们没有编造"算成一次没命中，是在给自己制造假失败。
- **MRR** = $\frac{1}{|Q_{ans}|}\sum_q \frac{1}{\mathrm{rank}_q}$，未命中**计 0**（不是
  排除）。只对命中者算的那个另报为 `mrr_answered`，**不进门槛**——门槛绑的是把"答不出"
  算进去的那个。
- **误注入率** = $\frac{\sum_q |\mathrm{inj}_q \setminus (E_q \cup O_q)|}{\sum_q |\mathrm{inj}_q|}$，
  **micro**（按注入条数汇总，不是按查询平均）。`optional` 不算错——判它错会把"去冗做得
  好"变成一个负分项。这个口径在槽位填满时会饱和（每条 1 条正确、8 个槽位 → 上限
  0.875），所以它主要响应"注入了多少条"；排得准不准由 hit@K 与 MRR 管，两者互补。
- **AUC** = $\frac{\#\{s_p > s_n\} + \frac12 \#\{s_p = s_n\}}{|P| \cdot |N|}$。正集是
  $E_q$ 各条的 `fused`，负集是库里不属于 $E_q \cup O_q$ 的条，逐查询配对后 pooled，
  并列按 ½ 计。**它因此是上界**：`fused` 只由通道得分与通道权重决定，与 `min_score`、
  `max_items`、`budget`、`mmr_lambda` 全都无关，所以 AUC 描述的是"这个打分函数能不能把
  对的排在错的前面"，在任何阈值下都成立。

四项都取的是**最稳的代表**：per-category 的数字照报，但**不进门槛**——n≈5 时标准误约
0.18，拿它当判据等于每天红一次。

#### 怎么跑

```bash
uv run python tools/bench_recall.py                     # 报告；探测到 Ollama 就用语义通道
uv run python tools/bench_recall.py --no-semantic       # 纯词法，不探测（CI 与 pre-commit 用这条）
uv run python tools/bench_recall.py --no-semantic --check   # 与基线比，跌破容差即退出码 1
uv run python tools/bench_recall.py --no-semantic --json    # 额外一份机器可读报告
```

退出码有含义：**0** = 达标（或只是报告）、**1** = 跌破基线容差（**不是程序出错**，意思是
"召回行为比登记在案的基线差了"）、**2** = 用法或环境不对、**3** = 结构不变量被违反——
那既不是"变差"也不是"没配好"，**是 bug**。

> **门槛只绑词法通道**（`--no-semantic`）。词法 SDR 是 blake2b 哈希编码，不需要模型、
> 不需要网络、不需要 GPU，所以它在 CI 与每次提交里都跑得动；把门槛绑在语义通道上等于让
> "有没有装模型"决定提交能不能过。语义数字仍然会报，它的价值是回答"换一个嵌入模型会不会
> 更好"，那不是一个 CI 判据。
>
> 一个直接的后果，别误读：本机 40 对短句上词法 AUC 已是 0.884，这套语料上是 0.909——
> **离线 AUC 逼近的是词法打分函数自身的天花板，不是系统上界**。本地带 Ollama 跑过一次
> `--semantic` 作对照（数字记在 `CORPUS.md`）：**AUC 从 0.9093 涨到 0.9243，而 hit@8
> 从 0.9559 跌到 0.8971、误注入率从 0.8205 涨到 0.8902**。排序变好而用起来变差，因为
> `min_score` 那个初值是按**词法量纲**标定的，多一条通道就把一批不相关的也抬过了它。这正是
> "本版只报告、不改默认值"的原因：换通道组合要重标阈值，而那要真实库上的数据。

#### 语料是量具，不是文档

改它等于换了一把尺子。四道锁缺一不可，全部写在 `benchmarks/gold/CORPUS.md` 里；这里只
记**改语料时要动的三处**（必须同一次提交）：两份 JSONL → `freeze.json` → 重跑
`--freeze` 更新 `baseline_lexical.json`。少任何一处都会红，而失败消息直接写出还差哪个。

```bash
uv run python tools/bench_recall.py --no-semantic --freeze   # 重算基线（强制重跑，不接受手工输入）
```

**门槛的红不是"程序出错"。** 先分流：语料被改过（sha256 不符）、召回行为真的变了（指标
跌破容差）、还是结构不变量被违反（pinned/cold/excluded 被注入——**那是 bug**，别当"数字
不好看"顺手把容差调宽）。`--check` 会把前两条线索都打出来。

#### 第二把尺子：路由语料

`benchmarks/routes/` 是金标准的**同位体**：那一个把记忆灌进 `:memory:` 库再逐条召回，
这一个把输入逐条喂给路由。区别只在被测对象，纪律一套——语料是**量具不是数据集**，冻结
判据同样是 `sha256(原始字节)`，同一份 denylist（`bench/corpus.py::PERSONAL_DENYLIST`）机械
执行。120 条虚构输入分九类（斜杠 7 / 祈使 24 / 问句 14 / 闲聊 25 / 歧义 12 / 否定 10 /
重复与纯标点 8 / 长任务 12 / 今天还判错的 8），每一条为什么这么构造写在
`benchmarks/routes/CORPUS.md` 里。

```bash
uv run python tools/bench_router.py --no-model            # 只有规则层，不探测（CI / pre-commit 用这条）
uv run python tools/bench_router.py --no-model --check    # 与基线比，跌破容差即退出码 1
uv run python tools/bench_router.py --no-model --freeze   # 重算并覆盖基线
```

**两把尺子，不是一个。** 门槛只绑**规则层**（纯函数、离线、确定性）；**模型自分类照报不
进门槛**——它要 Ollama，把门槛绑上去等于让"这台机器装没装模型、装了哪个"决定提交能不能过
（与召回那边只绑词法通道是同一条纪律）。"该不该把模型自分类打开"正是那份报告要回答的
问题，而它不是一个 CI 判据。

**`accuracy` 与 `coverage` 必须成对看。** 这一层有一档"我不知道"（歧义 → 退回闲聊并反问），
所以：只看准确率，一个把 40% 的输入都推给用户确认的规则层能接近 1.0——那正是最该被看见的
退化；只看覆盖率，一张"什么都判 task"的表能拿满分。报告因此印三个数：`accuracy`（分母是
**敢判的那些**）、`coverage`（敢判的比例）、`accuracy_all`（放回全长度，包含蒙对的）。
再加一个 `majority_baseline`——**它是底线不是成绩**（首次实测 0.6083，说明这份语料闲聊占
多数，任何准确率都要先减掉这层水份）。

**容差 0.02 不是采样噪声。** 这份测量是确定性的（同一份语料跑两遍逐位相同，有一条测试钉住
它），没有任何随机来源，所以按统计学算标准误在这里是错的。0.02 折成条数大约一到两条，取
这么紧是因为**这张表是手写的、每次改都是一个词**——改一个词而弄坏了另一条，正是这个门槛
要抓的那件事。反过来，改善只会把数往上推，任何时候都是绿的。

**「今天还判错的 8 条」进门槛，金标准的近义改写不进。** 分界线不是"难不难"，是**够不够
得着**：那 8 条加一个同义词、挪一条优先级就能修好（不需要模型、不需要网络），所以它们是
**可见的待办清单**，账记在准确率的分母里；近义改写要语义通道，离线腿够不着，只能只报告。

> **首次实测（规则层）**：覆盖 0.7917 / 准确率 0.9684（含"不知道"一起算 0.9333）/ 任务查全
> 0.9524 / 闲聊查全 0.9811。这张表在"敢判的那些"上已经很准，**短板是覆盖率**——25 条亮了
> 歧义，其中 8 条其实是过度谨慎。完整报告、分类别数字与那 8 条判错的清单在 `CORPUS.md`。
> **模型层的数一次都还没有**（要跑 120 次 Ollama），`baseline.json` 里 `model_layer` 是空的，
> 这是有意留白。
>
> **2026-10-12 追记：上面那句"加一个同义词就能修好"兑现了 7/8。** 那 8 条里有 5 条是同一族
> （"去看已经存下来的东西"，被"句末问号 → 闲聊"整族吃掉），补进词表之后 `hard` 类判对
> **7/8**，覆盖 0.7917 → 0.8333、准确率 0.9684 → 0.9900，**其余八类一个数没动**。剩下那条
> `u-0113`（"谢谢你帮我查资料"）是刻意不修的，理由在 `CORPUS.md`。基线与这份追记的差不是
> 漂移——门槛是相对闸门，改善不重新冻结。

### 关联基质量具：图 A 与 W

**P4a 交付的是一个数，不是一次行为变更。** 这一版建出两样东西——关联图 A
（边 = 关联码的 Jaccard，每节点留 top-m 邻居）与神经元级基质 W（``AᵀA`` 的隐含表示，
不物化那张 4096² 的稠密矩阵）——但**没有任何东西把它们接进召回**：
`RecallConfig.graph_weight` 保持 0、`ChannelScores.graph` 保持恒 0、`recall.py` 一个字
没改。理由是 README 上面记着的那次实测否定结果（加语义通道让 AUC 涨了而 hit@8 跌了，
因为 `min_score` 是按词法量纲标定的）：**换通道组合要重标阈值，而那要真实库上的数据。**
所以 P4a 只做一件事：把"这套基质到底值不值得用"量出来。

量具在 `benchmarks/substrate/`（200 条虚构记忆，10 个**词场** × 20 条 + 40 条查询），
四项指标的口径写在 `axo.bench.substrate` 里，`tools/bench_substrate.py` 只报告：

```bash
uv run python tools/bench_substrate.py                        # 默认档，报四个数
uv run python tools/bench_substrate.py --k 32,64,128,256      # 关联码取多少位
uv run python tools/bench_substrate.py --scale 200,2000,20000 # W 的容量悬崖在哪
uv run python tools/bench_substrate.py --assoc weight         # 换一条选位规则
uv run python tools/bench_substrate.py --check                # 与基线比（CI 与 pre-commit 用这条）
```

**进门槛的只有两个数**：`neighbor_auc`（同簇边的权重高于异簇边的概率）与
`completion_top1`（确定性地丢掉一半活跃位之后还认得自己的比例）。它们是基质的**性质**，
全部输入是 blake2b 与 numpy——无随机数、无模型、无 GPU、无网络，所以能在 CI 里跑。
`graph_hit@*` / `mrr` **只报告、不进门槛**：它衡量的是"第三通道该不该上"这个问题，而
P4b 扫完一档之后答案是"默认不上"（见下节）。**答案出来了，门槛照旧不进**——那条记录的
是一条**路径**（换通道组合要重标 `min_score`），不是"够不够好"，冻住它会把将来的标定
变成"不许变坏"。

**实测出来的三件事**（完整留档在 `benchmarks/substrate/CORPUS.md`）：

1. **A 与 W 坐在分叉的两端。** 关联码的选位规则是 `encode_assoc` 的一个参数，两种取法
   各废一半：

   | 选位规则 | 200 条码的并集位 | 两两 Jaccard 均值 | `neighbor_auc` | `completion_top1` |
   |---|---|---|---|---|
   | `hash`（默认，摘要最小） | 552 / 4096 | 0.0988 | **0.7083** ✅ | 0.0250 ❌ |
   | `weight`（权重最高） | 3224 / 4096 | 0.0191 | 0.5287 ❌ | **0.8700** ✅ |

   `hash` 保相似（码挤在 552 维里，词法结构还在 → A 好；但公共分量淹没了 W → 补全死）；
   `weight` 近似正交（码散在 3224 维里 → A 塌；但 W 干净 → 补全活）。**两条规则都是
   纯函数**，所以"A 用一份码、W 用另一份"完全可行。**P4b 只用到 A**，所以这一半自然定了
   （A 用默认的 `hash` 档）；**W 那一半由 P4c 接手，用的正是 `weight` 档**——上面那两句
   在这里原样兑现，见下面「睡眠巩固（P4c）」。一份图、两份码，互不干扰。
2. **W 有容量悬崖，而且它来得比理论还早。** weight 档上 `completion_top1` 随规模的实测：
   n=200 → 0.8700、n=500 → 0.2250、n=1000 → 0.0900、n=2000 → 0.0300。与"经典 Hopfield
   容量 ≈ 0.138·N ≈ 570"的形状一致，拐点还更靠前（本仓的关联码互相相关，相关模式正是
   把吸引子容量压得更低的东西）。**结论：5 万条规模上全局 Hebbian W 的一步补全大概率
   不可靠**，P4c 的吸引子回放要建在别的东西上。这正是 P4a 存在的理由。
3. **第三通道现在没带来东西。** 图上的扩散 `hit@1` 0.8250 **低于**词法基线 0.8500，
   `mrr` 0.8883 也低于 0.9021——沿 A 扩散一步轻微拖后腿。这是 P4a 的合法结论，也正是
   "与词法基线并排报"要防的事（把两个数分开报，"图没带来什么"就会被含糊过去）。

> **两条必须连着报的注意事项。** 其一，`--scale` 放大语料用的是**合成**条目（同簇两条
> 句子拼接），n=20000 上那些数不是"两万条真实记忆"上的数；`--scale` 的分列标题里写着
> 这件事。其二，语料的第一版按**主题**分簇，`neighbor_auc` 在每一档都停在 0.50——参数
> 怎么调都不动。根因不是参数：簇是主题关系，而 `encode_assoc` 只承载**词面**信息。改成
> **词场**簇之后，同一套代码同一套参数：AUC 0.5054 → 0.7083、precision@m 0.2213 →
> 0.6510。**这不是把基准调绿**——被测对象仍是那个 64 位哈希子采样，它确实能把词面信号
> 毁掉（`k=573` 时 AUC 0.7205 / precision@m 0.8207，那是"A 建在词法码上"的上界）。

### 联想通道与邻居面板（P4b）

**P4b 的形状由 P4a 量出来的那个负数决定。** 既然"沿图扩散一步"量出来是拖后腿的，P4b 交付的
就不是"联想通道上线了"，而是三件各自站得住的事：通道**接上了**（可以打开）、打开要付
什么代价**已经量在纸上**、图本身**能看了**。

**通道：接上了，默认关。** `RecallConfig.graph_weight` 的默认值**仍然是 0.0**，所以
出厂行为逐位不变——`graph_weight=0` 时扩散**根本不算**（短路，不是"算了不用"），
`_scan` 的权重 dict 里连 `graph` 这个键都不加。这条是硬约束，有一条测试拿"同一份 config、
一次 `graph=<真图>` 一次 `graph=None`"比对整份账本。

设置页「记忆」里有一个「启用联想通道」勾选框，旁边**先写代价再写好处**：`min_score`
（0.10）是按词法量纲标定的，多一条通道会让它不再对应原来的严格程度。要打开的人应该先去
看 `benchmarks/gold/CORPUS.md` 里「联想腿」那一页——那里有一档扫描，四项指标没有一项变好，
AUC 从 0.9093 掉到 0.8450，`hit@1` 四列全平（联想只抬中后段，从不改榜首）。**为什么大概率
是负的，写在实现里**：图的边来自 `assoc_sdr`，而它是从 `lex_sdr` 派生出来的纯哈希子采样，
所以"联想找到的邻居"与"词法已经找到的东西"同源——加的是同一份证据的第二遍。

`_GRAPH_CHANNEL_WEIGHT = 0.25` 是**未标定的初值**，取的是扫描表里那一档（MRR −0.0037、
AUC −0.0172，比 w=1.00 的 −0.0643 轻得多）。真实库上要取多少，得等将来那一轮**标定**
（它还没排进上面的阶段表）——在那之前**注释里写着不要往上调**。

**界面：局部邻居列表。** 选中一条记忆，下面一栏列出建图那一刻它的前 8 个邻居（按边权
降序），点一条跳过去。**不做全局星图、不引 networkx / matplotlib / QGraphicsView**——
仓里只有 QPainter 自绘的先例，而列表能落在纯层（`memory/browse.py` 的
`association_header` / `neighbor_label`），核心腿就能测。三处判断值得单独记：

* **指向已删除节点的边不静默过滤。** `GraphIndex.neighbors()` 有个 `live=` 参数能把它们
  滤掉，这里**刻意不传**——滤掉之后，"图是旧的、库里删过东西"这件事在界面上完全看不见，
  用户看到的是一份"看起来很正常"的邻居表。改为逐条查一次库，查不到的标「已经不在库里了」、
  不可点，顶栏说出「另有 N 条邻居已被删除，图还没重建」。**图的年纪要说出来，不能靠少显示
  几行来掩盖。**
* **`stale` 是三态，不是布尔。** `True` 确定过期、`False` 刚比对过是最新的、`None`
  **没比对过**（库太大，见下）。`None` 与 `False` 都是假值，但一个说"查过了"、一个说
  "根本没查"，把后者当 `True`/`False` 显示都等于替一份没验过的图打包票。
* **没有数据的地方一个数字都不许出现。** 没图 / 这条不在图里 / 一条邻居都没有，三种
  顶栏文案里连 `0` 都没有——`0 个邻居` 会被读成"算过了、结果是零"，而真实原因可能只是
  边权没过门槛。有数据时才写真数字（边权、记忆权重）。

**建图时机：小库自动 + 大库手动。** 图只在**打开记忆窗口**时自动建（程序启动时无条件建
的话，用不上这个功能的人每次开程序都要等），阈值 `AUTO_GRAPH_MAX = 2000`——按
`graph.py` 的实测表，n=2000 **含编码**是 3.0 s，n=20000 就是 66 s，所以 2000 是"一次全量
重建仍是几秒量级"的最大点（中间档没实测，是外推的）。库比它大时 `GraphWorker` **不遍历、
也不判过期**：`list(iter_items())` 在 5 万条上很占内存，而 `is_stale` 本身是一次全量重编码
（约 63 s）。大库把图当"可能过期但先用着"，由顶栏那句话如实说出来跟你手动兜底。

设置页「记忆」里那个「重建联想」按钮因此**不是可有可无的**：它是大库唯一的兜底。它和自动
那条路共用一个 worker，用 `force` 分开——**手动那条必须真的重建**。少了这个分叉，大库上
点它会原样把旧图还回来（自动那条路的短路条件恰好成立），按钮看起来坏了，还没有任何报错。
同一时刻只跑一趟：两趟会同时写同一个 `graph.npz`，而"哪一趟先落盘"决定盘上最后是哪张图。

> **已知代价**：5 万条手动重建约 4.5 分钟（建图 259 s + 编码 63 s，那是两者之和），而关窗
> 时收尾会等到超时、打印「收尾超时」再放行。**那不是 bug**：建图线程不写库，最坏是白算
> 一次。本版**不做取消**（登记在下面「排障」的最后两行里，没有排给哪个阶段）。

> **这一版有四件事只有人眼能验，测试替不了**（跑一次 `run.bat`，开记忆窗口）：邻居行的
> 排版挤不挤（一到两行之间是设计，三行就是坏了）；大库重建时按钮长时间禁用（几分钟）的
> 观感——它是不是看起来像卡死了；`#memoryNeighbors` 与左边那个条目列表放一起协不协调；
> 以及**在真实库上打开开关之后，`min_score`（0.10）是不是明显松了**——最后这条是
> `_GRAPH_CHANNEL_WEIGHT` 需要标定的直接原因，合成语料答不了它。

**P4b 这一版没做的**（越界就登记，不顺手实现）：按通道组合重标 `min_score`（同属那轮还没
排号的标定）、图 A 的增量更新。这一版当时列的另外三项——SNN 热度面板、W 基质、吸引子
回放——**都已在 P4c 落地**（见下一节），所以从这个清单里去掉，而不是留在原地说"还没做"。
`memory/browse.py` 的 `PROBE_CONFIG` 保持 `graph_weight=0`——探针回答的是"以这条为线索
附近还有谁"，联想浏览走邻居面板那条路。

### 睡眠巩固（P4c）

**它的形状由 P4a 那个负数决定。** 全局 W 一步补全在 n=200 上是 0.8700、n=500 上就塌到
0.2250，所以回放**不是**"全库一个 W 取 top-1"，而是**先按关联图分簇、再在每一簇自己的 W
上问"还认不认得自己"**——容量的作用域从全库缩到簇内。簇上限 `MAX_CLUSTER = 200` 取的是
那条曲线上**唯一还活着的实测点**，不是经典 Hopfield 的 `0.138·N ≈ 570`（本仓的相关码把
悬崖提前了）。

一轮做三件事，**次序本身就是要紧的东西**：

1. **分簇**（`memcore/consolidation.py` 的 `partition`，纯函数）：图的 `edges()` 折成无向
   （同一对边取 `max`，与 `diffuse` 同口径）→ 确定性标签传播 → **对超过上限的组做区域生长
   切分**。第二步不是兜底而是主路径：真实库的最短路 top-m 图几乎必然是一整个巨大分量。
   **全程无随机数**，簇序与簇内序都是规范的——`--replay` 的逐条比对靠它。
2. **回放**：每簇现算 `weight` 档关联码、建一份只装这一簇的 W，对每条做 50% 丢位探针 +
   一步补全。判据是**回放辨认率**，与基质量具的 `completion_top1` **同口径**——丢位算子
   `drop_bits` 从 `bench/substrate.py` 搬进了 `memcore/sdr.py`，理由与 `diffuse` 那次一字
   不差：**让量具与生产用同一个算子**。
3. **改库只做一件事**：`decision == "reinforce"` 的条目 `reinforce_count += 1`（批量一条
   `executemany`）。**不动 `weight`、不更新 `last_access_ts`、不做全库衰减结算**——那三件
   各有各的主人，而 `reinforce_count` 与 `access_count` 分开记，是**独立证据字段**、不是
   权重的输入。v1 也**不做 tier 升降**：那要真实库上的分布作依据，拍一个常量批改全库的
   tier 正是本仓最警惕的"看起来正常的错"。

**事件是每轮一个 JSONL**（`memory/consolidation/<run_id>.jsonl`），一行一条、每行自足、带
`run_seed` 与 `seq`，**`mem.db` 的 schema 一个字节都没改**——事件不是查询对象，是**证据**。
`tools/sleep_once.py --replay <run_id>` 拿同一个 `run_seed` 在同一个库上重跑并**逐条比对**
（`memory_id` / `decision` / `confused_with` / `epoch` 同序相等，`jaccard` 容 `1e-6`，
`at` 不比）。找不到那个 `run_id` 退 **2**，能重跑但序列不一致退 **3**——一轮巩固不可复现就
推翻了这套设计的全部卖点。事件文件**不轮转**（体积小、是证据），只有快照轮转，这个不对称
是刻意的。

**改库之前先拍一份整库快照**（`memory/snapshots/mem-<UTC>.db`，留最近 5 份；按**文件名**
排序轮转而不是 mtime——从备份里拷回来之后每份的 mtime 都是"刚才"，按它排序等于随机删）。
用 SQLite 的**在线备份 API** 而不是 `shutil.copy`：库是 WAL 模式，裸拷 `mem.db` 会漏掉
`-wal` 里未检查点的提交，而漏掉的那部分恰好是**刚刚写进去的记忆**。**空转的一轮不拍**
（一条都没加固，那次修改根本不存在），快照失败就**不改库**——宁可不巩固，也不要一次没
退路的批量改。

**它自己会跑。** `ui/consolidation_scheduler.py` 是一个单发 `QTimer`（**没有抄
`ReminderScheduler` 那个 60 秒上限**：那是为"机器休眠、每 60 秒对一次表"设计的，巩固是
24 小时级的任务，睡晚了只是跑得晚），周期**默认每天一次、默认开**；跨重启的"上次跑过
没有"记在 `memory/consolidation/last.json` 里（它**不是证据**，是给下一次跑用的记录——
坏了只当"不知道"，不算事故，更不会编一个时刻出来）。自动那条路有三道让行，每次都要**先把
表接上**再返回：**已经在跑**（单飞——两轮会重复计数，而且同一个 `at` 秒里起的第二趟会撞上
同一个事件文件名）、**正在生成或装配**（推迟一分钟；这是"用户正忙"的**代理**，不是真
idle 检测，挡不住"用户在别处用这个库"）、**库里的图还没建**（挂起并请一趟建图——图是懒建
的，所以"从没打开过记忆窗口"的人反而是这条路的常客）。

**手动那条路随时可用**：托盘菜单的「立即巩固」，以及设置页「记忆」里那个同名的按钮。它与
自动那条**共用一个 worker、一道单飞守卫、一段收尾**，差别只有两条：**跳过"库里没有新
记忆"那道门**（用户点它就是要跑一趟），以及**回来说不说气泡**——手动弹，自动不弹（否则
每次开机弹一次就是噪音）。反过来，手动也**不排队、不推迟**：已经在跑或正在生成时只回一句
"为什么按不动"。一个按下去没反应的按钮，用户的结论是"它坏了"，然后他会再按一次。

> **登记：自动那趟从此在人前完全无声。** 它跑完之后只有两个落点——记忆界面那句「SNN
> 热度」，以及设置页「记忆」里的状态行；**记忆窗口没开着的时候，一个痕迹也没有**。这是
> 有意的：原来那行会往对话区正中间插一句"认出 4 条 ……（辨认率 28.6%）"，而它每一轮都插。
> 代价是"它到底跑没跑"从一个看得见的事实变成了一个要主动去看的问题——所以手动那趟保留
> 托盘气泡（那是用户自己按的，弹一下不算噪音），而自动那趟不弹（弹了就变成每天一次）。
> 若日后觉得太静，最省事的落点还是托盘，但要有心理准备那就是一天一次的通知。
>
> **失败那趟照旧在对话区说。** 这条不对称是有意的：成功是日常，沉默；失败是"本该发生
> 而没发生"，那正是必须说出口的一类。所以 `_on_consolidation_failed` 一个字没动。

> **这是本版唯一一处"无人值守的批量改库"，三道保险都要说清**：① 快照在最前；② 每簇是一次
> 「改库 + 追加事件」，崩在中途留下的是 `seq` 连续的前缀；③ WAL 保证每个 `UPDATE` 要么整体
> 落盘要么整体回滚，不会留下半截事务。**关窗不会打断它**（本仓关窗只隐藏不退出），只有托盘
> 退出 / Ctrl+Q 才走 `_shutdown`，那时 `wait_for_all` 等 3 秒，超时就打印「收尾超时」放行。
> **第一次看到那行字会吓一跳，它不是 bug。** 本版**不做取消与进度**，与 `GraphWorker` 同一
> 姿态。

**它认得出来多少，量在纸上——而这一次的结论是"没有结论"。** `tools/bench_consolidation.py`
读**同一份**基质语料（不新造语料、不新冻 `freeze`），把「全局 W(hash) / 全局 W(weight) /
分簇局部 W(weight)」三列并排报出来：n=200 上分簇那一档 0.9000 高于全局的 0.8700，串扰
J 中位 0.1480 是真串扰；但 n≥500 上它仍随规模掉，而掉的原因是**那份语料自己的近重复**
（认错 J 中位 → 1.0000，89.6% 的认错都在 0.9 以上）。**这份语料分不开"分簇解决了容量"与
"合成重复压住了辨认率"**，所以这里既没有"分簇赢了"、也没有"分簇没用"。完整读数、限度与
它为什么不进门槛写在 `benchmarks/substrate/CORPUS.md` 的「分簇 + 局部 W」那一节——
**不进门槛的理由是"只有默认路径进门槛"，而巩固没有默认路径**（它不参与召回），
`baseline.json` 一个字没动。

> **两条登记在案、没有在这里假装已经裁决的占位**：周期 86400 秒**没有实测依据**（一轮只
> 处理一两个簇，工作量与周期无关，与周期挂钩的只有快照频率和磁盘占用）；`MAX_CLUSTER = 200`
> 取自**合成**语料，真实库上最优的簇规模要拿 `reinforce_count` 的分布回头标定。

> **这一版有三件事只有人眼能验**（跑一次 `run.bat`，要么等它自己到点，要么直接按
> 「立即巩固」）：真库上跑完一轮之后「SNN 热度」那句话**读不读得通**；手动那一次弹的托盘
> 气泡在真实使用里**烦不烦人**（自动那趟不弹也不写对话区，所以这条只对手动那趟有意义）；
> 以及**每天一次这个周期在真实节奏下是偏密还是偏疏**——最后这条正是"86400 是占位、没有
> 实测依据"的直接原因。不点界面也能确认这条路算得
> 通的是 `tools/sleep_once.py --dry-run`（跑完整轮、一个字都不写；**没有图它会明说并退 2**
> ——图是懒建的，打开一次记忆窗口就会建），它列在下面「出问题时先跑哪个脚本」里。

### 云端后端（OpenAI 兼容）

后端页有两组，二选一：**本机 Ollama**（默认），或者**云端 OpenAI 兼容端点**。第二组要填
两样——服务地址（默认 `https://api.deepseek.com/v1`）与 API key。切过去之后本机组会整个
收起来，本机地址与「允许远程主机」那两件跟着一起消失：云端没有"只连本机"这回事。

**key 怎么存的。** 走 Windows 的 DPAPI（`ctypes` 调 `CryptProtectData`），**按「当前用户 +
这台机器」加密**，盘上留的是 base64 密文。于是：

* 把设置文件拷到另一台机器、或者换一个 Windows 账户打开，**都解不开**——那时按"没配过"
  处理（回一句"没配 key"），不崩，也不会拿一个解不开的字符串去发请求。
* 因此换机器要重填一次。这是这个方案的**代价，也是它被选中的理由**：不引入任何第三方
  依赖，key 也就不经过一个我们控制不了的库。
* 非 Windows、或 DPAPI 调用失败时走"存不下"的分支，**不静默落明文**。

**对话走云端，嵌入仍走本机 Ollama。** 这不是配置项，是前提——多数云端厂商根本没有嵌入
端点，而记忆的召回、回填、探针整条路都靠向量。两个后果：

* 云端模式下**本机仍然要有一个嵌入模型**（`ollama pull nomic-embed-text`），嵌入清单也
  仍然问 Ollama 要，与对话用哪家无关。所以主窗口在云端下会**起两趟**：一趟问云端要对话
  模型（灌下拉框），一趟问本机 Ollama 要嵌入模型（喂记忆装配）。**少掉第二趟的症状是语义
  召回静默退化成纯词法**——不报错，只是记性变差。所以那一趟有专门的守卫
  （`tests/test_ui_cloud_wire.py` 里那条"云端下嵌入模型仍然来自 Ollama"）。
* 本机 Ollama 没在跑时，记忆只说一句"没有可用的嵌入模型（…），记忆只用语汇匹配"，
  **对话照常**。云端模式下这两件事是分开的，不会再出现"Ollama 挂了所以整个终端不能用"。

**会发出去什么。** 这一轮的对话，**以及被召回注入的那几条记忆**——`AssemblyWorker` 把它们
拼进 prompt，它跟对话一起出去。记忆库本身、嵌入向量、逐字稿仍只在本机。设置页把后端类型
切到云端时，这句话就摆在 API key 输入框下面，**措辞里点名了"记忆"**：只说"对话内容"是
不完整的。

**地址得过一道门。** 与"只连本机"那道门方向相反——这道门防的是"key 会发给谁"：`https`
随便用，**`http` 只允许本机**，其余一律拒。地址不可信时后端不会被建出来，状态栏照常说
为什么。

**模型清单以服务端为准。** `/models` 返回什么就用什么，对方报了 `context_window` 就直接
用它（不再让后端自己去问一趟——那会是一次 UI 线程上的网络往返）。`/models` 拉不到时**不
静默兜底**：照常报错，同时往下拉框里灌两个预设名（`deepseek-chat` / `deepseek-reasoner`），
让人离线也能先选一个，并且看得见原因。清单是**按名字排序**的，所以第一次切过去时下拉框
替你选的是 `deepseek-chat`（服务端有的话），不是名字排第一的那个——一个云端账户上几十上百
个模型是常态，认第一条等于随便挑一个。

**没做的**（登记，不顺手实现）：嵌入端点、多 provider 并存或一键切换、按 provider 分开的
工具集、OpenAI 那套接口里函数调用以外的任何东西。

### Live2D 接入（P6b）：只登记接缝，不实现

**这一版一行实现都没写**，因为缺的是**第三方授权物**：Cubism 的 Web 运行时与一个模型
目录，两个都进不了本仓。缺料时能做的、也是这一版做了的，是**把接缝定死并登记下来**，
好让物料到位时只是往一个文件里填实现。

**接缝在哪。** `ui/web/js/live2d.js` 暴露 `window.Live2DHost`，形状是四个方法加一个只读
属性：`loaded`、`load(modelPath)` → `Promise<boolean>`、`setExpression(name)`、
`setMouthOpen(value)`（0 闭 1 全开）、`setLookAt(x, y)`（-1..1 归一化）。语义里最要紧的
一条是 **`load()` 失败不抛异常**——一个装饰性的看板娘加载不出来，不该让整个对话窗口崩掉；
`load` 返回 false 时其余方法全是空操作。

**唯一一条活接线**在 `ui/web/js/app.js` 的 `pushToken`：每收到一段流式 token 就把
`setMouthOpen(0.85)`，90 毫秒后回到 `0.1`。这是"模型说话时嘴在动"的**唯一来源**——接入
之后不需要再动别处。

**容器已经摆好**：`ui/web/css/app.css` 的 `#live2d-host`，右下 240×320、`z-index:2`
（在壁纸与蒙层之上、在所有对话 chrome 之下），且**默认 `pointer-events: none`**——
没接入时不挡点击，`.active` 才收回来。

**两个必须在物料到位前想清楚的问题**，都不是"接线"能解决的：

1. **CSP 怎么过。** `index.html` 那条 CSP 是 `script-src 'self' qrc:`，运行时脚本放在
   web 根下（同源）就能跑；但**模型数据归 `connect-src 'self'` 管**，而 `'self'` 在
   `file://` 源上匹不匹配是已知的薄弱点——**要在目标 QtWebEngine 版本上实测**，不能推。
   （贴图若由 `Image()` 载入，走的是已经放行的 `img-src 'self' data: file:`，那是另一条
   规则，别把两者混着看。）测不过就得换壁纸那条路：`QUrl.fromLocalFile` 注入绝对
   `file://`，甚至内联 base64。
2. **模型放哪。** 壁纸已经有一条现成范式——**文件拷进数据目录、库里只存文件名、
   取用时只取 basename**（防目录穿越）；而 `live2d.js` 头注释预留的是"相对 web 根 +
   `window.BASE`"。两条路选一条，选壁纸那条与既有做法更一致，但要**改 `live2d.js` 的
   路径假设**，不是改 Python 侧。

**GPU 那一条已经安排好了**（见 `ui/app.py`）：**默认不动 GPU 标志**，正是为了 Live2D 的
硬件加速；`--disable-gpu` 只在设了 `AXO_SOFTWARE_RENDER` 时才加。所以接入时
**不要**为了"保险"给它补一个 `--disable-gpu`，那会把要用的东西先废掉。

**没有"从 CDN 拉"这条退路**：`chat_view.py` 关掉了 `LocalContentCanAccessRemoteUrls`，
运行时与模型都必须是本地文件。这条与"记忆不出设备"是同一个姿态。

### 跑测试与 CI

```bash
ci.bat                                # 本地跑一遍（七条腿，Windows）
uv run python tools/ci_local.py       # 同上，跨平台入口；--fast 跳过三条门槛腿
uv run pytest -p no:pytest-qt --ignore-glob='tests/test_ui_*'   # 只要核心腿
uv run pytest -m gui                 # 只要 gui 腿（**不要**加 -p no:pytest-qt）
```

`ci.bat` 与 `.github/workflows/ci.yml` 的六个 job 一一对应：`lint`（ruff check +
format）、`test`（核心腿，Python 3.10 与 3.12）、`goldset`（金标准 `--check`，报告传
artifact）、`router`（路由 `--check`，同样传报告）、`substrate`（基质 `--check`，同样传
报告）、`package`（构建 wheel → 干净 venv 装一遍 → 断言里面**没有** PySide6）。命令只有
一份，写在 `tools/ci_local.py` 里，`.bat` 只是它的一层壳——两边各抄一份的话，CI 改了个
参数而本地没跟上，症状是"本地全绿、推上去红"。

**本地比 CI 多一条 gui 腿**（`ci_local.py` 的第四条，标着「本地独有」）：CI 的 `test`
job 排除 `tests/test_ui_*`，而那两百多条里有两条守卫守的是本仓踩过的坑（接线、`0xC0000409`）。
在这条腿存在之前，它们跑与不跑取决于有没有人记得手敲 `pytest -m gui`。它**进不了**
`--fast`——`--fast` 的用途恰是"只改了界面"。它只证明**本机**全过，不证明 CI 机器上会过。

> **三条门槛腿的退出码有含义**（`bench_recall.py` / `bench_router.py` /
> `bench_substrate.py` 共用一套）：**1** = 跌破基线容差、**2** = 用法或环境不对、
> **3** = 结构不变量被违反。**3 是 bug**，不是"数字不好看"——别顺手把容差调宽。
> 前两条带 `--no-semantic` / `--no-model`：让"这台机器装没装模型"决定提交能不能过是
> 不可接受的；基质那条**不需要开关**，它的全部输入是 blake2b 与 numpy。
>
> **巩固那两条命令行只用 0 / 2 / 3，没有 1。** `bench_consolidation.py` 只报告（0）或
> 报用法/环境不对（2）——它不进门槛，见「睡眠巩固（P4c）」那一节；`sleep_once.py` 多一个
> **3**（重放对不上）。**1 在本仓的含义是"跌破基线容差"**，而巩固没有基线可跌，所以它不
> 产生这个码，将来有了默认路径再说。
>
> 「找不到语料文件 / 基线文件 / `--config` 指的文件」也走 **2**。这条是 2026-10-10 补的：
> 在那之前两个脚本都让它冒到顶层，退的是 **1**——于是"工作目录不对"这类**环境**问题在 CI
> 上伪装成了一条门槛失败，而 1 的含义是"行为确实变了，去看看是不是有意改的"。这句谎话
> 会让人去查一个根本没跑起来的基准。

> **`-p no:pytest-qt` 是核心腿的一部分，不是可选的优化。** 排除 `test_ui_*` 只是不
> **选**那些文件；pytest-qt 的 `pytest_configure` 在**收集之前**就把 QtGui 导入了，而
> 它在环境里（dev 组带 PySide6）。无头 Linux 上这条腿因此一个测试都跑不到：
>
> ```
> INTERNALERROR> ImportError: libEGL.so.1: cannot open shared object file
> ```
>
> 退出码 3，报错里没有一个字提到 Qt 或 gui 测试——**CI 第一次跑就是死在这里**，而本机
> （有显示器的 Windows）完全复现不出来。给 runner 装 `libEGL` 也能"修好"，但那是为了
> 让一个**用不到的插件**能 import 而给 CI 装图形栈，与"核心腿不该需要 Qt"正相反。
> 三个地方都带着它：`.github/workflows/ci.yml`、`tools/ci_local.py`、pre-commit 的
> `memcore-layering`。gui 腿那一条不要加——加了是 `fixture 'qtbot' not found`。
>
> 代价是核心腿末尾挂一行 `1575 passed, 1 warning`，那条警告是
> `Unknown config option: qt_api`（插件没加载，所以它注册的 ini 键没人认领）。无害，
> **别顺手加 `--strict-config` 把它变成错误**——那会让几条腿一起红，理由写在
> `pyproject.toml` 那段注释里。

> **`ci.bat` 与 `run.bat` 必须是 CRLF。** 这不是风格问题：cmd.exe 解析 LF-only 的批处理
> 时会算错行偏移，把半行当命令执行（`'rt' is not recognized`、`) was unexpected at this
> time`），然后以 255 退出。纯 ASCII 的 LF 批处理碰巧能跑，有中文就必然错位——所以
> `run.bat` 曾经是坏的。守它的是 `.gitattributes` 的 `*.bat text eol=crlf`、
> pre-commit 里 `mixed-line-ending` 的 `exclude`，以及
> `tests/test_entry_points.py`（**别在编辑器里把它"修"成 LF**）。
>
> 顺带一条：**改 `.gitattributes` 不会回头重写工作区里已有的文件**，它只管下一次检出的
> 那一刻。属性改对之后 `git status` 反而是干净的（git 入库时按同一套规则归一化，工作区
> 的 LF 与库里的 LF 相符），而那个文件仍然是坏的。修法是让 git 重写一遍：
> `rm run.bat && git checkout -- run.bat`。

核心腿 **1575** 条、gui 腿 **368** 条，合计 1943。新增测试会让这三个数字变化；数条数用
`--collect-only -q` 加一段求和（摘要行被 `addopts="-q"` 压掉了）：

```bash
uv run pytest --collect-only -q | awk -F': ' '/^tests\/.*: [0-9]+$/ {s+=$2} END {print s}'
```

两条腿分的是**"能不能不碰 Qt 就验完"**，不是"重要不重要"：

| 腿 | 测什么 | 为什么在这儿 |
|---|---|---|
| **核心腿** | 记忆与召回、装配与预算、逐字稿 schema、**工具注册表与沙箱**、**agent 循环与闸门**、**路由的每一条判定**、三份基准 | 这些模块**一行 Qt 都没有**，所以能跑得快、跑得稳、在没有图形栈的机器上也能跑 |
| **gui 腿** | 确认卡片出现在对话流里、点了允许/拒绝的去向、**等待确认期间点停止**、**收尾落在卡着等确认的 worker 上时进程退出码是 0**、`tools=()` 时 `AgentWorker` 与 `ChatWorker` 产出同一段文本、**语域路由真的接进了对话回合**（`test_ui_router_wire.py`）、**顶栏状态文字真的拿得到宽度**（`test_ui_elided_label.py`，见下）、**被拒绝的工具行回看时不把写给模型的文案渲染给用户**（`test_ui_tool_rows_display.py`）、**关窗的两支与托盘的菜单**（`test_ui_close_to_tray.py` / `test_ui_tray.py`）、**提醒到点真的会响**（`test_ui_reminder_scheduler.py`）、**联想开关与图真的从设置页走到了召回配置**（`test_ui_graph_chain.py`） | 只验**接线**。gui 测试一律不构造真的 `MainWindow`。**CI 排除了它**（无头 Linux 上不装 Qt），但 `tools/ci_local.py` 会跑它——本地跑一次就带上，不必手敲，`--fast` 也跳不过 |

**`tools` 非空才走 `AgentWorker`，为空仍走 `ChatWorker`**，所以两条消费路径短期并存。
缓解是一条平价测试（上面表里最后一行），而**移除准则写在那条测试自己的 docstring 里**：
平价测试一过就把 `tools=()` 也并进 agent 循环、删掉 `ChatWorker`。本版**不合并**——合并不
带来新能力，却要碰已经稳定的生成路径。

**反空转四条必须一起钉。** 只断言"最终有文本"的话，一个**从不执行工具的循环**也能过。
所以 `tests/test_agent_loop.py` 里同一个测试同时钉四件事：spy 工具被调用**恰好 1 次**
（`== 1`，不是 `>= 1`）、第 2 次请求的 `messages` 里**含那条工具结果的正文**、第 1 次请求的
`tools` **非空且条数 == 注册表条数**、`backend.stream` 被调用 **≥ 2 次**。再配一条"守卫的
守卫"（`test_registry_never_silently_drops` 断言登记的工具数等于 `specs()` 的条数），防某个
工具因 `spec` 空或名字空被静默漏掉。

三份语料各有自己的守门测试，形制一致：`test_goldset_integrity.py` /
`test_router_corpus_integrity.py` / `test_substrate_corpus_integrity.py` 管**语料本身**
（指纹、自洽、无个人信息、类别不能空转），`test_recall_gate.py` / `test_router_gate.py` /
`test_substrate_gate.py` 管**门槛**（结构不变量、可复现、与基线比）。基质那份多两条这一层
特有的：簇名必须在**记忆侧**存在（否则同簇对永远为空，AUC 会以"分母为零"的方式假绿），
以及每条查询的 `expect` **不许写满整簇**（写满就等于把答案抄给了排名）。

**顶栏那句状态文字曾经从来没显示过，而三条老守卫全是绿的。** `ElidedLabel` 用
`QSizePolicy.Ignored`，而 `IgnoreFlag` 让布局把 `sizeHint` 与 `minimumSizeHint` **一起**
无视，于是标签宽度参与分配时是 **0**——`text()` 有内容、tooltip 有内容、`paintEvent` 拿 0
去算省略号得到空串（"● Ollama 就绪 · 4 个对话模型"实测宽度 0、画出 `''`）。老测试全是
**拿孤零零一个标签**量的，而那个标签自己的 `sizeHint`/`minimumSizeHint` 一直都对，所以
问不到"布局实际给了多少"。修法是策略改成 `Preferred`（实测 1900px 宽时给 252px 全显、
1100px 时省略、窗口最小宽度只多 12 像素），守卫改成**拿真顶栏量**：
`test_the_status_label_actually_gets_room_in_the_real_header` 建一个普通 `QWidget` 当
`self` 调 `MainWindow._build_header`，断言布局给它的宽度大于 0。**这条守卫拿旧策略验过红**
（`assert 0 > 0`），没验红的守卫等于没写。

### 出问题时先跑哪个脚本

界面出问题的第一个问题永远是"哪一段坏了"。下面几个脚本一人管一段，都不需要
点界面，所以可以逐个排除：

```bash
uv run --extra app --extra llm python tools/_smoke_window.py    # 窗口+接线+模型清单（必须有显示器）
uv run --extra app --extra llm python tools/smoke_backend.py    # Python → Ollama
uv run --extra app --extra llm python tools/_smoke_e2e.py       # 提交 → 流式 → 落盘
uv run --extra app --extra llm python tools/_smoke_recall.py    # 记住 → 重启 → 想起来（P1 验收）
uv run --extra app --extra llm python tools/_smoke_memory.py    # 记忆界面八步（P2 + 人设验收）
uv run --extra app --extra llm python tools/smoke_agent.py      # 模型会不会真的吐工具调用（P3a 探针）
uv run --extra app python tools/_smoke_webview.py               # Python → 网页渲染（必须有显示器）
uv run python tools/sleep_once.py --dry-run                     # 巩固这条路算不算得通（不写库、不拍快照）
```

`smoke_backend.py` 不显式传模型名时**挑第一个能对话的**（`pick_chat_model`），而不是取列表
队首。理由是个具体的坑：`/api/tags` 的返回值**按名字排序**，队首正是 `nomic-embed-text`
——一个不能对话的嵌入模型。拿它去发 `/api/chat`，报回来的错与这个脚本要验的东西毫无关系，
而根因是"选择列表本身就不该从这里取"。全是嵌入模型时它直说并退 1，**不拿嵌入模型凑数**。

`smoke_agent.py` 是 P3a 的 **Step 0 探针**，也是本版唯一"整个方向都压在它上面"的那条假设
的验证：本地模型到底会不会吐出格式良好的 `tool_calls`。它**不设确认闸门**（改状态的工具
直接执行，只打印一行"真跑起来这里会问一次"）——它量的是模型的这一侧，闸门与跨线程握手是
另一件事。**结论写在它自己的模块 docstring 里，是 P3a 三处设计的依据**，也是
`max_rounds`、工具声明 token 开销的标定来源：那个 4B 模型在单工具选择上 13/13 全对、负
对照从不误调，但在"先查再写"的多步任务上**五轮只对一轮**，而失败的主形态是**声称做了却
没做**。这正是"界面显示真实轨迹、绝不转述自述"与"模型自分类默认关"两条的来处。`--dump`
能把真实字节冻成测试夹具（已经冻了一份，见 `tests/fixtures/ollama_tool_calls.json`）。

> **它现在退出码是 1，而且是预期的**——`return 1 if failed` 里的那条"多步·先查再写"至今
> 没通过，那正是它要留下的记录。**别把 1 读成"脚本坏了"**，也别为了让它是 0 而把那条用例
> 删掉：那是把这个探针变成一次自我祝贺。

`_smoke_recall.py` 的 `both` 模式**真的另起两个进程**——同进程里重新 open 一次库
证明不了"重启之后还在"。它的退出码就是验收结论，别只看最后那行字。

`_smoke_memory.py` 走的是「点按钮 → 建窗口 → 编辑 → 遗忘 → 恢复 → 探针 → 删除 →
首启人设卡片 → 关窗收尾」八步，**不需要 Ollama**（记忆界面不依赖模型，没有模型恰好是
必须验的降级路径）。它覆盖的正是 gui 单元测试碰不到的那一段：那些测试一律不构造真的
`MainWindow`（它一连 Ollama、起好几个线程、加载 WebEngine），所以主窗口与记忆窗口之间
的接线只能在这个脚本里验。第七步（人设）还有一层意义——**"`_wire` 里忘了接
`persona_answered`"这种漏法在别处看不出来**：卡片答完了、库却没变，界面上只表现为
一张不肯消失的卡片。它跑起来要几秒，最后一行是结论。

**退出码要在子进程里量。** 异常退出的那一段发生在解释器收尾，同进程里没有别的办法
观测；所以上面几个脚本每个都是真进程，`$LASTEXITCODE`（PowerShell）/ `$?`（bash）
是真的。别把它们串成一条 `&&` 链——前一个非零会静默跳过后面几个，看起来像"全过"。

**哪些能在离屏下跑，取决于它建不建真的网页。** `_smoke_e2e.py` 与 `_smoke_memory.py`
把对话区换成了替身（正是为了绕开下面这条），所以**加 `QT_QPA_PLATFORM=offscreen` 没问
题**，无显示器的环境里也能跑。相对的，`_smoke_window.py` 与 `_smoke_webview.py`
**必须有显示器**：前者构造真的 `MainWindow`（里面就有 QWebEngineView），后者要读渲染
结果。**别在离屏下跑真正的渲染路径**——本机实测，离屏模式下第一次 `runJavaScript` 会
让整个进程被硬杀，连异常都没有、连退出码都没有，看起来就像"脚本什么都没干"。网页侧
的承诺因此由 `_smoke_webview.py` 单独负责，而 Python 侧由那两个用替身的脚本负责。
加 `AXO_SOFTWARE_RENDER=1` 可去掉离屏 GPU 的刷屏报错。

`_smoke_webview.py` 现在依次打四段：正文渲染（含 `<script>` 与 `javascript:` 链接是否
被挡住）、外观（读回 `--accent`、`data-theme`、`has-wallpaper`、`#wallpaper` 的
`backgroundImage`、遮罩不透明度）、空状态（`clear()` 之后 `#empty` 是否回来）、人设卡片
（`setPersonaState` 的显隐与 `#empty` 互斥、正等人设时 `#input`/`#send` 的 `disabled`
读得回来、以及点两个按钮走一遍 **JS → Python** 那条半程）。第二段是**外观那版**唯一一处
"猜错了就得回改设计"的检查：**壁纸住在数据目录、不在 web 根下**，能不能画出来取决于
`LocalContentCanAccessFileUrls` 在本机 QtWebEngine 上放不放行——万一不放，传输方式要
改成带体积上限的 base64。它刻意造一张放在**系统临时目录**的图来验这件事；图放在 web
根下的话，那个设置项坏了它照样画得出来，这条检查就空转了。

第四段里的 JS → Python 半程也是**只有这里能验**：QWebChannel 找不到槽位时是**静默
丢弃**，两侧名字对不上（比如 JS 里写 `answerPersona`）不报任何错，只表现为"点了没
反应"。所以脚本末尾把 Python 收到的答案按顺序打出来，对照下一条期望行看。

### 排障

| 症状 | 原因与处理 |
|---|---|
| 顶栏红字「后端不可用」 | Ollama 没起来。跑 `ollama serve`，然后点顶栏的 ⟳ |
| 下拉框是空的但状态是绿的 | Ollama 在跑但一个模型都没有。`ollama pull <模型名>` |
| 云端后端报 `401`，或说密钥无效 | key 没填、填错，或者**这份设置是从别的机器 / 别的 Windows 账户搬过来的**——DPAPI 按「当前用户 + 这台机器」加密，那边解不开，于是按"没配过"处理。重新填一次就好，这是加密方案的代价 |
| 云端后端报 `429` | 对方在限流（免费档常见），或者余额用完了。与本地那份设置无关——key 与地址都对也会这样 |
| 切到云端后模型下拉是空的 | `/models` 拉不到（key 不对是 401，地址写错是 404，网络不通是超时）。框里那两个 `deepseek-*` 是**兜底预设**、不是从服务端读来的，所以能先选一个用；按状态栏那句话修好之后点顶栏 ⟳ 换成真的清单 |
| 云端下能聊天，但记忆说"只用语汇匹配" | **本机 Ollama 没在跑，或者里面没有嵌入模型。** 云端模式下嵌入仍然走本机（多数云端厂商没有嵌入端点）。`ollama serve` + `ollama pull nomic-embed-text`，重开一次或点 ⟳。注意这条**不影响对话**——两件事在云端模式下是分开的 |
| 窗口空白、没有任何内容 | 显卡驱动让 QtWebEngine 的 GPU 进程崩了。设环境变量 `AXO_SOFTWARE_RENDER=1` 再启动 |
| 中文显示成方块 | 系统缺中文字体。本项目的 CSS 首选 Microsoft YaHei UI |
| 首次提问等半分钟才出字 | 正常，模型正在从硬盘加载进显存（4B-Q4 冷启约 35 s）。加载完就常驻，第二次提问首字约 2 s |
| 想不起来 | 看右侧账本，别猜。它分得清三种情况：**语义通道没接上**（去装嵌入模型）、**分数不够**（去调阈值）、**库里确实没有**——三者的处理完全不同 |
| 记忆窗口里看不到刚说的那条 | 列表在打开时载入一次，**不自动跟随**。点「刷新」 |
| 记忆窗口里那条显示「没有语义向量」 | 正常，多半是刚编辑过。编辑是纯本地的，向量交回填管线下一轮补上（见上面「记忆界面」） |
| 「遗忘」按钮点不动 | 它是**钉住**的条目。钉住的条目不走召回，软遗忘对它是个空动作，所以置灰；要让它消失请看 tooltip 里说的彻底删除 |
| 记忆窗口里「本轮归因」说不在账本里 | 两种可能，界面给不出唯一结论：这条**钉住了**（recall 在扫描前就跳过），或它属于**本会话**（被 `exclude_ids` 排除）。都不是错误 |
| 一启动就看见人设卡片 | 库里还没有你写的那条人设——全新的库，或者你把那条删了。这是**设计如此**，见「首次运行：定一次人设」 |
| 输入框点不动、发送键是灰的 | 同一件事的另一半：卡片正等着回答。答完（写了或点「这一次先不写」）就解锁 |
| 选了「先不写」，下次启动又问一次 | **有意的**，见那一节的最后一段：不写就等于没做这个决定。永久不问就写下任意一句 |
| 记忆窗口里人设那条改不动、也删不掉 | 那是**内置**那条，tooltip 里写着理由。要改说话方式去「设置 → 人设」改你自己写的那条；内置那条改不了也删不掉，是"任何模型读到的身份完全一样"的代价 |
| 退出码非零（`0xC0000409` 或 `3`） | 见下面的「退出码怎么读」。别按 QtWebEngine 查，它通常是无辜的 |
| 换过一个地址后某项功能说连不上、别的却好好的 | 十有八九是 `allow_remote` 没传到那一个构造点。非本机地址**必须**在五处都带上它：模型列表、记忆同步、对话后端、嵌入后端（由前者构造）、连接测试 |
| 勾了「允许远程主机」还是连不上 | 勾选框只解除**本程序**的护栏，不负责网络。先用「测试连接」看返回的是 `Connection refused`（服务没起）、超时（防火墙）还是 404（地址写成了 `/v1`） |
| 壁纸没出来 | 看图是不是被删了——文件不在时设置里的名字**刻意留着**（数据目录搬回来壁纸就自己恢复）。换过盘符/搬过数据目录是常见原因；壁纸按文件名从 `wallpapers/` 取，不记绝对路径 |
| 换壁纸后旧的那张还在磁盘上 | 正常，直到设置窗口关闭才清。按内容哈希命名是**「撤销修改」的前提**：覆盖着写的话，撤销之后那个名字指向一个已经不存在的文件 |
| 浅色模式下主色与我选的不一样 | 预设各带一支手挑的浅色值，自定义色会按对比度下限现算。设置窗口里写着「你选的是 `#xxxxxx`」——**刻意不悄悄换掉**，也不改用户存的色 |
| 控件看起来不像 Windows 原生的 | 外观那版起 `QApplication.setStyle("Fusion")`。这是**刻意的**：Windows 原生样式会忽略相当一部分 QSS 规则，出现"颜色改了但控件还是系统灰"。想回到原生观感就删掉 `ui/app.py` 里那一行（主题会跟着退化成半套） |
| 顶栏状态文字变成 `…` | 那是**省略**不是截断：把鼠标停上去有全文。加了「设置」之后顶栏有 5 个按钮 + 模型下拉，状态文字必须可压缩 |
| 双击 `run.bat` 没反应，或只打印一串 `'xxx' is not recognized` | 行尾被改成了 LF。cmd.exe 解析 LF 批处理时会错位，把半行当命令执行，然后以 255 退出——**看起来像"双击了但什么都没发生"**。见上面「跑测试与 CI」里那段：`.bat` 必须是 CRLF，`tests/test_entry_points.py` 就是拦这个的 |
| `bench_recall` 说连不上 Ollama | **正常状态，不是降级。** 语义通道是可选的，没有它就只有词法通道（`recall.py:168-171`）。CI 与 pre-commit 一律用 `--no-semantic` |
| 金标准门槛红了 | 先分流，别急着改容差：**语料 sha256 不符** = 有人改了题（那要在同一次提交里更新 `freeze.json` 并重跑 `--freeze`）；**指标跌破容差** = 召回行为真的变了；**结构断言红**（退出码 3）= pinned / cold / excluded 被注入，**那是 bug，不是标定问题**。`--check` 会把前两条线索都打出来 |
| 模型说「已记住」但记忆库里没有那条 | **先看工具轨迹，别信那句话。** 本机实测的主形态正是"声称做了却没做"（`write_memory` 一次都没被调用）。工具行是唯一的事实来源 |
| 该用工具的时候它只聊天 | 这一轮被判成了聊语域。用 `/task 正文` 强制一轮试试：能调说明是路由判偏（那要去补词表），不能调才是工具这一侧的问题 |
| 确认卡片迟迟不出现、整轮像卡住 | **设计如此**：整轮被这张卡片挡着（默认 180 s）。卡片上有倒计时和一个「跳过」= 立刻拒绝。人走开了由计时器兜底，按**拒绝**收场 |
| 点了「允许」却没落库 | 卡片的 `call_id` 与当前待决请求比对不上（比如期间点过停止）时会被丢弃并**标记为已失效**。看卡片上的状态，别重复点 |
| `read_file` 说「未配置可读目录」 | 去「设置 → 工具」加一条。**空 = 那个工具被禁用**，默认既不是当前目录也不是家目录（最小权限） |
| 路由门槛红了 | 与金标准同一条纪律，先分流（语料 sha256 / 指标跌破 / 退出码 3 = bug）。补一句这一层特有的：规则层是**一张手写词表**，改一个词能同时弄坏另一条——那正是这个门槛要抓的。`hard` 那 8 条判错的清单在 `benchmarks/routes/CORPUS.md` |
| 基质门槛红了 | 同样三档分流。这一层特有的：**它守的东西最容易被间接触坏**——量具的输入是 `encode_assoc` 的 `ASSOC_K` 与 `person` 前缀、以及建图的 `top_m` / `min_weight`，动其中任何一个都会让 `neighbor_auc` 或 `completion_top1` 变，而动手的人往往以为自己在改别处（所以它也在 pre-commit 里）。另外别拿 `--scale` 那一列去比 `baseline.json`：前者是**合成语料**、用来把容量悬崖看出来，后者是 `benchmarks/substrate/` 实测档冻下来的基线——**两把尺子** |
| 关掉窗口但任务管理器里进程还在 | **设计如此**：窗口收进了系统托盘（右键图标 →「退出」，或 Ctrl+Q）。第一次收起来时会弹一条气泡说明 |
| 通知区域里找不到托盘图标 | Windows 默认把新图标折进「隐藏的图标」里（点任务栏那个 `^`）。托盘**真的不可用**时（极少数精简版系统）程序会退回"关窗即退出"，不会出现"关不掉也找不到"的状态 |
| 设了提醒却没响 | 三个地方依次看：**程序当时开着吗**（关窗收进托盘仍然算开着，真退出就不算了，错过的会在下次启动聚合成一句）、**托盘气泡有没有被系统静音**（对话区里仍然有一条，那是唯一可靠的落点）、**`%LOCALAPPDATA%\axo\reminders.jsonl` 里有没有那条**。第三处排除掉之后剩下的都在前面两处 |
| 重启之后同一条提醒又弹了一遍 | 理论上不会：响过的 id 记在 `reminders.fired.jsonl`（先落盘再弹）。真出现了先看那个文件里有没有那一行——**没有**说明当时落盘失败了，那是个 bug，把 `reminders.jsonl` 与 fired 那个文件一起留着 |
| 核心腿在没图形栈的机器上报 `libEGL.so.1` 且退出码 3、测试一条都没跑 | pytest-qt 的 `pytest_configure` 在收集前就导入了 QtGui，而**排除 `test_ui_*` 拦不住它**。给命令加 `-p no:pytest-qt`（见上面「跑测试与 CI」）。别去装 `libEGL`——那是为了让用不到的插件能 import 而给机器装图形栈 |
| `git status` 干净，可 `.bat` 里的行尾就是 LF | 改 `.gitattributes` **不会**回头重写工作区已有的文件，而工作区 LF 与库里 LF 相符，所以没有任何差异可报。`rm run.bat && git checkout -- run.bat` 让属性重新生效；确认办法是 `tests/test_entry_points.py` |
| 巩固跑过了，「SNN 热度」还是一个数字都没有 | 两种可能，界面分得开：**根本没跑过**（说"巩固还没跑过"）与**跑过但一条都没被回放认出**（明说这句）。后者是正常的——新的记忆还没进关联图，或者都没通过探针。看不出来时去 `%LOCALAPPDATA%\axo\memory\consolidation\last.json` 看有没有那个文件 |
| 到点了却没跑巩固 | 三处依次看：设置「记忆」里勾选框还在不在；**盘上有没有图**（`memory/graph.npz`，图是懒建的，从没打开过记忆窗口就没有，那时这一轮会先请一趟建图、建完再跑）；`last.json` 里的 `newest_id` 是不是等于库里最新那条——**库里没有新记忆时自动那条会让掉一轮**（巩固的对象是已有的记忆，重跑只是把同一批再认一遍）。这三道门**手动那条都不走**：托盘的「立即巩固」随时能强制跑一趟 |
| 退出时打印「收尾超时：… 仍在运行」，而当时正在巩固 | 不是 bug：收尾只等 3 秒，巩固可能是几分钟。**有快照在**、每簇是一次「改库 + 追加事件」，所以最坏是这一轮只跑了一部分，而**库与事件是同一个前缀**、`seq` 连得上。下一次到点会重跑 |
| 巩固跑到一半发现选错了参数，想停下 | 本版**没有取消**（与建图同一姿态，也没有排给哪个阶段）。要退就托盘退出——见上一行的收尾行为；库里的改动由快照兜底，`memory/snapshots/` 里那几份整库副本可以直接拿来还原 |
| 冻结出来的 exe 双击了没反应 | 先跑带控制台的那一版（`python tools/build_exe.py --console`），回溯会打在控制台上。**无控制台的版本撞上未捕获异常只弹一个错误框、进程还活着**——所以"任务管理器里进程在"不能当成"起来过" |
| 构建报某模块没被收进去 | 去 `build/axo/axo/warn-axo.txt` 看（PyInstaller 会在 workpath 下**再套一层同名目录**，别按 `build/axo/warn-*.txt` 找）。里面绝大多数行是无害的，要看的只是 `tools/build_exe.py` 里 `_FORBIDDEN_MISSING` 那六个名字 |
| 冻结产物的对话区白屏 | 两种可能，构建时自检分得开：**web 资产没进镜像**（第 2 条）与 **QtWebEngine 的运行件没带上**（第 3 条，`QtWebEngineProcess.exe` / `qtwebengine_locales` / `plugins`）。重跑一次构建看它报哪条，别去改应用代码 |
| 首次双击弹 SmartScreen | 正常：exe 没有代码签名。点「更多信息 → 仍要运行」是一次性的 |
| 冻结产物没有自定义图标 | 构建时画图标那一步失败了，只打一句话、不中断构建（图标是外观，不该让整次构建挂掉）。重跑看那句报错 |
| 窗口标题栏、任务栏上没图标 | 与资源管理器里那个**文件**图标是两回事：前者是程序启动时自己装的（`ui/main_window.py` 的 `_install_window_icon`，跟着主题主色走），后者才是嵌在 exe 里的那一份。所以这一条只会出现在旧产物上——构建自检第 5 条会拦下它，重跑一次构建即可 |
| 构建完了，可 exe 找不到 | 它在 `dist/axo/`，而 `dist/` 在 `.gitignore` 里——编辑器里是灰的、远端上不存在，所以"看不见"是常态。构建成功时桌面会多一个快捷方式；**没多就是那次自检没过**（快捷方式只在全过之后才放），回构建输出里看它报的是哪一条 |
| 桌面那个快捷方式点了没反应，或指向旧位置 | 它里面是**绝对路径**（`.lnk` 的固有属性），仓库搬过家它就指着旧的。重新构建一次会覆盖成新的（`--no-shortcut` 那次不会重新放）。桌面被 OneDrive 接管过也不影响——路径是问系统要的 |

### 退出码怎么读

本项目的异常退出**几乎只有一种：`abort()`**。它在没装 faulthandler 时表现为
`0xC0000409`（Windows fast-fail：没有回溯、没有 stderr、Python 的 `atexit` 都不跑），
装了 faulthandler 时是 `3`——**这是同一个病的两种长相**，不是一个 Qt 问题加一个
Python 问题。已知成因只有两个，靠 stderr 或栈顶分开：

| 线索 | 成因 |
|---|---|
| stderr 有「收尾超时：… 仍在运行」 | 一个**还在跑的线程**被析构，`~QThread` 触发 `qFatal`。收尾路径没走到（`_shutdown()` 是唯一入口，别绕过它） |
| faulthandler 的栈顶停在 `main_window.py` 的 `release` | **在界面线程里丢掉一个住在工作线程里的 QObject 的最后一个引用** |

**P3a 给第一条加了一个新的触发方式：worker 卡在"等用户点确认"上。** `wait_for_all`
收尾时做的是 `thread.quit()` + `thread.wait(3000)`，而 **`quit()` 只结束线程的事件循环**，
worker 却是被 `started` 以 `Qt.DirectConnection` 直连进 `run()` 的——它根本不在事件循环里，
`quit()` 唤不醒它。于是它若正卡在确认上，收尾会 3 秒超时后继续退出，进程撞上
`0xC0000409`。所以 `AgentWorker.stop()` 必须做**两件**事：翻停止标志 + **`slot.cancel()`
立即唤醒还卡在 `wait` 里的 worker**。

> 这一条**不是优化，是这条设计成立的前提**。同理，`_shutdown()` 与「停止」都必须也调
> `_agent_worker.stop()`——`_reset_generation_state` 现在复位的是"三个 worker + 三个线程"，
> 它的 docstring 早就警告过"只复位一路"的症状。回归测试在 gui 腿：
> `test_ui_agent_slots.py`（等待确认期间点停止 → worker 在预算时间内退出）与
> `test_ui_agent_worker.py`。

第二条的修法是结构性的，写在 `MainWindow._track` 的文档里：worker 的 Qt 亲和面
**留在界面线程**，`run()` 靠 `Qt.DirectConnection` 在工作线程里直连执行。于是"丢最后
一个引用"永远是同线程析构。两个方向都要守住——亲和面搬回工作线程（`moveToThread`）
会招回这个 abort，`started` 少写一个 `DirectConnection` 则会让 `run()` 排队回界面线程
执行，症状是**界面在每次请求期间冻住**（看起来像 Ollama 慢）。回归测试：
`tests/test_ui_worker_track.py`（标 `gui`，核心腿用 `--ignore-glob='tests/test_ui_*'` 排除）。

> **`--ignore` 不认通配符。** 它收的是**路径**。写成 `--ignore=tests/test_ui_*` 或
> `--ignore=tests/test_ui_` 时它一条都排不掉，而且**不报错**——命令照常跑、照常
> 全绿，只是"核心腿"里混进了 gui 测试。要通配就用 `--ignore-glob`（它要引号，
> 否则由 shell 先展开）；按标记排则是 `-m "not gui"`。两条现在都给出 1575 条，
> gui 腿是 368 条（数条数的办法见上面「跑测试与 CI」）。

**还有一个长得一样但性质不同的退出码**，只在冒烟脚本里出现：脚本自己在收尾前
**没把事件队列排空**。窗口的 `show()`/`close()` 会投递事件，`deleteLater` 要等事件
循环才执行；带着一队未处理事件退到解释器收尾，Qt 同样走 `qFatal`，症状一模一样
（`0xC0000409`、无回溯、无 stderr）。**这不是产品的第三种成因**——真窗口全程有事件
循环，不受影响——但排查时很容易把它算到产品头上（`tools/_smoke_memory.py` 就曾因此
被误判）。那个脚本末尾排了一个 `QTimer.singleShot(200, app.quit)` + `app.exec()`，
原因写在它自己的注释里，改动那个脚本时别把这一句删掉。

### 打包（P6a）：冻结成免安装的 Windows 产物

```bash
uv sync --all-extras                  # PyInstaller 在 pack 那一组里，见下
python tools/build_exe.py             # 构建 + 自检 + 在桌面放一个快捷方式
python tools/build_exe.py --dry-run   # 只打印要跑的命令，不动盘
python tools/build_exe.py --console   # 带控制台的排障版，与上面那个并存
python tools/build_exe.py --no-shortcut   # 只构建，不碰桌面
```

产物是**一个目录**（onedir，`dist/axo/` 里是 exe 加一个 `_internal/`），不是
单文件。单文件每次启动都要把几百 MB 解到临时目录，而这个产物的几百 MB 里主要是
QtWebEngine——解压那一下正好压在启动路径上（现在实测**起一次 1.9 秒**，含窗口出现）。
机器上**不需要装 Python**，`_internal` 里带着解释器与全部依赖。

**产物藏在哪、怎么找到它。** `dist/` 是构建输出、在 `.gitignore` 里，所以它在编辑器里是灰的、
在远端上根本不存在——"构建完了却找不到 exe"是常态，不是谁弄错了。所以**自检全过之后会在桌面
放一个快捷方式**（文件名取界面上的显示名，即 `Axo.lnk`，目标与工作目录都指着
产物），双击即启动；`--no-shortcut` 关掉它。三条要知道的：

* **只在自检全过之后才放。** 指向一个自检没过的 exe，比桌面上什么都没有更糟。
* **桌面是问系统要的**，不是拼 `%USERPROFILE%\Desktop`：桌面可能被 OneDrive 接管（那时它在
  `%USERPROFILE%\OneDrive\桌面`），也可能被组策略挪走。拼字符串会静默落到一个存在的、但不是
  桌面的目录里，于是"建成功了、人却看不见"——那正是这一步要治的症状。走的是
  `SHGetKnownFolderPath`，它会把这些重定向一并算进去。
* **快捷方式里是绝对路径**（`.lnk` 的固有属性）。仓库搬了家它就指向旧位置——重新构建一次会
  覆盖成新的。建不出来时**不中断构建**（与画图标同一姿态），但会打印目标路径让人自己建一个。

**不写 `.spec`。** 构建参数在 `tools/build_exe.py` 里拼出来（`--specpath build`），理由是
`.spec` 属于 `.py` 之外的散件：ruff 扫不到、测试读不到，等于一块不进任何腿的代码。参数与
自检逻辑住同一个文件，两边都能被 AST 读到（`tests/test_packaging.py`）。

**图标是构建时现画的，仓里没有图片文件。** 调 `ui/tray.py` 那个托盘图标本身，按
256/64/48/32/24/16 六档各画一张、手工拼成 `.ico`——**每一档现画**，因为把 64px 那张缩到
16px 会把中心那个点缩没，而 16px 恰恰是任务栏最常用的那一档。画不出来时**不中断构建**，
只说一句（图标是外观，不该让整次构建挂掉）。

**自检是这一步的正文。** 冻结坏掉的方式几乎都不抛异常——资源没带进去、QtWebEngine 的
平台件落在镜像外、某个 import 漏了——它们表现为"双击之后什么都没发生"。所以构建完立刻查
盘上的这六条：

1. 产物在（`dist/axo/axo.exe`）。
2. **镜像路径假设成立**：`_internal/axo/ui/` 下的 qss 与三处网页资产都在。
   这一条成立，应用代码才一个字都不用改（那两处读取是 `Path(__file__).with_name(...)`）。
3. **QtWebEngine 的运行件在**：`QtWebEngineProcess.exe`、`translations/qtwebengine_locales/`、
   `plugins/`，以及 `resources/` 下四份运行件（它们是第 6 条删掉的那些的孪生）。
4. **缺失清单干净**：读 PyInstaller 自己写的 `warn-<name>.txt`，只比**整名**——numpy 会留下
   一大坨 `numpy._core.atleast_2d` 这种**属性式**记录（实测 175 行），按前缀比会让这份名单
   天天在响。
5. **真起一次，看有没有开出窗口、窗口上有没有图标**。判据不是"进程还在不在"：无控制台版本
   撞上未捕获异常会弹一个模态错误框、进程活着，那是**假绿**（实测踩过）。所以要求它名下有一个
   可见顶层窗口、且不是对话框、也不是控制台，**且那个窗口上挂着图标**（问 `WM_GETICON` 那三
   个槽，全 0 就是没有）。图标单列一条是因为它是唯一"窗口开出来了、看着像好了、其实是半成品"
   的那一档：exe 里嵌的那份只影响资源管理器里那个文件的外观，窗口自己不设，标题栏左上角就空
   着一格——而三处里只有一处会被顺手注意到。
6. **调试变体真的删了**（见下一条）。

**体积：521.2 MB，其中删掉了 77.2 MB。** 首次构建 598.4 MB，量出来的构成是 QtWebEngine
自己（`Qt6WebEngineCore.dll` 194.1 MB）、它的资源与语言包（`resources/` 101.4 MB +
`translations/` 53.0 MB）、软件 OpenGL 兜底（`opengl32sw.dll` 19.7 MB）、numpy 的
BLAS（`numpy.libs/` 20.2 MB）。里面**能删且删得干净**的只有一组：`resources/` 里的
**调试变体**——`qtwebengine_devtools_resources.debug.pak` 一个文件 72.3 MB，加上另外四份
`.debug.pak` / `.debug.bin`，共 77.2 MB。它们是给 Qt WebEngine 的**调试版**用的（这里链的
是发布版 DLL），而且**每一个都有同名的非调试孪生一起进了镜像**，所以删的是"同一份东西的
另一版"。自检第 3 条钉住孪生那一侧、第 6 条钉住"真的删掉了"，`tests/test_packaging.py`
里那条守卫则钉住"名单里只许出现调试变体"。删完当场实测：主窗口照常开出来（窗口类
`Qt6120QWindowIcon`、标题就是产品名），它下面那个 `QtWebEngineProcess.exe --type=renderer`
子进程在 15 秒里一直活着——**后者才是"白屏"的判据**，因为资源或语言包缺失的典型表现正是
那个子进程起不来，而主窗口照样好好地开在那儿。

**其余几块一律不动，这是有意的。** 它们都不是"没被用到的 Python 模块"，而是 Qt 自己的运行
件（语言包、软件渲染兜底、QML 插件树）；砍它们省下的是几十 MB，换来的是**白屏**——而这里
唯一的机器判据（窗口开没开出来）**根本不走那些代码路径**，所以那种坏法机器验不出来，只能
等你双击之后看屏幕。`--exclude-module` 一组都没加，理由同此。真要再审，触发条件是 Live2D
接入（那时 QtQuick 那一侧才真的进画面，也才有办法验）。

**四条如实的限制：**

* **CI 验不了这一环。** 六条腿全在 `ubuntu-latest`，而 **Windows exe 只能在 Windows 上
  构建**；名字叫「构建 wheel」的那条腿构建的是 **wheel 不是 exe**，也不碰 PyInstaller。
  所以这一环唯一的守卫是构建脚本自己那六条自检。
* **exe 没有代码签名**，首次运行会被 SmartScreen 拦一次（「更多信息 → 仍要运行」）。
* **仍然需要本机装着 Ollama 与一个嵌入模型。** 冻结改的是"跑起来需不需要装 Python"，
  不是"记忆从哪来"——云端后端那条路也一样仍要本机嵌入模型。
* **`benchmarks/` 不进产物**，界面也不 import `bench`。所以"wheel 要不要连语料一起带"
  那条**仍然开着**：P6a 冻结的是 exe，不是 wheel（见 `pyproject.toml` 与三份 `CORPUS.md`）。

**只靠眼睛验的两件事**（没有一条腿能替）：双击**桌面上那个快捷方式**（或
`dist/axo/axo.exe`），确认窗口、**对话区（那一区是网页，最可能因为
资产没带对而白屏）**、托盘图标、记忆窗口都正常；以及那个图标在三处的观感——它是程序画的圆角
方块加一个点，放大到 256px 好不好看、缩到任务栏那一档还认不认得出来，只有看了才知道。
（**"有没有"不在此列**：自检第 5 条会拦下没图标的产物。）

**冻结的入口是 `src/axo/__main__.py`**，不是 `ui/app.py`：PyInstaller 收的是
**一份脚本**，它把入口文件当 `__main__` 跑、`__package__` 是空的，而 `ui/app.py` 里那几处
相对 import 在那种情况下解析不了。`run.bat` 走的仍然是 `-m axo.ui.app`，源码
检出那条路没动。

#### 发给别人：`--release`

上面那一条产出的是**你自己机器上能跑的东西**。要给别人一份"下载、解压、双击"就行的
压缩包，多跑一个开关：

```bash
python tools/build_exe.py --release                 # 全跑，最后打一个 zip
python tools/build_exe.py --release --skip-build    # 产物已经在 dist/ 里，只跑闸门
```

`--release` 不是第二个工具，是同一条流水线后面接了几步：构建 → 自检六条 → **剔 GPL-only
模块** → **隔离的首启探测** → **残留闸门** → **与第三方清单对账** → 打 zip。理由是这两个
工具迟早会漂——本仓刚吃过一次"替身跟丢"的亏。**任何一步红就不出 zip**：一个"打出来了但
内容不对"的压缩包比没有更糟，因为它会被发出去。

四条只有发布这一步才跑的判据：

1. **剔掉 GPL-only 的那几族 Qt 模块。** PyInstaller 的 PySide6 钩子把整个 wheel 的 DLL
   照单全收（实测 154 个），其中 Charts / DataVisualization / Graphs / VirtualKeyboard
   历来只在 GPLv3 下提供。删之前**先证明删得干净**：全树按字节扫一遍，除了要删的那些
   文件自己，没有任何别的文件提到那 8 个名字才动手；提到了就**一个都不删**并报红——半剔
   的树比没剔的更坏（既没消掉许可风险，又留下一堆指向空处的插件）。实测那 8 个名字的
   引用者只有 4 个 QML 插件目录与 1 个输入法插件，都在 `_GPL_ONLY_COMPANIONS` 里。
2. **首启探测。** 给子进程一个临时的 `AXO_DATA`，起完之后**断言那个目录是首启
   形状**：库建出来了、库里**只有内置人格锚一条**、没有逐字稿、没有壁纸。这一句就是
   "别人下载到的是最初始化的版本"的机器判据。（顺带修掉一个旧毛病，见下。）
3. **残留闸门。** 产物树里不许有 `*.db` / `*.log` / `*.jsonl`，不许有 `sessions/`、
   `wallpapers/`、`benchmarks/`、`tests/`、`tools/`；内容上，全树不许出现**检出路径**，
   而**用户目录那一族**只在仓自己的文件里（顶层 exe 与 `_internal/axo/`）搜。
   这条区分是实测逼出来的：产物 3157 个文件里有 270 个（Qt 的 DLL、CPython 的 `.pyd`）嵌着
   **它们构建机**的用户目录路径——Qt 的构建机用户名是 `qt`、CPython 的落在一个临时构建
   目录里，都不是我们的痕迹。全树搜会天天误报，然后被无视。这里**不把那些路径写进本文**
   也是同一个理由：判据里的针是从 `Path.home()` 算出来的，README 里再抄一遍反而让
   "全仓搜不到用户目录路径"这句话不成立了。
4. **与 `THIRD-PARTY-NOTICES.md` 对账。** 读产物的 `PYZ-*.toc`（**产物里到底冻结了哪些
   包，答案在这里，不在 `_internal/` 的目录列表里**——纯 Python 字节码全在 exe 体内那个
   PYZ 归档里，按 `_internal/` 找 httpx 会得出"没带进去"的错误结论），用
   `importlib.metadata.packages_distributions()` 反查发行包，再与那份清单里机器可读的
   那张表逐条比。**多一个、少一个、版本对不上，都红**——一份没人核对的手写清单，唯一的
   结局是慢慢与现实脱节，而那种失效看起来一切正常。

**隔离数据目录这一条修掉的是个真毛病。** 原来的活体探测只弹掉了 `QT_QPA_PLATFORM`，
没有隔离数据目录——于是子进程按 `paths.data_dir()` 落到 `%LOCALAPPDATA%\axo`，
**每次构建都拿你自己的真库起一遍应用**，往真库里写内置锚、真库里本来就有的东西也一并被
读到，而构建日志里一个字都不显示。现在子进程拿到一个临时目录，"这次构建碰过我的库没有"
这个问题才有答案，而且答案是"没有"。

产物是 `dist/axo-<版本>-win64.zip`（版本从 `pyproject.toml` 读，不写第二份常量），
顶层一个目录，里面是产物树 + `README.txt`（**写给拿到它的人**，不出现本仓行话——由
`tests/test_packaging.py` 机械地查）+ `LICENSE` + `THIRD-PARTY-NOTICES.txt` + `licenses/`
（GPL/LGPL 全文，逐字节钉在 `tests/test_licenses.py` 里；其余第三方的短许可打包时从装好的
`dist-info` 现取，按发行包分目录）。**归档内文件名一律 ASCII**：中文文件名在 zip 里要靠一个
通用的 UTF-8 标志位，老解压器会乱码，而正文照旧中文——乱码只发生在文件名上，恰好是最容易
被当成"文件坏了"的那一半。

**验红怎么验。** `--skip-build` 存在的理由不是省时间，是让闸门可以被验红：往 `dist/` 里塞
一个空的 `memory.db`、再往仓自己的资产里塞一行含检出路径的文本，跑 `--release --skip-build`，
必须报出这两条并且**不出 zip**；塞一个假的 `Qt6Charts.dll` 并让另一个文件提到它，剔除那一步
必须**拒绝删并报红**。两条都实测过。

**解压到仓外再起一次**也实测过：在空目录里解开，以隔离的 `AXO_DATA` 起来等 15 秒
再结束，产物目录**一个文件都没多、没少、没变**，而数据目录里是 `memory/mem.db` 一条
`persona://default`、外加空的 `sessions/` 与 `wallpapers/`。

## 数据放在哪

默认 `%LOCALAPPDATA%\axo\`。**刻意不放在仓库目录里**——否则
`git clean -xdf` 会抹掉全部记忆，而且有把私人对话提交进版本控制的风险。

用环境变量 `AXO_DATA` 改到别处（开发时常指向仓库里的 `data/`，
它已在 `.gitignore` 里）。

**卸载要删两处，不是一个目录。** 除了数据目录，外观与后端设置走 `QSettings`，
而在 Windows 上它的原生格式**是注册表**：

```
HKEY_CURRENT_USER\Software\Axo\axo
```

记忆库、逐字稿、壁纸都不在那儿（它们全在数据目录里），那里只有主题、选中的模型、
工具开关这类设置，以及**云端后端那个 API key 的密文**。密文是用 DPAPI 按「当前
Windows 账户 + 当前机器」加密的，拷到别的账户或别的机器上解不开——这是 `secrets.py`
的全部理由，也是"把设置从一台机器搬到另一台"会看到"没配过"的原因。

程序本身不留别的东西：没有服务、没有开机启动项、没有安装到 `Program Files`。

### 你聊的东西绝不进版本控制

会话逐字稿、记忆库、你选的壁纸、配置——**推上去就收不回来了**，所以这里不靠"记得
别提交"，靠三层各管一段：

| 层 | 管什么 | 在哪儿 |
|---|---|---|
| 默认值 | 数据目录根本不在仓库里 | `src/axo/paths.py` |
| 忽略规则 | 万一指进来，也进不了 `git add` | `.gitignore`（含 `*.jsonl`、`*.db*`、`sessions/`、`wallpapers/`） |
| 断言 | **索引里现在确实没有**——查的是 `git ls-files`，不读 `.gitignore` | `tests/test_repo_hygiene.py` + pre-commit 钩子 `repo-hygiene` + CI |

第三层是唯一"检查结果而不是意图"的一层：前两层写对没写对，它都能给出一个事实答案。
它把 `.jsonl` 一律当逐字稿，只放行**逐个登记**过的量具语料目录（目前三个：
`benchmarks/gold/`、`benchmarks/routes/` 与 `benchmarks/substrate/`）——逐字稿与语料同名，而漏掉一份私人对话
不可逆，多放行一个目录只是多写一行。**登记是一份一份来的，不是"benchmarks/ 下面的都放
行"**：那条更松的写法会让误放进来的 `benchmarks/transcripts/2026-10-10.jsonl` 被静默
放行，而"放行"在这里的含义是"推上去就收不回来了"。逐个登记的另一半好处是，加一份新语料
**必须动那个文件**，于是"这里还有一份语料"在 diff 里看得见。

> 反向的失效**踩过两次，形状一模一样**：路由语料落地时 `.gitignore` 没跟着加放行，于是
> 那份 `utterances.jsonl` 只在工作区里——**本地每条腿都绿**，而门槛、指纹测试、仓库卫生
> 都要等到别人检出之后才会红。P4a 加基质语料时又漏了一次（`memories.jsonl` /
> `queries.jsonl` 被抓在 `*.jsonl` 里）。所以"加一份语料"要动的名单是**两份**：
> `.gitignore` 的放行规则与 `_JSONL_ALLOWED_UNDER`，同一次提交里改完。
>
> 第二次之后补了一条守卫，把"两处要一起动"从一句叮嘱变成一次执法：
> `test_repo_hygiene.py::test_registered_corpus_directories_survive_the_ignore_rules`
> 按 `_JSONL_ALLOWED_UNDER` 逐个目录问"里面的 `.jsonl` 会不会被忽略规则挡住"。它问的
> 问题与上面那条**不重复**——`git ls-files` 看不到被忽略的文件，正是那个盲区让前两次
> 都是绿的。登记了却没放行，现在当场红。

另一件事同样进了机制：`tools/bench_space.py` 的 40 句语料是**全仓唯一"形态上就是
记忆条目"的东西**（第一人称、具体、可查），它曾经写着真实的显卡型号、盘符与相邻仓库
的名字，2026-10-10 换成同形状的虚构事实，并由 `test_repo_hygiene.py` 里一张 denylist
盯着别再改回去。

> 那两张 denylist **自己写着被禁的词**——要拦一个词就得写下它。这是知情的取舍，理由
> 写在 `tests/test_repo_hygiene.py` 的模块 docstring 里：语料的正文已经干净，剩下的
> 只是一张"被禁词清单"，且没有通用规则能代替它。

> **真出了事怎么办。** `git rm --cached <路径>` **不等于**删掉内容——历史里还在，
> 远端还有。要 `git filter-repo` 重写并强推，然后假设那份内容已经泄露（改了历史也
> 清不掉别人 clone 走的副本）。所以这一节的重点是前面那三层，不是这一段。

## 几个刻意的取舍

**对话区是网页，外壳是 Qt。** markdown 流式渲染与 Live2D 都要求完整的 web 引擎；
用原生控件做这两件事等于把标准重写一遍。两者之间用 `QWebChannel` 直连，
**不起本地 HTTP 服务器**——不需要端口、不需要令牌、不需要管理服务器生命周期。

**会话记录 ≠ 记忆库。** 前者是逐字稿（可以几百兆，可以整段删掉），后者是提炼
出的条目（带权重、分层与关联，删一条会改变图上的边）。混在一起的话，
「清空聊天记录」这个动作就有概率把长期记忆一起清掉。

**记忆的编码有两条轴，别把它们混成一条。** 一条是**模型依赖性**：词法 SDR
（blake2b 哈希，**模型无关**）做相似度、去冗与关联基质的地基；语义 SDR（依赖当前
embedding 模型）走语义通道。若记忆结构依赖 embedding，换模型就等于关联全废——那条
承诺也就不成立了。

另一条是**同一个源上的稀疏度**：在同一个词法 SDR 之上再取一档更稀疏的**关联码**
（k=64，对词法码的 k=573），喂图 A 与神经元级基质 W。它与模型无关（纯哈希子采样），
所以"记忆独立于模型"这条在基质上同样成立——**换嵌入模型不用重建图**。P4a 说的
"双尺度"指的就是这一条；把它读成上一条（词法 / 语义）曾经是一次真实的误读。

**不做**（"轻"的边界）：多用户／云同步；向量库（P ≤ 5 万时 numpy 分块 matmul
约 5 ms，够用）；常驻守护进程（**系统托盘已经落地了，而且它不是守护进程**——那要有后台
任务才需要进程活着，而托盘的存活范围就是"这个程序开着的时候"，退出仍然是用户按一下的
事，见上面「托盘与定时触发」）；自学的人格模型（偏好是规则表，不做 embedding 化的
「性格向量」——那会把性格重新绑回模型）。

**工具循环只加一条消费路径，不动已有的那条。** `tools` 非空才走 `AgentWorker`，为空仍走
`ChatWorker`——**回归为零**是本版的一条硬约束，而合并不带来新能力、却要碰已经稳定的生成
路径。代价是两条路径短期并存会漂移，所以配了一条平价测试与一条写死的移除准则（见上面
「跑测试与 CI」）。

**路由的模型自分类默认关，而且这个默认值是量出来的。** 本机那个 4B 模型在"两个工具该调
哪个"上五轮只对一轮，它不足以可靠地判自己这一轮属于哪个语域。于是 `/task` 这类显式命令
是**主要**的可靠入口，不是便捷方式——这也是为什么路由三段里最先落地的是斜杠，模型自分类
排最后、而且默认关。

**模型仍可能声称做了一个它没做的动作，环境槽只是缓解、不是保证。** 工具是靠请求里的
`tools` 字段声明的，而"字段不存在"与"字段为空"在模型的输入里长得一模一样——它读得到自己
收到了什么，读不到自己**没**收到什么。所以没有工具的那一轮，L1 环境槽会补一句事实：「这一轮
没有工具可用，也不会有任何动作被执行」（`session/environment.py`）。它是**事实**不是
**指令**，两处都写会让人格锚那条"一个字都不许改写"的纪律失去意义。

**这句事实只写"这一轮发生了什么"，不列能力清单。** 列清单的话，**那个清单可以被原样背
回去**：2026-10-11 用户打「晚上好」，模型据它回了一句"我无法使用工具查看记忆"，用户于是
以为工具坏了（真实原因是那一轮是闲聊语域、本来就不该有工具，见上面「语域、工具与确认
闸门」）。所以它写的是一句描述"这一轮发生了什么"的**事件**——说的是同一件事实，但它不能
被反手当成能力免责声明，因为里面已经没有能力可列。`tests/test_environment.py` 里有一条
专门钉住"清单不许回来"。

**"不许声称你调用了工具"这条要求归人格锚，而它此前哪里都没有。** L1 不肯写它（写了就是
指令），L0 里也没有，所以只能落进人格锚的正文——而那段正文只有程序能改：不给它一个升级
路径的话，"这条要求有地方兜着"就只是一句印象。

补它需要一次迁移，因为只改常量是**够不着**的：`ensure_builtin_anchor` 原先在库里已经有内置锚
时直接返回 `None`，于是新装的库有这句、老库没有，"任何模型读到的身份完全一样"会变成"同一个库
上一样、跨库不一样"——那比"大家都没有"更糟。所以内置锚现在带**版本号**，`ensure_builtin_anchor`
多了一个"旧了就原地升"的分支。它改写的只是**内置**那条：那条锚本来就只有程序能改
（`read_only_reason` 拦住界面上的编辑与删除），所以"正文与常量不一致"只有一个解释。

> **人格锚版本记录。** 第 1 版 = 加版本号之前写进库里的那些（**没有版本键**，所以它们是
> 判成"旧"的入口，而不是 0 或"未知"）。第 2 版加了第四句「只说你真的做过的事：只有真的
> 调用过工具才算用过工具，没调用就不要说保存了、记住了或查过了」。
> 改 `DEFAULT_PERSONA` 就要把 `BUILTIN_PERSONA_VERSION` 加一，并在这里添一行。
> 升级只在启动时跑一次，且**会在对话区说一句**（"已从第 1 版升到第 2 版"）——改的是模型
> 读到的身份正文，用户看不见那次改动，不说就是一次静默变更。

**这一句是一句要求，不是闸门。** 下面那段实测的否定结果它管不了：真正挡住"说了没做"的仍然是
对话流里那行**真实工具轨迹**与动作的确认闸门。

**而那句事实在最该起作用的那一次没有起作用——这是实测的否定结果，不是推测。** 2026-10-10
那句露骨提示词（"调用 `write_memory` 工具，参数 content 填「我最喜欢的颜色是靛蓝」"）被路由
判成 `ambiguous=True / tools=False`，也就是说**这一轮确实没有工具**、**两句事实都在提示词
里**（拒绝的那句不在，因为这一轮根本没走到闸门），而模型照样回了"已通过 write_memory 工具
保存记忆……该记忆已写入本地文件系统"。所以"降低概率"这个说法要收紧成：**在本机这个 4B 模型
上，它没有拦住已经发生的那种幻觉。** 唯一的事实来源仍然是对话流里那行**真实工具轨迹**，
而不是模型的自述——界面上显示的就是前者。
